# 업로드 이미지 압축

새로 업로드하는 본문 사진과 프로필 사진은 원본 파일을 저장하지 않고 서버에서 검증·압축한 WebP 파일만 저장합니다. 저장 백엔드가 로컬 디스크이든 Supabase Storage이든 같은 처리를 거칩니다.

| 구분        | 업로드 한도 | 처음 적용하는 크기·품질               | 저장 용량 상한 |
| ----------- | ----------- | ------------------------------------- | -------------- |
| 본문 사진   | 10MiB       | 가로·세로 최대 2400px, WebP 품질 82   | 2MiB           |
| 프로필 사진 | 5MiB        | 중앙 정사각형 512×512px, WebP 품질 82 | 256KiB         |

- JPG·PNG·WebP·GIF의 실제 파일 형식을 검증합니다. 확장자만 바꾼 파일, SVG, 읽을 수 없는 파일을 거부합니다.
- EXIF 방향을 적용한 뒤 EXIF/GPS·ICC·XMP·IPTC 등 원본 메타데이터를 제거합니다. 투명도는 보존합니다.
- GIF와 움직이는 WebP는 첫 장면 한 장으로 저장합니다. 본문 사진은 작은 이미지를 확대하지 않습니다.
- 출력이 용량 상한을 넘으면 품질을 낮추고, 이후 해상도를 줄이는 순서로 최대 네 번 인코딩합니다. 무제한 재시도하지 않습니다.
- 원본 최대 2천만 화소 제한과 입력·출력 바이트 제한을 함께 적용합니다.
- 저장된 DB의 byteSize는 실제 압축 결과 바이트 수입니다.
- 작은 원본은 포맷 변환 후 파일 크기가 약간 커질 수 있습니다. 모든 파일이 일정 비율로 작아진다는 보장은 하지 않습니다.
- 기존 저장 파일은 자동으로 다시 압축하거나 삭제하지 않습니다. 기존 프로필 메타데이터의 2MiB 상한은 호환을 위해 유지합니다.

공통 정책은 `src/domain/image-compression.ts`, 실제 처리 함수는 `src/server/image-compression.ts`입니다. `media.ts`와 `profile-photos.ts`가 저장 직전에 이 함수를 호출합니다.

`tests/image-compression.test.ts`는 실제 sharp로 크기·메타데이터·회전·투명도·GIF/WebP 첫 프레임·노이즈 사진의 재압축·잘못된 파일·픽셀 폭탄을 확인합니다. 8개 압축 검사와 기존 프로필 사진 11개 검사가 통과했습니다.
