# CRUD 검증 기록 · 2026-09-30

- `npm run check`: TypeScript, 도메인·DB·서비스 36개 테스트, Drizzle 메타데이터 검사 통과
- `npm run test:api`: 실행 중인 Next.js와 PostgreSQL 18을 통한 HTTP 통합 검사 통과
- `npm run build`: 프로덕션 빌드 통과, 메인과 API는 동적 경로
- 개발 플래그가 들어 있는 동일 `.env`로 `next start` 실행: `canWrite=false`, 글 작성 HTTP 401 확인
- 프로젝트 전용 PostgreSQL 중지·재시작: 글·댓글·이미지 DB 행 수가 동일하게 유지됨을 확인
- 테스트 종료 후 개발 서버를 `127.0.0.1:3000`에서 다시 실행

서비스 검사는 소유권, 익명 작성자 정보 비공개, 글·댓글 수정/삭제, 답글 관계 보존, 알림 중복·수신자·읽음, 좋아요 멱등성, 북마크 범위, 조회 중복, 이미지 소유권/롤백, 검색·정렬·페이지 처리, 삭제 글 쓰기 차단을 포함한다.

HTTP 검사는 잘못된 Origin 403, 위조 authorId 400, 타인 글 수정 403, 가짜 PNG 차단, 이미지 재인코딩·연결, 작성·조회·수정·삭제, 북마크 조회, 서명 방문자 쿠키와 중복 조회, 댓글 삭제 후 답글 유지, 삭제 글 이미지 404를 확인했다. 이 검사에서 만든 글만 소프트 삭제했다.

브라우저 도구가 로컬 주소 접근을 보안 정책으로 차단했다. 이 변경에 대한 브라우저 클릭·키보드·반응형 화면의 최종 자동 검증은 수행하지 못했다. 기존 화면 구조와 스타일을 유지했지만, 새 CRUD 버튼의 수동 UI 검증은 남아 있다. 기존 screenshots는 이전 미리보기 단계의 이미지이며 현재 DB CRUD 검증 증거로 사용하지 않는다.

Supabase 원격 연결·OAuth·운영 Storage·배포 검증은 이번 범위에 포함하지 않았다.

## 외부 신청 링크 추가 검증

모집글 신청 링크 필수 입력, URL 검증, DB 저장·재조회·교체, 타인 변경 차단, 글 유형 변경 시 링크 제거를 추가 검증했다. `npm run check`의 40개 테스트와 실제 PostgreSQL HTTP 통합 검사가 통과했다. 로컬 DB에 `0003_recruitment_application_link.sql`을 적용했다. 실제 외부 플랫폼으로 신청을 제출하지 않았으며 새 버튼의 브라우저 클릭 검증은 수행하지 않았다.

## 커서 페이지 처리 및 Sliper 폴더 이동 검증

프로젝트를 `C:\Sliper`에서 실행했다. 기존 `.env`, `.local/postgres`, `.local/uploads`를 유지하고 프로젝트 전용 DB를 재시작했다. PostgreSQL의 현재 데이터 경로가 `C:/Sliper/.local/postgres`임을 확인했다.

- `npm run check`: TypeScript, 48개 테스트 및 Drizzle 메타데이터 검사 통과
- `npm run build`: 이동된 폴더에서 프로덕션 빌드 통과
- `npm run test:api`: 이동된 폴더의 Next.js·PostgreSQL을 통한 CRUD·이미지·모집 링크·커서 페이지 처리 HTTP 통합 검사 통과
- 기존 DB와 이미지 파일을 통해 메인 HTTP 200, 작성 가능 상태, 기존 첨부 이미지 HTTP 200 확인
- 개발 서버를 새 프로젝트 경로에서 `127.0.0.1:3000`으로 실행

추가 테스트는 마이크로초 시각 동률, 커서 경계 삭제·새 글 삽입, 조회 조건·작성자 변경 시 커서 거부, 최상위 댓글과 답글의 독립 페이지, 삭제된 부모의 답글 조회, 105개 알림 조회 및 전체 미읽음 집계, 이미 불러온 댓글·알림 상태 보존을 확인한다. 인기순은 고정 시점의 순위 스냅샷이 아니며 실제 다중 연결 부하 검증은 남아 있다. 새 UI의 브라우저 클릭 자동 검증은 앞서 기록한 도구 보안 제한으로 수행하지 않았다. 인증과 Supabase 원격 연결은 계속 후속 단계다.
