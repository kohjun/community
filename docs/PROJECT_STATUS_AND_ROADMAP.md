# Sliper 구현 현황과 남은 단계

기준일: **2026-10-11** · 프로젝트: **C:\Sliper**

현재 Sliper는 핵심 커뮤니티·행사 운영 흐름을 **로컬 PostgreSQL에 연결한 MVP**다. 글·신청·공지·전적·크루·알림을 실제로 저장한다. Supabase·카카오/구글·결제 플랫폼·서비스 도메인은 아직 실서비스로 연결하지 않았다.

이 문서는 현재 상태의 요약이다. 이전 문서에서 “다음 단계”로 적었던 구독/알림함·공유/검색·크루는 현재 구현되어 있다. **구현**은 코드와 로컬 저장 흐름이 있다는 뜻이며, 실제 외부 서비스·휴대폰 검증까지 완료했다는 뜻은 아니다.

행사 기록·포트폴리오의 첫 단계도 추가했다. 완료 확인과 회원 전용 회고, 별도 제작진 수락, 공개 동의에 따른 참가/제작/자료 포트폴리오, 기록 검색과 연결 동선을 제공한다. [사용법·DB/API·권한·다음 단계](EVENT_RECORDS_AND_PORTFOLIOS.md)를 참고한다.

4단계 협업형 아카이브도 추가했다. 회원의 수정 제안을 작성자가 비교·승인하면 원본을 보존한 새 자료 버전을 발행한다. 지식·콘텐츠 연구 글은 특정 자료 버전과 양방향으로 연결한다. [협업 흐름·권한·설계](COLLABORATIVE_ARCHIVE.md)를 참고한다.

5단계 템플릿 시장도 추가했다. 구매 버전·금액·이용 조건 보존, 구매/판매 관리, 비공개 문의와 거래 당사자가 아닌 운영자의 처리, 자료 전용 서명 결제/환불 브리지와 버전별 실제 완료 운영 사례를 제공한다. [사용법·계약·권한·검증](TEMPLATE_MARKET.md)을 참고한다.

룰북·이벤트 템플릿을 개요/기획·미션/규칙·타임라인/진행·준비물/예산 목차로 나누었다. 개별 미션 검색·펼침, 큐시트와 예산 자동 합계, 구조화 편집·코엑스 예시 불러오기를 제공하며 이전 발행본·유료 권한·행사 진행 사본을 보존한다. [구조화된 운영 가이드](STRUCTURED_PLAYBOOKS.md)를 참고한다.

구매 영역을 모바일 대응 카드로 정리하고, 외부 자료 결제가 미설정된 격리 로컬에서는 테스트 구매 후 가이드가 바로 열리도록 했다. 실제 청구는 없고 기존 구매 내역과 운영 환경의 접근 권한은 유지한다. [활성 조건과 테스트 구매](LIBRARY_TEST_PURCHASE.md)를 참고한다.

번개도 외부 신청 링크를 연결할 수 있다. 외부 신청 번호 제출 후 담당자 확인 또는 검증된 연동 승인으로 참가 확정·공지방 입장을 처리한다. 직접 신청은 무료이며 실제 외부 제공자 설정은 후속 단계다. [번개 신청 방식](LIGHTNING_AND_DISCOVERY.md)을 참고한다.

이야기의 모집 탭에서 목록형/카드형을 전환하고 카드에 썸네일·장소·한국 시간 일정·참가비를 보여준다. 검색·정렬·20개 페이지는 유지하며 보기 설정만 기기 저장소에 기록한다. 알림함 버튼은 미읽음 최대6개 드롭다운을 열고 하단 더보기로 전체 페이지에 이동한다. 조회만으로 읽음 처리하지 않으며 각 알림 선택 시 읽음 처리한다. [알림 조회·저장·권한](ENGAGEMENT_AND_NOTIFICATIONS.md)을 참고한다.

커뮤니티 보완의 첫 묶음(A1/B1/B2): 관리자 이용 현황, 홈 시작 동선, 오늘/이번 주/전체 인기와 모바일 광고 노출 정책을 추가했다. [기능·지표 정의·한계·다음 순서](COMMUNITY_DISCOVERY_AND_METRICS.md)를 참고한다. C 단계도 구현했다: 이야기 말머리·질문 답변 채택·관심 구독 피드·스포일러 미리보기와 관리자24시간 답변률. [동작·API·권한·검증](COMMUNITY_DISCUSSIONS.md)을 참고한다. D 단계의 주제별 이야기·모임·자료 탭, 명시적 태그 별칭·관심 피드, 아카이브 인원·시간·가격·운영 사례·공개 난이도/환경/스태프 필터도 구현했다. [연결 방식·권한·검증](COMMUNITY_TOPICS_AND_ARCHIVE_DISCOVERY.md)을 참고한다. 비밀값 예시 정리와 Git 커밋 전 검사도 추가했다. [비밀값·Git 보호](SECRETS_AND_GIT.md). 다음 제품 단계는 E 종료 후 할 일·회고·재개최 동선이다.

환불 계산: **5일 전까지100% → 4일 전80% → 3일 전60% → 2일 전40% → 1일 전20% → 당일 이후0%**. 현재는 예상액·요청·처리 기록이며, 실제 돈의 환불/정산은 외부 플랫폼을 연결해야 한다.

미디어는 **새 업로드부터 압축**한다. 사진은 브라우저에서 전송량을 줄인 뒤 서버에서 재검증한다. 영상은 비공개 원본·DB 작업을 접수하고 별도 Worker에서 변환하며 에디터가 ready 결과만 첨부한다. 본문 사진 최대2400px/2MB, 프로필512px/256KB, 영상은50MB/3분 이하 원본·글당3개·최대720p MP4/25MB 이하 결과다. 기존 파일을 일괄 변환하지 않는다. YouTube/Vimeo 링크는 원본 플랫폼을 사용하며 GIF·움직이는 WebP는 첫 장면만 저장한다.

QR은 **행사 현장 입장 확인**이며 휴대폰 번호 소유/신원 인증을 대신하지 않는다. 전적·매너 온도는 자동 매칭이나 노쇼 방지 보장 기능은 아니다.

RLS는 브라우저 직접 접근 차단의 기반이며 서버의 소유권·참가/관리 권한 검사를 대신하지 않는다. 운영 DB 역할과 마이그레이션 소유자 분리는 실제 프로젝트에서 적용/검증해야 한다.

**사용자 폭주 대응을 실측 완료한 상태는 아니다.** 요청 제한·정원 행 잠금·페이지 제한·인덱스·DB 대기열·영상 처리 한도는 있다. SSE는 Redis 힌트와 정기 DB 재확인을 사용하고 영상은 별도 Worker당 하나씩 처리한다. 여러 Worker는 DB 선점과 토큰으로 중복 완료를 막는다. 영상 Range 응답도 현재 전체 파일을 읽어 범위를 반환한다. 대규모 운영에는 별도 측정과 개선이 필요하다.

1~4는 프로젝트·도메인·업체 설정이 필요하다. 영상 변환 경로는 배포 환경의 요청 크기·시간·CPU·임시 디스크 제약과 맞아야 한다. 영상 변환은 별도 Worker에서 실행하지만 Web 업로드 본문50MiB와 비공개 공유 저장소는 배포 환경이 지원해야 한다.

5의 구체적인 후속 구현/절차:

- 미완성 글 첨부·소프트 삭제 미디어·정리 실패 파일의 **보관 기간과 자동 정리**.
- 서비스 내 탈퇴 이후 외부 Auth 계정/공급자 연결 해제, 참가 스냅샷·거래 기록의 보관/파기.
- DB와 파일을 함께 백업하고 실제 복원하는 리허설.
- 구조화된 오류 로그·서비스/Worker 상태 확인·발송 대기열/재시도·DB 잠금·디스크/메모리 감시.
- 공개용 정책·문의 연락처·신고 대응 담당, 시작 이후 행사 중단/사고/예외 환불 절차.
- noindex 해제 여부·공개 페이지 범위·사이트맵 결정.

외부 서비스가 아직 준비되지 않아도 **파일 정리·운영 상태 확인/로그·백업 리허설·베타 검증 시나리오**는 먼저 진행할 수 있다. 추가 커뮤니티 기능보다 이 기반 작업을 다음 개발 대상으로 권장한다.

자동 매칭·노쇼 보증·크루 전용 푸시·오프라인 QR 동기화는 현재 없으며 선택 확장이다. Redis Pub/Sub은 공지방 갱신 힌트에만 도입했으며 추가 캐시/대기열 도입은 측정한 병목과 일관성 요구를 보고 판단한다.

커뮤니티 성숙화의 후속 순서는 **운영 지식 재사용 → 장소 이력 → 협업 아카이브 → 템플릿 시장**이다. 첫 단계 완료 기록과 포트폴리오에 이어 2단계 회고에서 템플릿 초안 만들기·자료 발행 버전·파생 출처·변경 이력·이용 조건을 구현했다. 3단계의 명시적 장소 연결·선택 당시 스냅샷·장소별 회원 공개 완료 기록·운영 팁과 4단계 수정 제안·작성자 검토·새 버전 발행·연구 글 연결도 구현했다. 5단계 템플릿 시장의 당시 구매 조건 보존·비공개 구매/판매·분쟁 처리·전용 결제/환불 승인 브리지·버전별 실제 운영 사례 연결까지 구현했다. **성숙화 1~5단계의 기능 개발은 완료**했으며 실제 업체 연동·거래와 정산 검증은 실서비스 P0 단계에 남아 있다. [5단계 상세](TEMPLATE_MARKET.md)를 참고한다. 다음 개발은 파일 보관/정리·운영 상태·백업 리허설 등 실서비스 기반 작업을 권장한다.
