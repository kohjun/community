| 광고 공간           | 공개 홈·이야기·번개·아카이브·주제의 본문/PC 좌우 AdSense 수동 배치 준비·사이트 확인·개인 화면 제외. 모바일 Google 광고는 본문형이며 자체 미리보기 바텀시트와 구분. 실제 ID·승인은 후속                            |

환불 계산: **5일 전까지100% → 4일 전80% → 3일 전60% → 2일 전40% → 1일 전20% → 당일 이후0%**. 현재는 예상액·요청·처리 기록이며, 실제 돈의 환불/정산은 외부 플랫폼을 연결해야 한다.

미디어는 **새 업로드부터 압축**한다. 사진은 브라우저에서 전송량을 줄인 뒤 서버에서 재검증한다. 영상은 비공개 원본·DB 작업을 접수하고 별도 Worker에서 변환하며 에디터가 ready 결과만 첨부한다. 본문 사진 최대2400px/2MB, 프로필512px/256KB, 영상은50MB/3분 이하 원본·글당3개·최대720p MP4/25MB 이하 결과다. 기존 파일을 일괄 변환하지 않는다. YouTube/Vimeo 링크는 원본 플랫폼을 사용하며 GIF·움직이는 WebP는 첫 장면만 저장한다.

QR은 **행사 현장 입장 확인**이며 휴대폰 번호 소유/신원 인증을 대신하지 않는다. 전적·매너 온도는 자동 매칭이나 노쇼 방지 보장 기능은 아니다.

RLS는 브라우저 직접 접근 차단의 기반이며 서버의 소유권·참가/관리 권한 검사를 대신하지 않는다. 운영 DB 역할과 마이그레이션 소유자 분리는 현재 Supabase에서 적용·감사했으며 배포 후 같은 제한 실행 역할을 사용한다.

**사용자 폭주 대응을 실측 완료한 상태는 아니다.** 요청 제한·정원 행 잠금·페이지 제한·인덱스·DB 대기열·영상 처리 한도는 있다. SSE는 Supabase Broadcast 힌트와 정기 DB 재확인을 사용하고 영상은 별도 Worker당 하나씩 처리한다. 여러 Worker는 DB 선점과 토큰으로 중복 완료를 막는다. 영상 Range는 현재 권한 확인 후 실제 부분 스트리밍으로 전송한다. 대규모 운영에는 별도 측정과 개선이 필요하다.

1~4는 프로젝트·도메인·업체 설정이 필요하다. 영상 변환 경로는 배포 환경의 요청 크기·시간·CPU·임시 디스크 제약과 맞아야 한다. 영상 변환은 별도 Worker에서 실행하지만 Web 업로드 본문50MiB와 비공개 공유 저장소는 배포 환경이 지원해야 한다.

5의 구체적인 후속 구현/절차:

- 미첨부 사진·ready 영상의 **30일 보관·정리 원장·명시적 CLI 실행은 완료**했다. 다음은 자동 스케줄·실패 대응과 소프트 삭제/계정·거래 기록의 추가 보관 정책이다.
- 서비스 내 탈퇴 이후 외부 Auth 계정/공급자 연결 해제, 참가 스냅샷·거래 기록의 보관/파기.
- DB와 파일의 암호화 로컬 백업·별도 복원 리허설은 완료했다. 다음은 원격 DB/객체 저장소·별도 키 보관·운영 복구 책임과 목표 시간 검증이다.
- 구조화된 오류 로그·서비스/Worker 상태 확인·발송 대기열/재시도·DB 잠금·디스크/메모리 감시.
- 공개용 정책·문의 연락처·신고 대응 담당, 시작 이후 행사 중단/사고/예외 환불 절차.
- noindex 해제 여부·공개 페이지 범위·사이트맵 결정.
