**2. A — 이용 현황을 확인할 기반**

화면: 기존 관리자 화면에 이용 현황을 추가하고 /admin/metrics로 분리해 상세 조회한다. 기본 기간은 최근7일/28일이며 모든 일자 경계는 한국 시간이다.

최초 표시 지표:

- 가입 회원 수와 가입7일 내 첫 글 북마크·댓글·신청 행동 비율.
- 가입 다음 날부터7일 내 재방문 비율과 월간 반복 활동 회원 수.
- 신청 제출·참가 확정·실제 참석을 각각 집계. 외부 플랫폼으로 나간 클릭을 신청/결제 완료로 집계하지 않음.
- 실제 완료 행사와7일 내 회고 발행 비율, 인증 후기 수.
- 작성자가 아닌 호스트가 자료를 사용해 실제 완료한 행사 수.
- 질문 말머리가 도입된 후에는24시간 내 다른 회원의 첫 답변률을 추가.

DB에 이미 존재하는 가입·신청·출석·후기·발행 기록은 원본에서 집계한다. 재방문이나 화면에서의 첫 행동처럼 없는 정보만 제한된 행동 기록을 추가한다. 거래·참석은 클라이언트가 보고한 값을 믿지 않는다. 댓글·저장 등의 반복 클릭과 재시도는 회원·대상·행동 식별자로 중복을 막고, 테스트·샘플·운영 계정 활동을 따로 표시한다. 집계가 수집 시작 전의 누락된 행동을 임의로 복원하지 않는다.

추가 데이터는 활동점수 테이블 및 알림 작업과 구분한다. 후보는 analytics_activity_days(회원의 날짜별 재방문), analytics_events(필요한 허용 목록 행동), analytics_daily_rollups(일별 합계)이며 원본에서 충분히 계산되는 테이블은 만들지 않는다. 초기 구현은 자체 PostgreSQL 집계로 시작하고 Redis의 기존 공지방 역할을 변경하지 않는다. 새 집계에는 기간·결과 수 제한과 필요한 인덱스를 둔다.

본문·연락처·정확한 좌표·푸시 endpoint·개인 신청 답변은 수집하지 않는다. 운영자 전용 집계 권한을 적용하고, 개별 회원 행동의 공개 순위를 만들지 않는다. 원시 행동90일, 개인 식별이 없는 일별 통계1년 보관을 초기 제안값으로 문서화하며 배포 전 보관/삭제 정책과 맞춘다. 수집 실패가 글쓰기·신청 성공을 실패로 바꾸지 않도록 원본 조회/별도 처리 경로를 사용한다.

완료 검사: 테스트 계정 제외, 중복 제출, 한국 날짜 경계, 집계 분모의 관찰 기간, 탈퇴 이후 식별 정보 처리, 비관리자의 API 접근 차단. 화면에는 비율과 함께 분자/분모·수집 기간을 표시한다.

**3. B — 홈에서 무엇을 할지 쉽게 고르기**

홈 상단은 큰 소개 영역을 계속 늘리는 대신 다음 세 가지 행동을 간결하게 보여준다.

| 시작 행동 | 연결 |
| --- | --- |
| 모임 찾기 | 현재 모집·번개 탐색과 지역/일정 필터 |
| 이야기 나누기 | 이야기 목록, 최신 대화와 질문 |
| 기획 자료 찾기 | 통합 아카이브와 초보 호스트 자료 모음 |

홈 본문 기본 순서는 가까운 일정의 모임 → 오늘의 이야기 → 실제 완료 행사 기록으로 제안한다. 로그인 회원에게는 관련 위치에 관심 콘텐츠를 보여주되 구독이 없으면 일반 목록으로 자연스럽게 시작한다. 자료가 없는 영역은 빈 숫자와 가짜 활동으로 채우지 않고 적절한 시작 안내를 표시한다. 기존 주소, 자료 통합 탭, 행사 관리 진입은 유지하고, 상단 메뉴 재배치는 사용 관찰 후 별도 작업으로 판단한다.

인기 기간은 오늘(KST00시부터), 이번 주(KST월요일00시부터), 전체로 구분한다. 첫 구현은 공개 글이 해당 기간에 받은 유효 좋아요 수를 기준으로 하고 동률은 최신 글·ID로 정렬한다. 누적 인기와 기간 인기의 의미를 UI에 표시한다. 반응 없는 글은 인기 항목을 억지로 채우지 않고 최신 대화에서 제공한다. 게시판 목록의20개 페이지와 모집 목록/카드 전환을 유지한다. 페이지 요청의 기간 조건·정렬을 고정하고 권한 필터, 숨김, 차단, 익명 작성자 보호를 동일하게 적용한다.

후속 측정에서 한 작성자의 과점이나 반복 노출 문제가 확인되면 홈의 편집 영역에 작성자 다양성 규칙을 도입한다. 전체 게시판 인기순에 임의의 감점이나 조작 가능한 신고 건수 점수를 즉시 추가하지 않는다.

광고는 현재 페이지별 공간을 활용하되 모바일 시트의 자동 노출을 늦춘다. 초기 제안은 페이지가 실제로 보인 시간30초 이후·세션1회이며, 로그인/가입·작성/편집·신청·결제·QR 화면이나 다른 모달/입력 중에는 열지 않는다. 기존 닫기·오늘 하루 숨김을 유지한다. 콘텐츠 자동 전환의 일시정지·동작 줄이기 설정도 유지한다. 실제 광고 공급자가 연결되면 노출 정책을 다시 검토한다.

완료 검사: 360px·390px·PC에서 가로 넘침, 키보드 동작, 뒤로가기·새 탭·글 모달, 페이지와 정렬 URL 복구, 한국 날짜/주 경계, 광고가 입력·신청을 가리지 않는지 확인. 새 사용자5~8명이 콘텐츠를 찾고 저장 또는 댓글을 작성하는 경로를 관찰한다. 관찰 전에는 전환 개선을 달성했다고 판단하지 않는다.

**4. C — 대화할 이유와 다시 읽을 동선**

전체·이야기·모집·투표의 상위 구분을 활용한다. 이야기 안의 말머리로 자유 이야기·질문·운영 팁·콘텐츠 분석을 제공하고, 기존 인증 후기는 본래 유형과 참석 검증을 유지한다. 일반 경험담을 인증 후기로 바꾸거나 질문 말머리로 출석 검증을 우회하지 않는다.

기존 topic 필드는 지식·연구소 등의 분류에 사용되므로 덮어쓰지 않는다. 별도 discussionType을 선택 필드로 추가하고, 과거 글은 자유 이야기로 표시하되 원문을 재작성하지 않는다. 질문에는 열린 상태/해결됨과 선택한 답변 댓글ID를 둔다. 질문 작성자만 해결 처리·해제를 할 수 있고 같은 질문의 유효한 타인 댓글만 선택한다. 선택한 댓글이 삭제·운영 숨김 처리되면 해결 상태를 재검토하고 잘못된 답변 링크를 노출하지 않는다.

목록은 최신·기간 인기·답변 기다리는 질문·관심 글로 접근한다. 관심 글은 기존 카테고리/호스트 구독을 사용한다. 비회원·미구독자에게는 일반 콘텐츠와 간단한 관심 선택을 제공한다. 피드 보기만으로 푸시 구독이 늘어나지 않는다. 익명 글은 호스트 구독을 통해 작성자를 추론할 수 없도록 기존 구독/익명 정책을 그대로 적용한다.

스포일러 글에는 주의 표시와 안전한 소개를 제공한다. 목록·통합 검색·OG·알림에서 스포일러 본문이나 이미지가 자동으로 요약되지 않도록 공통 표시 함수를 둔다. 제목에 정답을 적지 않도록 안내하며 필요한 경우 별도 안전한 미리보기 제목을 입력받는다. 상세에서 읽기 선택 후 내용을 펼치는 UX를 제공한다. 이 기능은 유료 정답지의 보안을 대신하지 않으며 유료/진행자 자료는 기존 서버 권한으로 보호한다.

완료 검사: 말머리별 목록·작성·수정·검색, 기존 주제/후기 호환, 답변 선택 권한, 댓글 삭제/숨김, 스포일러 요약·사진·푸시 누출, 피드에서의 차단/익명 정책. 신규 알림을 추가한다면 기존 작업 대기열·설정·중복 방지를 사용한다.

**5. D — 주제와 조건을 중심으로 연결**

새 독립 게시판을 많이 만들지 않고 /topics/{slug}에 주제 소개·관련 이야기·모집·아카이브를 묶는다. 첫 버전은 운영자가 관리하는 소수 주제만 등록한다. 기존 태그의 별칭을 정리하고 명시적 관계로 연결하며, 제목 문자열을 추정해 모든 글을 자동 분류하지 않는다. 주제별 관심 피드는 먼저 제공하고 키워드별 푸시 확장은 이후 실제 수요에 맞춰 진행한다.

아카이브는 이미 있는 필드를 먼저 활용한다.

- 참가 예정 인원: 최소 인원 ≤ 희망 인원 ≤ 최대 인원 조건으로 해당 인원을 수용하는 자료를 찾기.
- 진행 시간: 원하는 최대 시간, 분야, 룰북/템플릿, 무료/유료 자료.
- 실제 사용 사례: 공개 권한으로 확인 가능한 완료 사례가 있는 자료. 작성자의 예시 참가 인원과 구분.
- 두 번째 작업에서 준비 난도·실내외·필요 스태프 수를 선택 필드로 추가. 미입력 자료는 미입력으로 표시하며 추정하지 않음.

유료 자료의 보호된 eventPlan을 그대로 공개 검색 필터와 개수에 사용하지 않는다. 새 공개 검색 메타데이터는 작성자가 공개할 값으로 명시하고, 기존 유료 자료는 동의 없이 보호된 예산·미션·장소를 추출해 노출하지 않는다. 무료/유료 구분은 자료 가격이며 행사 참가비·운영 예산 필터와 혼동시키지 않는다.

완료 검사: 주제 중복/별칭, 삭제/숨김·비공개 원본의 관계 노출, 필터 경계와 미입력, 페이지 조건 일관성, 구매 권한별 검색/본문 분리, 과거 버전과 기존 행사 스냅샷 불변.

**6. E — 행사 이후 해야 할 일을 한곳에**

/management와 /mypage에서 기존 데이터로 다음 행동을 표시한다: 종료 확인 필요 → 회고 작성 중 → 제작진 수락 대기 → 발행 완료 → 다음 행사 준비. 참석자에게는 본인에게 허용된 후기 작성과 전적 확인을 제공한다.

기존 완료 트랜잭션·초안·경력 수락을 재사용하고 별도의 중복 상태를 만들지 않는다. 담당자와 주최자의 권한 차이를 유지한다. 완료 확인을 반복해도 기록·점수·알림이 중복되지 않아야 한다. 회고·사진·참가자 명단·경력을 자동 공개하지 않는다.

알림은 우선 사이트 안의 할 일로 제공한다. 추가 알림이 필요하면 행사 종료 다음 날1회 안내, 미완료인 경우7일 후1회처럼 횟수를 제한하고 설정을 존중한다. 취소·샘플·미참석과 이미 완료한 작업을 제외하고, 같은 작업의 알림 중복을 막는다.

자료를 개선할 때 기존 템플릿 초안 생성과 버전 발행으로 연결한다. 다음 행사 개설은 사용자가 일정·장소·참가비·정원을 다시 확인해야 완료되도록 한다. 이미 개설한 행사의 가이드와 참가 조건은 새 자료 발행으로 바뀌지 않는다.

완료 검사: 행사 개설→신청→QR/담당자 출석→완료→회고 발행→제작진 수락→자료 새 버전→다른 호스트 재개최. 환불 후 실제 참석 이력과 미참석의 구분, 동시/반복 처리, 공개 철회와 구독 해제까지 포함한다.

**7. F — 신뢰 운영과 공개 준비**

기존 신고함·문의·제재/분쟁 이력을 활용해 미처리/검토 중/처리 완료, 담당자, 처리 기한, 응답 이력을 보기 쉽게 정리한다. 이미 있는 필드는 추가 테이블로 중복하지 않는다. 이의 제기는 기존 문의/분쟁의 원조치와 연결하고 거래 당사자가 자신의 분쟁을 판정하지 못하게 한다. 호스트의 행사 당일 연락 경로는 필요한 참가자에게만 제공한다.

프로필에서는 활동점수·참가 확인·제작진 확인·매너 평가를 구분한다. QR과 담당자 확인, 후기 평균과 표본 수를 함께 보여주며 하나의 인증 배지로 신원/안전을 보증한다고 표현하지 않는다. 반복 신고만으로 자동 퇴출하거나 공개 블랙리스트를 만들지 않는다.

외부 준비 목록: Supabase 프로젝트/운영 DB 역할, 카카오·구글 설정, private Storage, HTTPS 도메인, 상시 Worker, 결제 제공자·승인/환불 계약. 비밀키는 환경 설정에서 관리하며 문서/채팅에 기록하지 않는다. 준비 전에는 무료/로컬 흐름과 실패/권한 검사를 진행할 수 있다.

출시 전에는 DB와 파일을 함께 복원하고 실제 Android/iPhone의 설치·알림·로그인·신청·QR을 확인한다. 동시 신청 정원, 공지방 Redis 장애 시 DB 재확인, Worker 중단 후 재시도, 미디어 접근 권한을 검사한다. 로컬 전체 검사 통과를 실서비스 실기기 검증으로 대체하지 않는다.

검색 공개는 승인된 공개 모집 소개·무료 자료·공개 주제 페이지부터 설계한다. 회원 전용 행사 기록과 포트폴리오는 기존 정책을 유지하며 색인용 요약을 임의로 만들지 않는다. noindex 해제·사이트맵·canonical은 배포 주소와 공개 경로가 확정된 뒤 적용한다.

**8. 첫 구현 작업 묶음**

이번 계획을 구현할 때 첫 작업은 다음 세 단위로 나눈다.

1. A1 — 관리자 지표: 지표 정의서·기존 DB 집계·필요한 활동일 기록·권한 검사·관리 화면. 과거 누락 데이터를0으로 표시하지 않고 수집 전으로 표기.
2. B1 — 홈 첫 행동: 세 가지 시작 버튼, 모임/이야기/행사 기록의 순서, 빈 상태와 모바일 읽기, 광고 시점/제외 화면 조정.
3. B2 — 기간 인기: 오늘·이번 주·전체 정렬, 기간/페이지 상태, 목록/모달/검색 링크 호환과 숨김·차단 검사.

각 단위에서 먼저 필요한 스키마·타입 → 서비스/API → 화면 → 의미 있는 회귀 검사 → 문서를 진행한다. 스키마 변경은 추가 마이그레이션으로 적용하며 데이터를 일괄 재작성하지 않는다. 새 측정/순위는 관리자 또는 제한 베타에서 먼저 확인한 후 노출한다. 기존 조회·신청·결제·공지·QR·자료 발행·미디어 검사와 전체 검사/빌드를 확인한다.

첫 묶음과 C의 질문/관심 피드, D의 주제/자료 탐색, E의 행사 종료 후 할 일·기록·재개최 동선을 마쳤으며, F1의 통합 운영 큐·담당/기한·읽기 전용 점검까지 구현했다. F2의 이의신청 연결·30일 보관·암호화 로컬 백업과 별도 DB 복원도 검증했다. 다음은 운영 환경의 인증·Storage·결제 계약·HTTPS·Worker와 실제 Android/iPhone 검증이다. 첫 답변률80%,7일 내 회고 발행률70%, 타인 자료 재사용3건은 초기 운영 실험 목표로 유지하며 개발 완료 기준과 분리한다. 모집 규모·관찰 기간·분자/분모를 함께 표시하고 첫2주 기준값을 확보한 뒤 목표를 조정한다.

**9. 개발과 함께 필요한 운영**

좁은 지역·장르에서 호스트3~5명과 베타 회원을 확보하고 첫 사용자5~8명의 행동을 관찰한다. 운영자는 답 없는 질문 확인, 주간 좋은 이야기/모임 편집, 실제 행사 회고, 첫 호스트 지원을 수행한다. 무료 자료10~20개를 목표로 삼되 실제로 사용할 수 있는 품질과 출처를 확인한다. 개발로 가입자·후기·참가 수치를 인위적으로 만들지 않는다.

광범위한 게시판 추가, 네이티브 앱2종, 범용1:1메신저, AI 자동 매칭, 복잡한 광고/수수료 상품은 초기 반복 사용이 확인된 뒤 별도 계획으로 다룬다.
