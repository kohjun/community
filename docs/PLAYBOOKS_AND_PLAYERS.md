# 룰북·이벤트 템플릿·플레이어·환불 정책

Sliper의 오프라인 이벤트 진행 도구와 P2P 행사 개설, 참가 전적, 한국시간 환불 기준을 구현했다. 기존 모집글·외부 결제 확인·담당자 승인·공지방 서비스를 함께 사용한다. 실제 OAuth, Supabase 클라우드, 결제 플랫폼·정산 연동은 후속 작업으로 남아 있다.

## 화면과 사용 순서

| 화면                                                       | 제공 기능                                                        |
| ---------------------------------------------------------- | ---------------------------------------------------------------- |
| `/archive`                                                 | 룰북·이벤트 템플릿 통합 목록, 종류·주제·키워드 검색·내 자료 보기 |
| `/archive?kind=rulebook`, `/archive?kind=template`         | 선택한 자료 종류의 목록                                          |
| `/archive/new?kind=rulebook`, `/archive/new?kind=template` | 자료 종류를 선택해 작성                                          |
| `/archive/{id}/edit`                                       | 같은 작성 화면에서 작성자 수정                                   |
| `/archive/{id}`                                            | 시나리오·규칙·준비물·멘트·타이머·다운로드·유료 구매 확인         |
| `/archive/{id}/host`                                       | 장소·일정·참가비·정원·신청 방식으로 모임 개설                    |
| `/archive/events/{postId}`                                 | 개설 시 보존한 행사 진행 가이드, 호스트/지정 담당자 전용         |
| `/players`                                                 | 공개를 선택한 플레이어의 역할·지역 탐색                          |
| `/players/{publicId}`                                      | 플레이어 성향·참가 전적·매너 온도·본인 공개 설정                 |
| `/players/review/{postId}`                                 | 같은 행사에 실제로 참가한 플레이어의 매너 평가                   |
| `/management/events/{postId}`                              | 참가 승인·행사 설정·종료 후 전적 기록·취소/환불 요청 처리        |
| `/events/{postId}`                                         | 참가/승인 상태·공지방·환불 안내와 본인 요청                      |

모든 화면은 제공된 공식 로고, 시그니처 `#0A84FE`와 검정·흰색·회색을 사용한다. 공통 서비스 탐색과 여백 중심 카드/목록을 적용했으며 모바일과 라이트 모드를 지원한다. 기존 광고 공간·콘텐츠 좌우 이동·자동 전환·일시정지와 동작 줄이기 설정은 유지한다.

기존 `/templates` 및 상세·작성·편집·개설·행사 진행 가이드 주소는 해당 `/archive` 주소로 이동한다. 데이터 ID, 구매 승인과 행사 원본 사본은 그대로 유지하며 자료를 복제하거나 병합하지 않는다.

## 플레이어·크루 통합 탐색

`/players`의 플레이어 찾기·크루 찾기 탭에서 탐색한다. 플레이어는 로그인 회원에게 공개 동의를 반영해 역할 성향·관심 지역으로 찾고, 공개 크루는 `/players?tab=crews`에서 이름·주제·내 크루로 찾는다. 검색 조건은 주소에 반영되고 크루 페이지 번호도 유지된다. 기존 `/crews` 목록 주소는 검색 조건을 보존해 크루 탭으로 이동하며, 개인 프로필·크루 상세·생성·가입 승인과 관리 권한은 기존 주소와 정책을 사용한다.

## 자료 초안·발행 버전·출처

자료 편집은 초안으로 저장하고 공개 동의와 변경 요약을 확인한 뒤 새 버전을 발행한다. 공개된 이전 버전은 초안 편집으로 변경하지 않는다. 과거 버전 열람·허용된 원본의 파생 초안·자신의 행사 회고에서 템플릿 만들기와 개설 당시 버전 보존을 추가했다. [자료 버전과 운영 지식 재사용](KNOWLEDGE_REUSE_AND_VERSIONS.md)에 상세 사용법과 권한을 정리했다.

## 통합 아카이브와 무료/유료 자료

룰북과 이벤트 템플릿은 아카이브의 자료 종류로 구분한다. 목록과 작성·상세 화면을 통합하고, 필터에서 전체·룰북·이벤트 템플릿을 고른다. 룰북은 규칙·진행 노하우 중심, 이벤트 템플릿은 재사용할 모임 구성 중심으로 안내하되 동일한 자료 저장 구조를 사용한다. 작성 항목은 제목·요약·카테고리·시나리오·규칙/점수·준비물·진행자 멘트·권장 인원·진행 시간·태그·라운드 이름/초 단위 타이머·배포 가격이다. 라운드는 1~20개, 준비물은 최대 40개, 태그는 최대 5개다.

무료 자료는 시나리오 전문과 도구를 공개하고 Markdown으로 내려받을 수 있다. 유료 자료는 외부 구매 링크가 필수다. 열람 권한이 없는 응답에는 공개 요약만 담고 전문·준비물·진행자 가이드·타이머 구성은 `payload: null`로 반환한다.

유료 이용 순서:

1. 외부 플랫폼에서 구매·결제한다.
2. Sliper에서 주문 번호와 전달 내용을 입력해 구매 확인을 요청한다.
3. 자료 작성자가 외부 구매 내역을 확인하고 승인한다.
4. 승인된 사용자가 전문·타이머·다운로드·모임 개설을 이용한다.

작성자만 구매 요청 목록을 조회하고 승인·반려·열람 권한 회수를 처리한다. 같은 자료의 구매 번호를 여러 사용자에게 재사용할 수 없다. 구매 대기 또는 승인된 이용자가 있는 자료는 가격/구매 링크 변경과 삭제를 제한한다. 자료 전문은 다운로드 API에서도 접근 권한을 다시 확인한다. 열람 권한 회수 후 새 다운로드와 새 행사 개설은 차단하며, 이미 개설한 행사의 담당자용 진행 사본은 보존한다. 공개·재배포·유료 운영 조건은 자료 작성자가 제시한 이용 조건을 확인해야 한다. 화면의 승인 체크는 실제 결제나 환불 명령을 실행하지 않는다. 자료 판매용 자동 웹훅 연동은 아직 구현 범위에 포함하지 않는다.

작성자 수정은 `{ content, expectedUpdatedAt }`를 전달한다. 서버가 현재 수정 시각과 비교하고 오래된 편집은 `CONFLICT`로 반환해 다른 탭의 저장을 덮어쓰지 않는다. 자료 종류는 수정할 수 없다.

자료의 진행 기록은 해당 자료로 개설한 행사 중 실제로 종료되어 담당자가 완료 확인했고, 참가 완료 전적이 있는 행사를 집계한다. 완료 확인 이전·취소·숨김 행사와 이용 제한된 주최자는 집계에서 제외한다. `sample=true` 행사와 허구 참가자는 실제 기록에 포함하지 않는다. 이 수치는 전문 심사·안전 검증·게임 품질 인증이 아니다.

타이머는 라운드 선택·시작/일시정지·초기화·다음 라운드를 제공하고 실제 경과 시간으로 계산한다. 준비물 체크리스트 상태와 타이머는 열린 화면의 로컬 상태이며 여러 담당자에게 동기화하지 않는다.

## 일반 사용자의 P2P 행사 개설

무료 또는 구매 승인된 자료에서 모임을 열 수 있다. 로그인된 사용자가 호스트가 되어 제목·구체적 장소·한국시간 시작/종료·참가비·정원·참가 안내를 입력한다. 시작은 미래여야 하고 종료는 시작보다 늦어야 한다. 정원은 자료의 권장 최소/최대 인원 안에서 선택한다.

하나의 트랜잭션에서 모집글, 행사 설정, 원본 자료의 진행 가이드를 생성한다. 기본 참가 승인 모드는 수동이다. 원본 자료의 제목·작성자·시나리오·규칙·준비물·멘트·타이머를 개설 시점 내용으로 보존하므로 원본의 이후 수정·삭제가 행사 진행 가이드를 바꾸지 않는다. 원저작자와 출처를 모집글에 표시하되 유료 자료 전문은 공개 모집글에 넣지 않는다. 보존한 전문은 해당 행사의 호스트 또는 지정 담당자만 읽을 수 있다.

외부 신청 링크가 있으면 그 플랫폼에서 신청·결제를 완료하고 Sliper에서는 사후 승인과 공지방을 제공한다. 외부 링크가 없으면 기존 Sliper 참가 신청을 사용하고 유료 결제·정산은 연결할 외부 플랫폼이 처리한다. Sliper 내부 신청의 무료 참가 즉시 확정, 유료 정원 예약, 결제 확인 및 공지방 자동 초대 동작을 재사용한다. 상세 외부 연동 계약은 [참가 신청 문서](PARTICIPATION.md)를 참고한다.

## 플레이어 성향과 신뢰 기록

본인은 두뇌형(`brain`), 피지컬형(`physical`), 전략가(`strategist`), 트릭스터(`trickster`) 중 선호 역할을 선택하거나 탐색 중으로 남길 수 있다. 자기 선택 성향과 담당자가 실제 행사에서 관찰한 역할 전적은 별도로 표시한다.

행사 호스트 또는 지정 담당자는 정확한 종료 시각을 등록하고 행사가 끝난 뒤 참가 확정 사용자의 실제 참가/미참석·우승 여부·관찰한 역할을 기록한다. 자신의 전적은 다른 담당자가 확인해야 한다. 기존 전적의 결과를 변경하려면 수정 사유가 필요하며 담당자 확인 기록을 남긴다. 미참석 전적에는 우승이나 역할을 지정할 수 없다.

매너 평가는 종료된 같은 행사에서 담당자가 실제 참가를 확인한 플레이어끼리만 가능하다. 자기 평가는 차단하고 행사·평가자·상대방 조합마다 한 번만 평가한다. 긍정 평가 항목은 규칙 준수/배려, 부정 평가 항목은 진행 방해다. 화면에는 평가 집계만 공개하며 개별 평가자와 담당자 수정 사유를 공개하지 않는다.

매너 온도는 아래 값을 합산한 뒤 0~99.9℃ 범위로 제한하고 소수 첫째 자리로 표시한다.

| 항목                         | 온도 변화 |
| ---------------------------- | --------: |
| 시작 온도                    |     36.5℃ |
| 실제 참가 완료               |     +0.1℃ |
| 같은 행사 참가자의 긍정 평가 |     +0.2℃ |
| 같은 행사 참가자의 부정 평가 |     −0.5℃ |
| 담당자가 확인한 미참석       |       −2℃ |

샘플 행사 전적과 평가는 매너 온도·실제 참가·진행 횟수에서 제외한다. 기능 체험 전적은 프로필 상세에서 별도로 표시할 수 있다. 전적과 온도는 신뢰 판단을 돕는 참고 자료이며 노쇼·트롤링을 완전히 차단하는 시스템은 아니다.

탐색 공개(`matchingVisible`)와 행사 제목/전적 상세 공개(`historyPublic`)는 기본 `false`다. 공개 프로필 URL에는 로그인 ID 대신 별도의 `publicId`를 사용한다. 공개 프로필에는 닉네임·소개·지역·성향·전적 집계가 표시되고 연락처·신청 메모·로그인 ID는 표시하지 않는다. 탐색 목록은 공개를 선택한 플레이어만 역할/지역 조건으로 제공하며 자동 매칭이나 자동 방 배정은 하지 않는다.

## 한국시간의 달력 날짜로 계산하는 환불

사용자가 선택한 기준은 `Asia/Seoul`의 **달력 날짜 차이**다. 시작 시각까지 남은 24시간 묶음으로 계산하지 않는다. 행사 시작일에서 취소·환불 요청일의 한국시간 날짜를 뺀 결과로 비율을 결정한다.

| 한국시간 기준 행사까지 남은 날짜 | 환불 비율 |
| -------------------------------- | --------: |
| 5일 이상                         |      100% |
| 4일                              |       80% |
| 3일                              |       60% |
| 2일                              |       40% |
| 1일                              |       20% |
| 당일 또는 이후                   |        0% |

예를 들어 한국시간 10월 10일 오후 7시 행사라면 10월 5일 밤 11시 59분까지 100%, 10월 6일 0시부터 80%다. 12,345원에 80%를 적용하면 `floor(12345 × 80 / 100) = 9,876원`이다. 원 단위 미만은 버린다.

신청 시 참가 금액·행사 시작일·정책 버전을 저장한다. 취소·환불 요청 접수 시에는 요청 시각·비율·환불 예정액·사유를 다시 보존하며, 담당자가 며칠 뒤 처리하더라도 요청 당시 비율을 사용한다. 일정이 있는 유료 Sliper 내부 신청에는 환불 정책 동의가 필요하다. 활동 중인 참가 내역이 있으면 설정한 일정 변경을 제한한다.

결제가 확인된 유료 참가자는 0% 기간에도 참가 취소를 요청할 수 있다. 동일 참가의 대기 요청은 중복 생성하지 않는다. 요청만으로 결제·참가·공지방이 즉시 취소되지는 않는다.

담당자 처리 순서:

1. 관리 대시보드에서 요청 당시 계산 금액과 사유를 확인한다.
2. 외부 결제 플랫폼에서 해당 금액의 환불과 참가 취소를 실제 처리한다. 0원은 금전 환불 없이 참가 취소를 처리한다.
3. Sliper에서 외부 처리 완료 체크와 실제 환불 금액을 확인한다.
4. 거래 기록과 참가 상태를 갱신하고 공지방 접근을 해제한다.

수동 완료의 실제 환불액은 요청 시점 계산액과 일치해야 한다. 반려는 사유가 필수다. 서명된 결제 웹훅에는 `refundAmountKRW`로 실제 환불액을 전달할 수 있으며 원래 결제액을 초과하거나 결제 완료 알림에 환불액을 함께 전달하면 거절한다. 이 필드는 일부 금액 환불과 0원 취소를 기록하기 위한 것이고 Sliper가 외부 플랫폼에 환불 명령을 내리지 않는다.

기존 행사에 시작/종료 일정이 없으면 최초 일정 설정은 허용한다. 다만 과거 참가 신청에 저장된 `eventStartsAt`가 없으면 나중에 행사 설정에 일정이 생겨도 그 참가의 자동 환불 예상액을 만들거나 새 정책을 소급 적용하지 않는다. 해당 참가자는 담당자에게 기준을 문의해야 한다. 자료 구매 환불은 외부 구매 플랫폼이 처리하며 위 행사 참가 취소 요청과 별개다.

## 데이터와 API 경계

기존 20개 테이블에 아래 7개 테이블을 추가해 Sliper 테이블은 총 27개다. 모두 RLS를 활성화하고 직접 공개 조회 대신 서버 서비스가 명시적인 DTO를 반환한다.

| 테이블                    | 용도                                 |
| ------------------------- | ------------------------------------ |
| `library_entries`         | 룰북/템플릿 원본·가격·구매 링크      |
| `library_access_requests` | 외부 구매 확인과 전문 열람 권한      |
| `template_provenance`     | 행사 개설 시점의 원본 내용·원저작자  |
| `player_preferences`      | 선호 역할과 공개 설정                |
| `event_results`           | 담당자가 확인한 참가 전적            |
| `manner_reviews`          | 같은 행사 플레이어의 매너 평가       |
| `refund_requests`         | 요청 시점 정책/금액과 실제 처리 결과 |

핵심 서버 모듈은 `src/server/library-service.ts`, `player-service.ts`, `refund-service.ts`다. 동일 이벤트의 변경은 기존 모집글 행 잠금 순서를 공유하며 참가·결제·공지방 트리거와 함께 트랜잭션으로 처리한다. 쓰기 요청은 인증과 동일 출처를 검사한다.

| API                                                   | 기능                            |
| ----------------------------------------------------- | ------------------------------- |
| `GET/POST /api/library`                               | 목록/작성                       |
| `GET/PUT/DELETE /api/library/{id}`                    | 상세/버전 검사 수정/삭제        |
| `GET /api/library/{id}/download`                      | 접근 권한 검사 후 Markdown 파일 |
| `POST /api/library/{id}/access`                       | 유료 구매 확인 요청             |
| `GET /api/library/{id}/requests`                      | 작성자의 구매 요청 조회         |
| `POST /api/library/{id}/decision`                     | 작성자의 승인/반려/권한 회수    |
| `POST /api/library/{id}/host`                         | 자료에서 P2P 행사 개설          |
| `GET /api/library/{postId}/event-template`            | 담당자 전용 원본 보존 자료      |
| `GET /api/players`                                    | 공개 플레이어 역할/지역 탐색    |
| `GET/PUT /api/players/me`                             | 본인 플레이어 설정              |
| `GET /api/players/{publicId}`                         | 공개 프로필과 공개 범위 내 전적 |
| `GET/PUT /api/players/events/{postId}/records`        | 담당자의 전적 목록/기록         |
| `GET/POST /api/players/events/{postId}/manner`        | 참가자의 평가 대상/평가 등록    |
| `GET/POST /api/participation/events/{postId}/refunds` | 권한 범위의 요청 조회/본인 요청 |
| `PUT /api/participation/refunds/{requestId}/resolve`  | 담당자의 외부 처리 확인/반려    |

목록은 커서로 더 보기 처리한다. 자료 검색·본인 목록, 플레이어 역할/지역, 구매/환불 관리 목록은 해당 조회 범위와 사용자에 묶인 커서를 사용한다. 다른 조회 범위의 커서를 재사용하면 거절한다.

## 로컬 체험과 검증

마이그레이션과 기존 로컬 DB setup을 완료한 `C:\Sliper`에서 실행한다.

```powershell
npm run db:migrate
npx tsx scripts/seed-library-demo.ts
npx tsx scripts/seed-player-demo.ts
npm run dev
```

체험 데이터는 `LOCAL_DATABASE=1`과 `127.0.0.1:55432/sliper_dev` 주소를 함께 검사한다. 무료 룰북·무료/유료 템플릿과 허구 플레이어·완료 행사 체험 전적을 준비하며 실제 결제나 구매, 현장 검증 이력을 생성하지 않는다. 유료 샘플의 `example.com` 주소는 실제 구매처가 아니다. 재실행은 기존 사용자/샘플 수정과 승인 상태를 덮어쓰지 않는다.

```powershell
npm run check
npm run test:api
npm run test:features
npm run build
```

`test:api`와 `test:features`는 개발 서버와 실제 로컬 PostgreSQL이 필요하다. `test:features`는 자료 CRUD·비공개 유료 전문·템플릿 행사 개설·환불 동의·80% 환불 처리·전적 권한·프로필 개인정보·공통 탐색을 HTTP로 확인한다. `build`는 운영 산출물과 서버 파일 추적 정책을 검사한다. 서명 결제 콜백 테스트는 [참가 신청 문서](PARTICIPATION.md)의 별도 운영 테스트 서버에서 `npm run test:payments`로 실행한다. 2026-10-01 최종 검사: 일반 회귀 145개·기존 HTTP/SSE 9개·자료/플레이어 HTTP 2개·번개 HTTP 1개·운영 서명 웹훅/정원 경합 3개, 총 160개 통과. 포맷·타입·Drizzle 검사와 운영 빌드도 통과했다. 실제 플랫폼/OAuth의 검증으로 간주하지 않는다. 브라우저 직접 클릭과 시각적 회귀는 자동 검증하지 않았다.

2026-10-06 아카이브 통합 검증: 전체 검사 623개, 실제 로컬 HTTP/PostgreSQL 통합 검사 2개, 배포 빌드·서버 파일 추적 검사 통과. 혼합 목록의 종류별 필터와 커서 페이지, 구형 템플릿 주소의 308 이동, 양쪽 자료의 상세·개설·담당자 가이드와 기존 환불 흐름을 확인했다. 개발 서버를 유지한 채 검증했다.
