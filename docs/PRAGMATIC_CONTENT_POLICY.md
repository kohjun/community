# 비용을 제한한 콘텐츠 정책 검사 — 2026-10-18

## 적용 방식

명백한 일부 욕설·차별 비하어·집단 대상 위협·성적 서비스 알선 및 음란물 배포 홍보 문구를 로컬 규칙으로 검사한다. 외부 AI·OCR·영상 분류 API, 새 대기열·서버·DB 테이블을 추가하지 않았다. 자동 검사는 모든 유해 콘텐츠를 판별하는 기능이 아니다.

이미지·영상·캡처 속 문구, 인용과 비평의 문맥, 규칙에 없는 우회 표현은 신고를 받은 운영자가 판단한다. 모든 업로드를 사전 승인 대기로 돌리지 않는다. 신고가 접수되어도 자동으로 게시물을 숨기거나 계정을 제재하지 않으며, 기존 운영자가 이유를 남기고 숨김·복원·경고·이용 제한을 결정한다.

신고 사유에 ‘혐오·차별’과 ‘음란·성적 콘텐츠’를 추가했다. 기존 varchar 필드와 호환되어 데이터베이스 마이그레이션은 필요 없다. `/admin`의 신고함과 `/admin/operations`에서 기존 운영 절차를 사용한다. 원문 링크는 현재 열람 권한을 유지하므로 숨김·삭제된 본문을 우회해 보여주지 않는다.

## 자동 검사 대상

- 일반 글·댓글의 생성과 수정: 제목, 본문, 미리보기, 태그, 투표 주제/선택지, 공개 안내 등.
- 번개 및 자료 기반 모임 생성, QR 인증 후기.
- 룰북·템플릿 최초 발행, 공개 자료 수정, 초안 발행과 수정 제안 최종 승인.
- 행사 기록의 발행과 공개 상태 수정.
- 장소·크루·프로필의 새 공개 문구, 크루 공지, 공개 제작 기여 기록.
- 모집 질문의 변경과 담당자 공지 메시지.

단순 작성 화면만 검사하지 않고 공통 서버 서비스에서도 필수 검사한다. 브라우저 검사를 건너뛰거나 API로 직접 요청해도 같은 정책이 적용된다. 글·댓글 작성창은 같은 규칙을 미리 실행해 제한된 필드와 이유를 바로 보여주고 입력을 유지한다.

## 동작과 오탐 방지

- 유니코드 정규화·제로폭 문자 제거와 제한된 공백/기호 우회를 처리한다. 문장이나 서로 다른 필드를 무작정 이어 붙이지 않는다.
- 일반 정체성 단어, 연애·성비 안내·프로그램 비평, 정상 단어인 ‘시발점·시발역’, ‘도시 발전·낚시 발판’ 등을 일괄 차단하지 않는다.
- Markdown은 기존 렌더러와 같은 파서를 재사용해 실제 텍스트를 추출한다. 링크·강조·문자 엔티티로 글자를 쪼개는 방식도 검사한다.
- 리치 문서는 인접한 글자와 이미지 설명·이전 Markdown을 검사한다. 문단 경계를 유지하고 ID·임베드 URL·파생 검색용 Markdown을 중복 검사하지 않는다.
- 차단 안내에 입력 원문·금칙어 목록·내부 규칙 ID를 노출하지 않는다. 오류는 기존 VALIDATION 응답이며 글·댓글·알림·점수가 부분 저장되지 않는다.

한국어 인용·풍자·동음이의어를 완벽하게 이해하지 않는다. 오탐은 표현을 수정하거나 운영자에게 문의할 수 있다. 순수 규칙 목록은 `src/domain/content-policy.ts`에서 검증 사례와 함께 제한적으로 관리한다. 이번 버전은 자동 검사 확정만으로 이용 제한이나 공개 블랙리스트를 만들지 않는다.

## 보호하는 기존 흐름

비공개 자료·행사 기록 초안은 내용을 보관하고 고칠 수 있도록 저장을 허용하고, 공개 시점에 검사한다. 신고·문의·이의신청의 증거 인용, 참가자의 비공개 답변·연락처, 결제·환불·행사 취소 사유에는 이 필터를 적용하지 않는다. 이미 저장된 자료를 일괄 재검사·삭제하거나 계정 권한을 변경하지 않았다.

프로필·장소·크루의 기존 문구를 바꾸지 않고 다른 설정만 변경할 때는 그 기존 문구 때문에 저장을 막지 않는다. 공개 문구를 새로 바꾸는 경우에 검사한다. 기존 글을 읽을 때마다 검사를 다시 수행하지 않는다.

## 비용과 운영

추가 유료 API 호출·API 키·월 구독은 필요 없다. 기존 서버에서 작성·수정할 때만 짧은 로컬 검사를 수행하고, 홈·목록·상세 조회에는 새 SQL이나 검사 호출을 추가하지 않았다. 이미 설치된 Markdown 파서 두 개를 직접 의존성으로 명시하여 기존 파싱 코드를 재사용한다.

사진·영상 자동 판별, OCR, 외부 링크 목적지 검사, 새로운 악성코드 검사는 구현하지 않았다. 기존 이미지 압축·파일 형식 검사와 영상 Worker, 비공개 Storage 접근 제어는 유지된다. 사람의 검토 시간은 필요하며 운영자는 접수된 신고를 확인해야 한다.

## 검증

- 순수 규칙·Markdown/리치 문서 추출·글/댓글 저장·대체 공개 경로·신고 UI의 격리 검사33개 통과.
- 제한된 글의 미디어 연결·점수 지급, 제한된 댓글의 알림 발송이 발생하지 않는 것을 확인했다.
- 비공개 초안 보존, 발행 시 검사, 기존 공개 글의 수정 실패 시 원문·버전·반응 보존을 확인했다.
- 실제 서비스 DB에 테스트 콘텐츠를 추가하거나 기존 글을 변경하지 않았다.

- `npm run check`: 비밀값·서식·타입·전체 테스트 **1,001/1,001**·Drizzle 검사 통과.
- 분리한 동일 소스의 webpack 운영 빌드 통과. 서버 trace **110개·오류0개**.
- standalone 실제 파일 **2,515개**, 비밀 파일·영상 Worker 바이너리 **0개**. QA용 의존성 junction만 산출물에서 제거하고 원본 의존성은 보존했다.
- PC와 Android Pixel 7 Chrome 에뮬레이션에서 실제 글·댓글 작성 컴포넌트를 확인했다. 제목·본문·댓글 차단 안내, 입력 보존, 제한 시 저장 콜백0회, 수정 후1회 호출을 확인했다. 브라우저 오류·실제 API 요청은0회다. 가짜 저장 콜백을 사용한 격리 검사이며 실제 회원 로그인·Supabase 저장 E2E나 실기기 검사는 아니다.
- 글·댓글의 실제 저장 차단과 부분 저장 방지는 별도의 PGlite 통합 테스트로 확인했다. 실제 서비스 DB를 수정하지 않았다.

로컬 개발 서버의 홈과 이용규칙 페이지도 HTTP200으로 확인했다. 자동 이미지 판별이나 사람이 모든 신고를 확인했다는 의미는 아니며, 공개 서비스 운영 시 신고 검토 담당자가 필요하다.
