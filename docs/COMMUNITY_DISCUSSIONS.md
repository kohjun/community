# 이야기·관심 피드 구현 (C 단계)

기준일: 2026-10-11 · 프로젝트: `C:\Sliper` · 로컬 PostgreSQL 마이그레이션: `0057_gray_maginty.sql`

## 사용 흐름

- `/stories`에서 최신 이야기, 기간 인기, 답변 기다리는 질문, 관심 글을 선택한다. 기존 20개 페이지와 카테고리·세부 주제·태그·기간 정렬을 유지한다. 말머리와 탐색 조건은 URL에 보존한다.
- 이야기 작성 시 자유 이야기 / 질문 / 운영 팁 / 콘텐츠 분석을 선택한다. `topic`은 지식·연구소·크루 세부 주제로 유지하며 인증 후기는 기존 검증을 따른다. 이전 일반 이야기는 저장 내용을 바꾸지 않고 자유 이야기로 표시한다.
- 질문 작성자는 타인이 남긴 같은 질문의 댓글 또는 대댓글을 채택·해제한다. 채택 답변은 댓글 첫 페이지 밖에 있어도 상세 상단에 제공한다. 해결 상태는 목록에도 표시된다.
- 관심 글은 기존 카테고리·호스트 구독으로 구성한다. 비회원/구독 없음에는 일반 글과 `/notifications#interests` 설정 안내를 제공한다. 조회만으로 구독·푸시 권한을 변경하지 않는다. 익명 글은 호스트 구독 조건으로 포함하지 않으며 카테고리 구독으로는 익명을 유지해 포함한다.
- 스포일러 설정 시 안전한 미리보기 제목은 필수이며 소개는 선택이다. 목록·인기/추천·통합 검색·공유 메타데이터에는 안전한 제목/소개를 표시하고 본문·문서·사진·영상·투표·태그를 미리보기에서 제거한다. 상세는 ‘본문과 댓글 펼쳐보기’를 누르면 내용을 표시한다.

모바일에서는 탐색 버튼이 줄바꿈되며, 기존 파란색·라이트 톤·Pretendard를 유지한다. 실제 휴대폰의 시각·터치 검증은 별도다.

## 저장과 API

| 항목 | 구현 |
| --- | --- |
| 이야기 필드 | `posts.discussion_type` (nullable), `spoiler`, `spoiler_title`, `spoiler_summary` |
| 질문 해결 | `question_resolutions` 질문 게시글별 1개; 질문 ID, 댓글 ID, 채택 회원, 시각 |
| 채택 무결성 | 같은 게시글의 댓글 복합 FK, 질문 작성자/타인 답변 DB 가드, RLS 및 Data API 권한 차단 |
| 작성·수정 | 기존 `/api/community/posts`와 Server Actions에서 선택 필드를 받음. 이전 클라이언트가 필드를 생략하면 수정 시 기존 설정 보존 |
| 탐색 | `/api/community?discussionType=question&focus=unanswered&page=1&limit=20`; `focus=interests`, 기본 `all` |
| 채택 | `POST /api/community/posts/{id}/resolve` — `{commentId: UUID 또는 null, expectedUpdatedAt: ISO 시각}` |
| 검색 | `/api/search?q=...&discussionType=tip`; 기존 분류·카테고리·페이지와 결합 가능 |

채택 요청은 게시글 행을 잠그고 서버의 정확한 수정 시각과 비교한다. 같은 버전의 동시 요청은 하나만 반영하고 나머지는409로 거절한다. 본인 댓글·다른 질문의 댓글·삭제/숨김/차단/탈퇴·제한 상태의 답변은 채택하지 못한다. 새로운 알림·점수는 지급하지 않아 중복 지급 경로가 생기지 않는다.

해결 상태는 원본 댓글의 현재 가시성을 읽을 때 재평가한다. 삭제·운영 숨김·조회자의 차단·답변자 탈퇴/제한 시 채택 ID와 답변을 표시하지 않고 미해결 탐색에 포함한다. 숨김/차단이 해제되어 다시 유효해지면 기존 채택이 보일 수 있다. 작성자가 질문을 다른 말머리로 바꾸면 채택 관계를 제거한다.

## 스포일러 표시 정책

`domain/discussions.ts`의 미리보기 함수와 `server/discussion-policy.ts`의 조회 표현식을 사용한다. 상세의 반응·수정 결과를 클라이언트 목록에 합칠 때도 다시 미리보기로 변환한다. 통합 검색은 스포일러 글의 원래 제목·본문·태그를 검색 조건에 포함하지 않아 숨긴 정답으로 결과를 찾아내지 못하게 한다. 자료 연결과 행사 기록의 관련 글 제목에도 안전한 제목을 사용한다.

알림함은 조회 시 현재 스포일러 설정을 확인한다. 푸시 발송 직전에도 설정을 확인해 이미 대기 중이던 제목·본문을 일반 안내로 바꾼다. 기존 댓글 알림·구독·중복 방지·재시도는 유지한다. 이미 기기에 전달된 알림을 소급 삭제하지는 않는다.

스포일러는 공개 글의 읽기 선택 UX이다. 상세 API/상세 페이지의 React 데이터에는 원문이 포함될 수 있고, 원본 미디어에 새로운 비밀 자료 권한을 부여하는 기능이 아니다. 유료/진행자 자료의 서버 권한과 회원 전용 행사 기록 미디어 정책은 그대로 적용된다. 작성자는 미리보기 제목·소개에도 정답을 넣지 않아야 한다.

## 관리자 질문 지표

`/admin/metrics`에 ‘질문 24시간 내 답변’을 추가했다. 선택 기간에 등록된 질문 중 등록 후24시간 관찰을 마친 질문을 분모로 삼는다. 그중 다른 일반 회원의 공개 댓글이 등록 후24시간 이내에 존재하는 질문 수를 분자로 표시한다. 같은 질문의 댓글은 여러 개여도 한 번만 센다.

샘플·테스트/운영 계정·제한/탈퇴 계정 및 삭제/숨김 질문·답변은 제외한다. 본인 답변과 관찰 중인 새 질문은 성공/실패로 세지 않는다. 채택률과는 다른 지표이며 현재 남은 공개 댓글 기준이므로 삭제·숨김·말머리 변경에 따라 값이 바뀐다. 분모가0이면 ‘관찰 중’으로 표시한다. 별도의 본문·회원 행동 로그는 수집하지 않는다.
