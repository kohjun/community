# 네이버 지도 기반 장소 선택 — 2026-10-29

## 이용 흐름

모집글·번개·이벤트 맵의 장소 등록을 ‘주소·지도에서 선택 → 도로명·지번 주소 검색 → 지도에서 위치 확인 또는 핀 이동 → 상세 장소 입력 → 이 위치로 선택’으로 통일했다.

- 모집글 작성·수정, 번개 열기, 템플릿으로 행사 열기, 행사 관리, 이벤트 맵 장소 등록·수정에 공통 선택기를 사용한다.
- 장소 등록에서 현재 위치 사용과 위도·경도 직접 입력을 제거했다. 내 주변 검색과 이벤트 맵 탐색의 현재 위치 버튼은 검색 기준으로만 사용한다.
- 참가 신청 화면과 모집 정보에서 주소를 확인하고 네이버 지도로 이동할 수 있다.
- 기존 공유 장소 검색과 행사 기록 연결은 유지한다. 공유 장소를 새로 선택한 경우 서버에서 확인한 이름·주소·좌표를 사용한다.
- 이름만으로 찾기 어려우면 네이버 지도에서 주소를 확인할 수 있는 링크를 제공한다. Geocoding은 주소 검색이며, 별도의 네이버 지역 검색 API를 연동한 상호 자동완성은 아니다.

## 저장과 일관성

- 기존 `posts.location`, `community_venues.address`와 행사·장소의 위도/경도 열을 재사용한다. 새 테이블과 DB 마이그레이션은 없다.
- 지도에서 선택한 행사장의 좌표를 자동으로 저장하며, 본인의 GPS 좌표를 행사장으로 자동 저장하지 않는다. 거리·반경 검색에는 선택한 행사장 좌표를 계속 사용한다.
- 일반 모집의 주소·상세 장소는 합쳐 120자, 공유 장소의 주소·상세 장소는 200자까지다. 초과하면 확인 버튼을 사용할 수 없다.
- 좌표를 클릭한 경우 Reverse Geocoding으로 주소를 확인한 뒤에만 확정한다. 실패하거나 주소가 없으면 주소 검색으로 다시 선택하도록 안내한다.
- 주소 결과가 기존 핀을 임의로 건물 중심으로 옮기지 않는다. 마지막으로 클릭한 지점을 유지한다.
- 조회 중 다른 위치 선택·입력·닫기·컴포넌트 해제가 발생하면 이전 결과는 반영하지 않는다.
- 설정 저장은 기존 트랜잭션에서 주소와 좌표를 반영한다. 저장 성공 후 목록 캐시를 비운다.
- 주최자 권한, 완료 행사와 참가 내역이 있는 행사의 장소 변경 제한을 유지한다. 글 수정에서도 주소만 바꾸는 우회를 차단한다.
- 기존 데이터는 일괄 변환하거나 삭제하지 않았다. 작성자가 주소·지도 선택으로 수정할 수 있다.

## 네이버 설정

기존 Web Dynamic Maps·Geocoding에 더해 사용자가 같은 Application의 Reverse Geocoding을 활성화했다. `https://sliper.kr`에서 공개 장소를 이용한 주소 검색·좌표→주소 변환이 모두 정상 응답하는 것을 확인했다. 별도 Secret을 브라우저에 추가하지 않았으며, 기존 공개 Key ID를 사용한다.

선택기 내부 지도는 선택기를 열었을 때만 사용한다. 타이핑할 때마다 조회하지 않고 검색 버튼·Enter 또는 지도 클릭으로 요청한다.

공식 문서: [네이버 지도 주소·좌표 검색 예제](https://navermaps.github.io/maps.js.ncp/docs/tutorial-3-geocoder-geocoding.example.html), [Service 응답 형식](https://navermaps.github.io/maps.js.ncp/docs/naver.maps.Service.html).

## 검증

- 전체 `npm run check`: 1,105개 테스트, 형식·타입·비밀값·Drizzle 검사 통과.
- 네이버 주소 응답 파싱, 클릭한 좌표 유지, 취소·타임아웃·늦은 응답 차단과 좌표 축·링크 인코딩 회귀 검사를 추가했다.
- 격리된 PGlite에서 주소·좌표 동시 저장, 타인 수정 거부, 같은 좌표의 주소만 바꾸는 참가 제한 우회 거부, 공유 장소의 서버 원본 주소 사용을 확인했다.
- Linux 운영 빌드와 서버 추적 117개 manifest 검사가 통과했다. 배포 산출물에 비밀 설정·로컬 데이터가 없는지 확인했다.
- 브라우저 검증은 전용 테스트 계정과 새 컨텍스트를 사용한다. 게시글·장소·번개 등록 등 변경 API는 차단하고, 실제 네이버 API와 제출할 데이터만 확인한다. 운영 검증의 최종 결과는 아래 기록과 Git 제외 `.local/location-qa`를 참고한다.
