# 마음의 온도 — 웹게임 기획안

작성일: 2026-11-09

상태: 개발 전 기획안. **확정**은 대화에서 정한 내용, **제안**은 구현 가능하도록 채운 기본안이며 최종 결정이 필요한 항목이다.

## 1. 게임 소개

같은 상황을 보고도 사람마다 느끼는 정도는 다르다. 참가자들은 한자리에 모여 상대의 말과 표정을 듣고, 어떤 상황을 얼마나 강하게 느끼는지 추리한다. 서로의 기준을 맞히는 과정과 결과를 보고 이야기를 나누는 시간이 게임의 핵심이다.

| 항목      | 내용                                                        |
| --------- | ----------------------------------------------------------- |
| 게임 이름 | 마음의 온도                                                 |
| 장르      | 대화 · 눈치 · 심리 추리                                     |
| 모드      | 기본 모드, 추리 모드                                        |
| 참여 방식 | 현장에서 말로 설명·대화하고 각자 휴대폰으로 입력            |
| 목적      | 상대의 숫자 또는 여러 상황의 숫자 순서를 가장 가깝게 추리   |
| 점수      | 차례/라운드별 가장 가까운 참가자에게 1점. 동점자는 모두 1점 |

**확정:** 기본 모드에서는 힌트 제공자가 한자리에서 말로 설명한다. 추리 모드에서는 참가자들이 상황과 숫자를 함께 제출하고, 상황과 작성자 닉네임을 공개한 뒤 숫자의 오름차순을 추리한다. 숫자 공개 후 서로의 선택을 이야기하는 시간이 이 게임의 재미다.

**제안:** 기존 슬리퍼 웹게임처럼 호스트는 로그인하여 진행만 하고 참가 정원에 포함하지 않는다. 참가자는 링크·QR을 통해 가입 없이 입장한다. 참가 인원은 기존 자동 게임과 같은 3~30명을 지원 대상으로 검토하되, 30명의 순위 정렬 UI와 실제 플레이 시간은 별도 검증한다. 모바일 웹을 우선하고 PC도 지원한다.

## 2. 공통 준비

1. 호스트가 `/games`에서 **마음의 온도**를 선택하고 게임방을 만든다.
2. 호스트가 기본 모드 또는 추리 모드, 라운드 수와 제한시간을 설정한다.
3. 참가자가 QR 또는 링크로 입장해 닉네임을 정하고 준비한다.
4. 최소 인원과 기존 대기실의 준비 조건을 만족하면 호스트가 시작한다.
5. 서버가 시작 참가자 명단과 순서를 고정한다. 게임 중 들어온 대기자는 기존 게임방 정책에 따라 기다린다.
6. 매 차례/라운드마다 공통 주제와 **0의 의미 / 100의 의미**를 모든 참가자에게 보여준다.
7. 결과를 보고 각자 생각한 이유를 말로 이야기한다. 기존 게임방은 진행·선택을 돕는 웹 도구이며, 현장 대화를 대체하는 음성 기능을 전제로 하지 않는다.

점수는 게임 전체에 누적하고, 마지막에 점수가 가장 높은 참가자를 우승자로 발표한다. 최종 점수가 같으면 공동 순위로 표시한다.

### 설정 기본안 — 제안

| 설정                | 제안 값                       | 설명                                             |
| ------------------- | ----------------------------- | ------------------------------------------------ |
| 모드                | 기본 / 추리                   | 방 설정에서 하나 선택                            |
| 라운드              | 1~10, 기본 2                  | 아래 모드별 라운드 정의 적용                     |
| 기본 모드 힌트 설명 | 30초 기본                     | 현장 발언용 시간. 시간 만료 시 처리 방식은 미결  |
| 숫자·상황·순서 제출 | 30/60/90초 중 선택, 기본 60초 | 실제 사용성을 보고 변경 가능                     |
| 주제                | 미리 준비한 목록              | 중복 방지·목록 범위와 직접 입력 여부는 추후 확정 |

숫자는 0~100의 정수로 제안한다. 확정된 값은 아니며 향후 소수점 허용 여부가 바뀌면 입력·채점·동점 처리를 함께 바꿔야 한다.

## 3. 기본 모드

### 핵심 규칙 — 확정

한 명에게만 공개된 0~100의 무작위 비밀 숫자를, 그 사람이 말로 설명한 상황이나 대상을 듣고 나머지 참가자들이 추리한다. 비밀 숫자에 **가장 가까운 숫자**를 제출한 사람에게 1점을 주며, 정답과의 차이가 같아 공동으로 가장 가까우면 모두 1점이다.

### 진행 순서

1. **힌트 제공자 선정:** 고정된 참가 순서대로 한 명을 선정한다. 호스트는 제공자가 아니다.
2. **공통 주제 공개:** 주제와 0/100 양쪽 기준을 모두에게 보여준다.
3. **비밀 숫자 배정:** 서버가 0부터 100까지 숫자 하나를 무작위로 배정하고 힌트 제공자 본인에게만 보여준다. 호스트와 다른 참가자에게는 공개하지 않는다.
4. **말로 설명:** 힌트 제공자가 받은 숫자에 어울리는 상황 또는 대상을 설명한다. 숫자 자체를 말하거나 보여주지 않는다. 예: 주제가 ‘얼마나 당황스러운가’, 숫자가 77이면 ‘중요한 발표에서 자료가 열리지 않는 상황’이라고 말한다.
5. **예상 숫자 제출:** 힌트 제공자를 제외한 참가자들이 0~100에서 각자의 예측값을 선택해 비공개로 제출한다. **제안:** 전원 제출 또는 서버 기준 제한시간 만료 시 마감한다.
6. **결과 공개:** 비밀 숫자와 참가자별 예상 숫자, 정답과의 차이 및 차례 점수를 공개한다. 제출 전에는 다른 사람의 예측을 보여주지 않는다.
7. **이야기:** 힌트 제공자가 왜 그 상황을 골랐는지 말하고, 참가자들이 예상이 달랐던 이유를 대화한다.
8. **다음 차례:** 호스트가 결과 확인 뒤 다음 참가자의 차례를 진행한다.

**제안:** 참가자 전원이 한 번씩 힌트를 제공하면 기본 모드의 1라운드다. 정해진 라운드를 마치면 최종 순위를 보여준다. 설명 완료 버튼과 자동 시간 만료의 관계는 구현 전 확정한다.

### 채점 예시

정답이 77이고 A가 76, B가 78, C가 85를 제출했다면 A와 B는 각각 차이 1로 공동 1등이므로 **각 1점**, C는 0점이다. 힌트 제공자는 그 차례에 추리하지 않으므로 점수를 받지 않는다. 아무도 유효한 숫자를 제출하지 않았다면 승자와 점수 없이 결과를 보여준다. 미제출은 0이라는 예측값이 아니다.

## 4. 추리 모드

### 핵심 규칙 — 확정

모든 참가자가 같은 주제에 관한 **자신의 상황과 해당 숫자**를 같이 제출한다. 숫자는 서버가 배정하지 않고 참가자가 자신의 기준으로 선택한다. 제출 단계가 끝나면 숫자를 숨긴 채 **작성자의 닉네임과 상황만** 공개한다. 각자는 공개된 상황을 실제 숫자가 낮은 것부터 높은 순서로 나열한다. 최종적으로 실제 순서에 가장 가깝게 맞힌 참가자는 1점을 받고, 공동으로 가장 가까운 참가자들도 각각 1점을 받는다.

### 진행 순서

1. **공통 주제 공개:** 예를 들어 ‘얼마나 당황스러운 상황인가요?’, `0 = 전혀 당황하지 않음`, `100 = 매우 당황함`.
2. **상황과 숫자 입력:** 참가자 각자가 상황 문장 하나와 숫자 하나를 함께 비공개 제출한다. 자신이 실제로 느끼는 정도를 바탕으로 정한다.
3. **상황 목록 확정:** 전원 제출 또는 서버 기준 제한시간이 지나면 유효하게 제출된 상황을 확정한다. 공개되는 것은 작성자 닉네임과 상황이며, 숫자는 작성자 본인 외에는 아직 공개하지 않는다.
4. **상황 순서 맞히기:** 각 참가자는 공개된 상황을 낮은 숫자부터 높은 숫자 순서로 나열해 제출한다. 작성자의 성향과 설명을 바탕으로 추리한다. 다른 사람이 제출한 순서는 결과 발표 전 숨긴다.
5. **결과 공개:** 각 상황의 숫자, 실제 순서, 참가자의 제출 순서, 순서 비교 결과와 차례 점수를 보여준다.
6. **대화:** 각 작성자가 자신의 상황을 왜 그 숫자로 정했는지 말한다.
7. **다음 라운드:** 호스트가 다음 주제로 진행한다. 정한 횟수가 끝나면 누적 순위를 공개한다.

**제안:** 추리 모드에서는 모든 참가자가 동시에 상황을 제출하고 순서를 맞히는 한 번의 흐름을 1라운드로 한다. 자신의 상황도 목록에 포함하여 모든 사람이 같은 목록을 정렬한다. 자신의 숫자를 이미 아는 점은 이 규칙에서 모든 참가자에게 동일하게 적용된다. 공개 목록의 최초 배치 순서는 정답이나 제출 시간을 유추할 수 없게 섞고, 모든 참가자에게 같은 목록을 보여준다.

### 상황 예시

| 작성자 | 공개되는 상황                       | 최종 공개되는 숫자 |
| ------ | ----------------------------------- | -----------------: |
| 민수   | 카페에서 음료를 조금 쏟았다         |                 20 |
| 지연   | 친구의 이름을 잠깐 잊어버렸다       |                 40 |
| 서연   | 약속 장소를 잘못 찾아갔다           |                 60 |
| 준호   | 중요한 발표 중 자료가 열리지 않는다 |                 80 |

정답은 **민수 → 지연 → 서연 → 준호**다. 추리 중에는 상황과 이름만 보이고 숫자는 결과에서 공개된다.

### 순서의 가까움 계산 — 제안

‘가장 가깝게’의 계산 방식은 아직 사용자가 확정하지 않았다. 개발 기본안으로 **서로 다른 숫자를 가진 상황 두 개씩의 앞뒤 순서를 비교해, 실제 앞뒤와 일치한 쌍의 개수**를 센다. 가장 많이 맞힌 참가자 전원에게 각 1점을 준다.

위 예시는 네 상황이므로 비교 가능한 쌍이 6개다.

| 제출 순서                 | 실제 앞뒤와 일치하는 쌍 | 점수                     |
| ------------------------- | ----------------------: | ------------------------ |
| 민수 → 지연 → 서연 → 준호 |                     6/6 | 해당 라운드 최다라면 1점 |
| 지연 → 민수 → 서연 → 준호 |                     5/6 | 해당 라운드 최다라면 1점 |
| 지연 → 서연 → 민수 → 준호 |                     4/6 | 해당 라운드 최다라면 1점 |

두 상황에 같은 숫자가 제출된 경우 둘 사이의 순서는 어느 쪽이 먼저여도 같은 숫자의 실제 순서와 모순되지 않으므로 **그 쌍을 채점에서 제외**한다. 다른 숫자의 상황과의 앞뒤는 각각 비교한다. 예를 들어 A=20, B=20, C=80이면 A/B는 비교하지 않고 A/C, B/C만 비교한다. 숫자의 차이가 1이든 50이든 앞뒤 관계 한 쌍의 배점은 동일하다.

**예외 제안:** 유효 상황이 2개 미만이거나 모든 상황의 숫자가 같아 비교 가능한 쌍이 없다면 채점하지 않고 0점으로 해당 라운드를 종료하거나 다시 진행한다. 자동으로 모두에게 1점을 주지 않는다. 최종 동작은 구현 전 결정한다.

## 5. 공통 화면과 단계

### 호스트

- 방 설정: 모드, 라운드 수, 인원과 제한시간.
- 대기실: 참가자·준비 상태·시작 버튼.
- 게임 진행: 현재 주제와 단계, 남은 시간, 제출 인원 및 다음 진행 버튼. 공개 전 비밀 숫자·타인의 상황 입력 초안·예상·순서는 받지 않는다.
- 결과: 해당 차례/라운드의 정답, 점수와 다음 단계.
- 게임 종료: 누적 순위와 공동 우승 표시.

### 참가자

- 공통: 내 닉네임, 현재 주제와 양쪽 기준, 단계·남은 시간·점수.
- 기본 힌트 제공자: 나에게만 보이는 비밀 숫자와 말로 설명하라는 안내. 다른 참가자의 제출값은 결과 전 숨김.
- 기본 추리자: 0~100 선택 슬라이더와 숫자 직접 입력, 제출 버튼. 타인의 예측과 정답은 결과 전 숨김.
- 추리 모드 상황 작성: 상황 입력과 숫자 선택, 제출 버튼. 입력 내용은 개인정보를 불필요하게 적지 않도록 안내한다.
- 추리 모드 순서 작성: 작성자 닉네임과 상황 카드 목록, 오름차순 안내, 순서 변경 및 제출 버튼. 모바일 드래그뿐 아니라 위/아래 버튼과 키보드 조작을 지원한다. 자신의 상황도 목록에서 식별할 수 있다.
- 결과: 공개 가능한 상황·숫자·순서와 본인 점수. 결과 표시 이후의 공개 범위와 방 종료 후 데이터 보관은 정책 확인이 필요하다.

### 단계 전환 기본안 — 제안

| 기본 모드                                                                                | 추리 모드                                                                                               |
| ---------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 대기 → 주제/힌트 제공자 → 말로 설명 → 비공개 숫자 제출 → 결과/대화 → 다음 차례 또는 종료 | 대기 → 주제 → 상황·숫자 비공개 제출 → 닉네임·상황 공개 및 순서 제출 → 결과/대화 → 다음 라운드 또는 종료 |

입력은 해당 단계에서만 허용하고, 제출 후에는 잠근다. 재접속 시 서버에 확정된 본인 제출과 현재 단계를 복원한다. 미제출 초안의 새로고침 후 보존 여부는 별도 결정한다.

## 6. 미제출과 중단 기본안 — 제안

- **기본 모드:** 제한시간 내 예상값을 제출하지 않으면 이번 차례 무득점. 힌트 제공자의 연결이 끊겨 더 이상 설명할 수 없다면 호스트가 해당 차례를 점수 없이 건너뛰는 방식을 검토한다.
- **추리 모드 상황 미제출:** 유효하게 제출된 상황만 확정 목록에 넣고, 미제출자는 그 라운드에서 점수를 얻지 못한다. 유효 상황이 2개 미만이면 무득점으로 종료하거나 다시 진행한다.
- **추리 모드 순서 미제출:** 임의 순서를 자동 확정하지 않고 그 참가자는 이번 라운드 무득점. 모든 유효 상황을 중복·누락 없이 한 번씩 포함해야 제출할 수 있다.
- **연결 단절:** 시작 명단을 임의로 바꾸지 않고 기존 게임방 재접속 정책을 따른다. 이미 확정한 제출은 연결이 끊겨도 남는다.
- **호스트 중단:** 게임 중단 시 아직 공개되지 않은 숫자·순서를 추가로 공개하지 않는다. 이미 공개된 결과와 점수의 보존 여부는 기존 게임방 정책과 함께 결정한다.
- **중복 요청:** 같은 차례의 재시도·중복 제출·동시 집계로 점수가 중복되지 않아야 한다. 시간 경과 중 연결이 모두 끊어졌을 때는 다음 서버 요청에서 서버 시각을 기준으로 정리하는 기존 방식과의 적합성을 검토한다.

## 7. 주제 예시 — 초안

1. **얼마나 당황스러운 상황인가요?** 0 전혀 당황하지 않음 / 100 매우 당황함
2. **혼자 하기 편한 활동인가요?** 0 혼자 하기 어려움 / 100 혼자 해도 아주 편함
3. **얼마나 즉흥적인 여행인가요?** 0 모든 일정이 정해짐 / 100 아무 계획 없이 떠남
4. **주말에 얼마나 에너지가 필요한가요?** 0 쉬기만 하면 됨 / 100 매우 활발하게 움직임
5. **얼마나 도전적인 음식인가요?** 0 아주 익숙함 / 100 선뜻 먹기 어려움
6. **얼마나 어려운 예능 미션인가요?** 0 아주 쉬움 / 100 매우 어려움
7. **모임에서 얼마나 먼저 나서는 행동인가요?** 0 조용히 참여 / 100 가장 먼저 나섬
8. **얼마나 오래 기다릴 수 있나요?** 0 거의 기다릴 수 없음 / 100 오래 기다려도 괜찮음

각 양끝은 가치판단이 아니라 개인의 기준임을 안내한다. 사람의 외모·민감한 경험을 강제로 털어놓게 하는 문항은 피하고, 참가자가 불편한 상황을 작성하지 않도록 호스트 안내와 기존 텍스트 정책을 활용한다.

## 8. 기존 웹게임과의 통합 방향

구체적인 DB 변경·마이그레이션은 아직 확정하지 않는다. 현재 `src/domain/game-catalog.ts`의 카탈로그와 게임방 생성·설정·안내, `src/domain/game-room.ts`의 게임 계약, `src/server/game-room-service.ts`의 권한/상태 전이, `src/components/game-room-lobby.tsx`의 게임 영역에 새 게임을 연결하는 방향을 검토한다.

- 공통 방·링크/QR·준비·대기열·호스트 권한·SSE 갱신과 재접속 정책을 재사용한다. 게임별 상태·정답·점수와 역할별 응답은 별도 설계한다.
- 서버가 인증된 참가자의 현재 단계·차례·정수 범위·상황 ID 전체성·마감·이미 제출 여부를 검사한다. 방 상태 변경과 집계를 기존 방 잠금/트랜잭션과 서버 시각에 맞춰 처리한다.
- 기본 모드 비밀 숫자는 결과 전 힌트 제공자에게만 제공한다. 추리 모드에서는 상황 공개 단계까지 다른 사람의 숫자를 숨기고, 결과 전 다른 사람의 순서도 숨긴다. 호스트·대기자·퇴장자 및 미입장자에게 비밀을 제공하지 않는다.
- 이벤트 버스/SSE 갱신 메시지 자체에 정답을 넣지 않는다. 접속 시 현재 단계에 맞는 권한별 데이터만 재조회한다.
- 사용자의 상황 입력은 기존 텍스트 정책을 통과해야 한다. 입력·정답·결과의 보존 기간과 삭제 정책을 결정하기 전 장기 보관을 가정하지 않는다.
- 추리 모드 순위 비교는 30개 상황일 때 최대 435개 쌍이므로 계산 자체보다 작은 화면에서 모든 카드를 편하게 정렬하는 UX 검증이 중요하다.

## 9. 구현 및 검증 체크리스트

1. **규칙 확정:** 쌍별 채점, 같은 숫자·전원 같은 숫자, 자신 포함, 미제출 및 주제/시간 정책을 확인한다.
2. **기본 모드:** 순서대로 힌트 제공 → 숨겨진 숫자 → 비공개 추리 → 최단 거리 공동 1점 → 다음 차례/최종 순위를 검증한다.
3. **추리 모드:** 각자 상황·숫자 입력 → 닉네임/상황만 공개 → 모든 카드를 정렬 → 숫자 및 순위 공개 → 최다 일치 공동 1점을 검증한다.
4. **동점·예외:** 기본 숫자 동거리, 추리 쌍별 동점과 동일 숫자, 전원 동일 숫자, 2개 미만 상황, 단계별 미제출, 중복·누락·타인 차례 요청, 마감 경계를 확인한다.
5. **권한·동시성:** 호스트와 다른 참가자의 비공개 숫자 접근 차단, 제출 전 순서 노출 차단, 동시 제출·집계·중복 요청, 중단·재접속을 확인한다.
6. **화면:** 320px 이상 모바일·PC, 30명 카드 정렬, 드래그와 위/아래 버튼, 키보드·화면 읽기 도구, 로딩/연결 오류 상태를 검증한다.
7. **통합:** 기존 게임 생성·QR·입장·준비·게임 설정·SSE·기존 게임 회귀를 검증한다. 실제 모바일 기기에서 긴 텍스트와 현장 진행도 확인한다.

## 10. 구현 전 최종 결정 사항

1. 추리 모드에서 **쌍별 순서 일치 개수**를 가까움의 기준으로 사용할지.
2. 추리 모드에서 자신의 상황을 정렬 목록에 포함할지. 현재 문서의 개발 기본안은 포함이다.
3. 상황이 두 개 미만이거나 숫자가 전부 같을 때 무득점 종료 또는 재진행 중 무엇을 선택할지.
4. 설명 30초를 자동 종료할지, 호스트가 완료를 누를 때까지 표시만 할지. 각 제출 제한시간과 미제출 기본안의 적용 여부.
5. 주제의 직접 작성 허용 여부 및 결과·상황·숫자의 게임 종료 후 보관/삭제 범위.

이 기획안은 구현이나 운영 반영을 의미하지 않는다.
