### 공통 규칙

- 기존 카드 선택·게임 소개·튜토리얼·방 생성·링크/QR·선착순 대기·호스트 참가 구조를 확장했다. 기존 여섯 게임을 제거하지 않았다. 새 게임 최대 12명, 기존 게임 정원은 유지한다.
- 호스트 설정 변경 시 준비 상태를 초기화하지 않는다. 방 안에서 모드·인원·시간 등을 바꿀 수 있다. 최소 인원·자료 준비 조건은 서버에서 다시 검사한다.
- 호스트도 플레이하거나 진행만 맡을 수 있다. 직접 낸 사진/단서 문제에서는 호스트도 채점 제외된다. 기본 문제를 쓰면 호스트도 정상 경쟁한다.
- 제한시간과 단계 전환·점수는 서버가 결정한다. 전원 제출 또는 제한시간 종료 후 다음 단계로 넘어간다. 호스트 일시정지·재개·다음 단계·중단도 제공한다.
- 그림 문장 30초, 해석 30초, 그리기 30/45/60/90초(기본45), 실시간 맞히기45초. 그림 유사 답은 담당자가 10초 판정 구간에서 인정하며 서버가 받은 순서로 최초 정답을 정한다. 화가와 마지막 문장 작성자는 해당 정답 맞히기에서 제외된다.
- 문장 미제출은 추천 문장으로 채우고, 그림/해석이 없는 체인은 맞히기를 건너뛴다. 마지막 결과는 원문부터 전체 전달 과정을 보여준다.
- 단서각은 기본5문제·60초. 문제수 1/3/5/8/10/15/20, 제한30/60/90초. 기본 소리 문제는10개까지만 선택할 수 있고 모드 전환 시 자동으로 범위를 맞춘다. 직접 출제는20문제까지 가능하다. 우리 사진은 참여 인원만큼 출제한다. 확정 답은 바꾸지 못하며 미제출은0점이다.
- 사진의 정답은 확인된 랜드마크 대표 지점이다. 사진 촬영자의 GPS 위치를 맞히는 문제로 표현하지 않는다. 게임 입력은 지도에서 선택하며 현재 위치 권한을 요구하지 않는다.

## 저장·보안·리소스

PostgreSQL이 방·개인 제출·점수·완료 결과의 원본이다. `game_assets`, `game_runs`에는 RLS와 직접 접근 권한 제한을 적용했다. 게임별 참가 연결과 호스트 권한을 서버에서 확인한 뒤 자료를 제공한다. 원시 IP나 쿠키 토큰을 회원의 신원으로 저장하지 않는다.

그림 스트로크만 별도 WebSocket 게이트웨이와 Redis Pub/Sub으로 전달한다. 첫 그림은 지정된 사람만, 라이브 그림은 허용된 참가자만 읽는다. HMAC 단기 티켓·정확한 Origin/경로·쓰기 담당자 확인·단계 변경 시 권한 회수·프레임/빈도/대기열/연결 한도·재연결 복원을 구현했다. 틀린 순서·중복 프레임은 재동기화하거나 중복 반영하지 않는다.

개인 사진은 브라우저 사전 압축과 서버 WebP·메타데이터 제거를 거친다. 소리30초·5MB, 영상15초·20MB를 별도 영상 워커에서 처리한다. 처리 임대 토큰과 재시도 한도로 중복 워커의 결과 덮어쓰기를 막는다. FFmpeg의 네트워크 프로토콜·입력 형식·해상도·실행 시간·동시 실행 수를 제한한다.

완료 결과와 개인 미디어는 실제 종료 시각부터24시간 보관한다. 다음 판을 시작해도 이전 결과를 당시 참가 연결로 다시 볼 수 있다. 파일 삭제는 durable object-cleanup 작업을 기록한 후 수행하며 저장 실패·경쟁 상태에서 다른 자료를 삭제하지 않게 참조를 확인한다. DB·업로드·다른 게임의 기록은 이번 정리와 별개다.

기본 자료는 공개 이용 조건을 확인한 장소 사진20개와 직접 만든 합성 소리10개, 총6.3MB 정도다. 출처·저작자·변경·라이선스를 `public/games/clue/ATTRIBUTIONS.json`과 `/games/credits`에 표시한다. 정답 은행은 서버에 두고 추리 중에는 정답 좌표·사진 주인을 클라이언트에 보내지 않는다.
