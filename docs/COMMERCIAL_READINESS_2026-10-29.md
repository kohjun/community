## 판단

서비스의 기본 기능과 운영 배포 기반은 마련되어 있다. 정식 유료 운영에는 운영 관리자, 개인정보·사업자 고지와 문의 창구, 복구 체계, 실제 행사·판매 자료, 외부 거래 확인이 더 필요하다.

권장 경로는 **운영 기반 보완 → 한 지역에서 무료 베타 → 외부 결제·수동 승인으로 첫 유료 운영 → 확인된 거래만 자동화**다. 대규모 신규 기능 개발과 별도 Redis·서버 증설부터 진행할 근거는 이번 점검에서 확인하지 못했다. 현재 서버 용량 관찰은 동시 접속 한도 측정이 아니다.

이 문서의 기간은 1인 개발자가 집중적으로 작업하고 사업자 정보·주최자·외부 계정이 준비된다는 가정의 **출시 준비 추정**이다. 외부 플랫폼 심사와 실제 고객 모집·반복 이용 검증은 별도다.

- 미디어 압축·별도 영상 워커·접근 권한·Range 재생, 요청 제한·신고/차단·텍스트 정책과 조치 이력.

운영 원본의 실제 회원 행사 전반 검증 기록과, 분리 DB에서 수행한 완료→회고→제작진 수락→포트폴리오 검증은 구분한다. 두 계층의 검사가 있다고 모든 과정을 새 도메인의 실제 iPhone에서 확인한 것은 아니다.

## 우선순위와 완료 기준

### P0-1. 사이트 운영 관리자와 응대 책임자

실제 `staff_roles`가 비어 있다. `src/server/safety-service.ts:65`는 이 역할을 검사하므로 현재 회원은 사이트 운영자 화면의 신고·문의 처리 권한을 받을 수 없다.

- 소유자가 사용할 실제 Google/Kakao 계정을 확인해 관리자 1명을 지정한다. 대상 계정은 소유자가 정해야 한다.
- 별도 일반 회원의 신고/문의 → 관리자 조회·답변/숨김·복원 → 회원 확인까지 검증한다.
- 신고 대응 시간, 긴급 연락, 오판 정정과 대체 담당/복구 절차를 정한다.
- 초기 주최자 3~5명의 연락처·행사 소개를 수동으로 확인한다. 모든 회원 대상 유료 본인인증 시스템 도입은 별도 판단한다.

예상 작업량: 약 0.5~1일 + 운영 계정 확인.

### P0-2. 개인정보·사업자·거래 책임 고지와 문의 창구

현재 `/policies/privacy`는 간단한 기능 안내다. 실제 운영자/책임자 연락처, 데이터 종류별 보유·파기 근거, 수탁/제공 구조를 구체화해야 한다. 특히 과거 신청 연락처·답변과 거래 기록은 탈퇴 시 함께 삭제되지 않는다고 안내하므로 그 범위·기한·파기 절차를 실제 동작과 맞춰야 한다. 개인정보 처리방침에는 처리 목적·보유 기간·파기·위탁·보호책임자 연락처 등의 기재 사항이 있다. [개인정보 보호법 제30조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0030&lsiSeq=283839&urlMode=lsScJoRltInfoR).

`src/app/support/page.tsx:8`은 비로그인 이용자에게 로그인 화면을 제공한다. `src/server/safety-service.ts:562`와 619에서는 탈퇴 계정의 문의 조회/작성을 거부한다. 공개 운영자 이메일 등 독립적인 대체 창구가 현재 화면/정책에서 확인되지 않았다. 로그인 장애·탈퇴 후 개인정보 요청 경로를 보완해야 한다.

유료 P2P 모임을 운영하려면 Sliper의 판매자/중개자 역할, 주최자 정보 확인·고지, 분쟁 처리 책임을 거래 흐름에 맞춰 확정해야 한다. 돈을 외부에서 받는 사실만으로 Sliper의 책임 범위를 확정할 수 없다. 사업자등록·신고/계약의 준비 여부는 코드나 이번 계정 접근으로 확인하지 못했다. [전자상거래법 현행 관련 조문](https://www.law.go.kr/LSW/lsInfoR.do?ancYnChk=0&chrClsCd=010202&efYd=20260721&lsiSeq=282793).

‘5일 전까지 100%·이후 일별 20% 차감’은 구현된 서비스 정책이다. 행사 종류·자료 판매의 청약철회, 주최자 취소·미제공·일정 변경과 외부 플랫폼 약관을 대조해 유료 운영 전에 확정해야 한다. 계산기가 있다는 사실은 적법성 검토 완료를 의미하지 않는다.

예상 구현량: 약 2~4일. 실제 사업자·책임자 정보와 적용 조건의 확정은 선행 조건이다.

### P0-3. 실제 모집·자료와 샘플 정리

다음에 신청할 행사와 공개 자료가 현재 운영 DB에 없다. 사이트의 탐색·신청·판매 기능을 이용자가 경험할 수 있도록 실제 공급을 준비한다.

- 한 지역·몇 가지 취향에 맞는 주최자 3~5명과 일정을 확정한다.
- 실제 예정 모임을 등록하고 준비물·진행자·만나는 곳·참가 대상·취소 방법을 확인한다.
- 공개 룰북/템플릿을 발행하고 재배포·상업 이용 조건, 원저작 자료 권리를 확인한다.
- 샘플은 샘플 표시를 유지하고 실제 판매·모집 실적으로 집계하지 않는다. 정식 홈에서 샘플을 노출할 범위와 example.com 링크를 점검한다.

권장 베타 목표는 실제 행사 3회, 주최자 3~5명, 공개 자료 3개와 참가 인증 후기 축적이다. 이는 운영 목표 제안이며 외부 승인 기준이나 현재 실적이 아니다. 콘텐츠 준비와 주최자 모집에는 별도 시간이 필요하다.

### P1-1. 복구·보관·서버 유지보수

수동 암호화 백업·개발 PC 사본과 별도 로컬 DB 복원 검증은 있다. 정기 백업과 별도 보관처는 사용자가 보류했고 이번에도 재개하지 않았다. 새 서울 프로젝트의 관리형 Auth/Storage/Realtime을 포함한 복구 절차, 운영 키 보관과 허용 손실/복구 시간을 확정해야 한다. Supabase 요금제의 자동 백업/PITR 실제 적용 여부는 이번에 확인하지 못했다.

확인한 Sliper systemd 타이머는 감시와 인증서 갱신이다. 일반 미첨부 미디어 30일 정리의 정기 실행·실패 대응을 별도로 점검한다. 영상 워커 내부의 원본 정리와 일반 미디어 정리를 혼동하지 않는다.

서버는 Ubuntu 20.04다. 이 버전의 표준 보안 유지보수는 2025년 5월 종료되었으며 확장 지원 범위를 확인해야 한다. 이번에는 Ubuntu Pro/ESM 활성 여부를 확인하지 못했다. 지원되는 LTS로의 이전 또는 실제 보안 지원 적용을 검토한다. 같은 인스턴스의 기존 사이트도 있어 변경에는 호환성 확인과 유지보수 계획이 필요하다. [Ubuntu 공식 지원 주기](https://ubuntu.com/about/release-cycle).

SSH는 root 로그인·비밀번호 인증을 허용한다. Ncloud 접근 소스 제한과 키 접속·관리 권한 정책을 함께 검토한다. 이번에는 접속 정책·OS·다른 사이트를 변경하지 않았다.

예상 검증·준비량: 약 2~4일 + 사용자 보류 해제/복원 대상/유지보수 일정.

### P1-2. 실제 행사 전체 흐름·실기기·제한된 부하 검증

- 실제 주최자와 참가자의 개설→신청→승인→공지→출석→완료→후기/회고→제작진 수락→포트폴리오/검색을 하나의 운영 흐름으로 확인한다.
- Sliper 정식 도메인에서 Android·iPhone의 로그인·설치/알림·지도·사진·영상·신청/취소를 확인한다. iPhone과 새 도메인 푸시 수신은 아직 미확인이다.
- 카메라 QR 검증은 사용자 보류 상태를 유지한다. 초기 운영의 담당자 수동 참가 확인 경로도 명확하게 안내한다.
- 동시 신청의 정원/중복, 알림 대기열, 영상 변환, 이미지 전송과 DB 연결·p95/오류율을 격리된 제한 부하로 측정한다. 실서비스 공유 인스턴스에 무단 부하 시험을 하지 않는다.

현재 2vCPU/8GB 서버의 관찰 부하는 낮고 디스크 여유는 약 23GiB다. 관찰 시점 값으로 수용 인원을 보장할 수 없다. 이미지 HEAD는 `private, no-store`와 ETag를 반환했다. 공개 이미지 캐시 헤더 정합성 개선은 남아 있으며, 권한 있는 비공개 미디어가 공개 캐시에 들어가지 않도록 분리해 검증한다.

예상 작업량: 약 2~4일 + 실기기와 실제 행사 일정.

### P1-3. 첫 유료 운영과 거래 자동화

실제 웹 프로세스에서 다음 연결이 모두 미설정이다.

- 행사 결제 브리지: provider/API URL/API key/웹훅 secret/허용 checkout origin.
- 외부 플랫폼 참가 자동 승인.
- 아카이브 구매 자동 승인.

브리지 주문 생성·서명·중복 처리·상태/금액 연결 코드는 있다. 첫 단계는 실제 외부 결제 링크와 담당자 수동 승인으로 소액 결제·취소·실제 환불·권한 회수를 확인하는 것이다. 이후 선택한 플랫폼 어댑터, 구매자/Sliper 회원 연결, 서명·지연/중복/역순 알림, 정원 초과와 환불·정산 대사를 연결한다.

외부 플랫폼에서 결제·정산된다는 사실과 Sliper가 수수료를 자동 수취한다는 것은 다른 운영 범위다. 초기 수익 모델과 계약·정산 방식을 먼저 확정해야 한다.

예상 구현량: 수동 연결의 화면/운영 점검 약 1~3일, API 자동화 약 1~3주. 제공자 기능·계약·심사는 별도다.

### P2. 검색 유입·광고·베타 지표

실제 홈에는 `noindex, nofollow`가 있고 `/robots.txt`, `/sitemap.xml`은 404다. 공개 글/자료의 검색 노출 범위·canonical·사이트맵을 준비하되 회원 전용·비공개·유료 본문은 현재 권한 정책을 유지한다. noindex는 검색 노출 설정이며 AdSense 승인 상태 자체를 뜻하지 않는다.

실제 AdSense는 비활성이고 광고 단위 설정도 없다. 게시자 ID를 알고 있어도 운영 설정·사이트 승인·실제 게재는 별도 확인이 필요하다. Google은 고유한 콘텐츠와 정책 준수를 요구하므로 실제 모임/자료·도움말·운영 정보를 준비한 뒤 심사를 진행한다. Google 계정의 승인 여부는 이번에 접근하지 않았다. [Google AdSense 자격 요건](https://support.google.com/adsense/answer/9724?hl=ko).

첫 참가자의 신청 완료·실제 출석·후기·재참가, 주최자의 재개최와 자료 재사용을 베타에서 측정한다. 마케팅을 넓히기 전에 모집할 모임과 공개할 자료, 응대 담당자가 있는지 확인한다.
