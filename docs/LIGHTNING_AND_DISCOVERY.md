# 번개와 위치·취향 이벤트 탐색

## 사용 순서

메인 상단 검색창 왼쪽의 **취향 이벤트 찾기**를 누르면 모임 종류(전체 이벤트·번개·일반), 카테고리, 기준 위치·반경, 한국시간의 시작 날짜 범위, 최소/최대 참가비, 신청 가능 여부를 함께 설정한다. 날짜 바로 선택은 오늘·이번 주, 참가비 바로 선택은 무료를 제공한다. 적용한 조건은 목록 위 칩으로 표시하고 개별 해제·전체 초기화할 수 있다. 카테고리 변경은 위치와 취향 조건을 유지하고 이야기·투표 탭으로 이동하면 이벤트 조건을 해제한다.

정렬에는 최신순·인기순·거리 가까운순을 제공한다. 가까운순을 위치 없이 선택하면 설정창에서 위치를 먼저 확인한다. 반경은 1·3·5·10·30·100km 중 선택하고 API는 0.1~100km를 허용한다. 거리는 지구 평균 반지름 6371.0088km를 사용하는 Haversine 직선 거리이며 도로/이동 거리가 아니다.

현재 위치는 버튼을 눌렀을 때만 브라우저의 위치 권한을 요청한다. 거절·시간 초과·위치 미지원이면 수동 좌표 입력을 제공한다. 검색 기준 위치는 React 상태에 보관하고 프로필이나 DB에 저장하지 않는다. 위치 삭제·수동 입력·설정 초기화·닫기 이후 늦은 위치 응답은 새 값을 덮어쓰지 못한다.

## 번개 빠르게 열기

`/lightning` 또는 메인의 번개 카드에서 소규모 모임을 열 수 있다. 기본 범위는 무료, 주최자를 제외한 참가 자리 2~12개, 개설 후 7일 이내 시작이다. 진행 시간은 15분~12시간이다. 제목·활동 카테고리·세부 활동 태그(선택)·행사장 이름/좌표·한국시간 시작·진행 시간·정원·간단한 소개를 한 번에 입력한다. 활동 카테고리에 맞는 커뮤니티 주제를 기본으로 설정하고, 접힌 추가 설정에서 기존 9개 주제 중 하나로 바꿀 수 있다.

게시글과 행사 설정, 장소 좌표를 하나의 트랜잭션으로 생성한다. 신청 방식은 슬리퍼 직접 신청과 외부 플랫폼 신청·결제 중에서 선택한다. 슬리퍼 직접 신청은 무료이며 기존 정원 검사와 함께 참가를 즉시 확정하고 공지방에 초대한다. 공지 작성은 주최자 또는 지정 담당자만 가능하며 참가자는 읽기만 한다. 행사 관리에서 참가자·공지·정원을 관리한다. 인증은 기존 요청에 따라 후속 연동이며 전용 로컬 환경에서만 개발 계정을 제공한다.

번개 인원·일정·좌표 규칙은 API와 DB에서 검사한다. 직접 신청은 무료이고 외부 신청은 0~10,000,000원의 실제 참가비를 설정할 수 있다. 일반 글로 바꾸는 것은 차단하고, 외부/직접 방식 전환은 활성 참가 내역이 없을 때만 허용한다. 유료 외부 번개를 직접 신청으로 바꾸려면 참가비를 먼저 0원으로 변경해야 한다. 대규모 이벤트는 일반 모집이나 템플릿 개설을 사용한다.

외부 플랫폼을 선택하면 http/https 신청 링크와 실제 참가비를 입력한다. 참가자는 외부 플랫폼에서 신청·결제한 뒤 /events/{postId}에서 신청 번호와 동의를 제출한다. 제출만으로는 pending_approval 상태이며 담당자가 결제 내역을 대조·승인하거나, 설정된 외부 결제 브리지가 검증된 동일 금액 영수증을 처리한 뒤 참가가 확정된다. 참가 확정 후 기존 전용 공지방에 초대되며 슬리퍼가 별도 결제 주문을 만들지 않는다. 실제 외부 결제 제공자 연결은 별도 설정이 필요하고 링크 저장만으로 자동 결제 연동이 활성화되지는 않는다. 번개 카드에 외부 신청 링크와 참가 확인·공지방 화면 링크를 함께 제공한다.

기존 번개는 글 수정에서 외부 신청 링크를 연결할 수 있고, 실제 참가비·정원·승인 방식은 내 행사 관리에서 바꾼다. 참가비 표시 문자열은 행사 설정 금액과 함께 갱신하여 금액 불일치를 방지한다.

세부 활동은 추천 태그 버튼 또는 직접 입력으로 최대 5개, 각 1~24자까지 등록한다. 공백 제거 후 중복을 거절한다. 활동 분류를 바꾸어도 이미 선택한 태그를 지우지 않는다. 여러 활동이 섞인 번개는 대표 카테고리를 고르고 세부 태그로 설명한다.

번개 탐색에서 활동 분류·태그·텍스트 검색을 조합한다. 텍스트 검색은 제목·소개·저장된 태그에 적용한다. 추천 태그는 정확히 일치하는 태그 필터이며, 직접 입력한 태그는 검색창에서 찾을 수 있다. 조건을 바꾸면 목록과 커서를 새로 불러오며, 초기화로 전체 활동을 다시 볼 수 있다. 카드에도 활동 분류·태그를 표시한다.

분류는 [오고토 이벤트 탐색](https://ogoto.co/explore)의 게임·문화·음식·액티비티 등 영역과 [소모임 공식 홈페이지](https://www.somoim.co.kr/)의 운동·문화·야외·공예·사진·반려동물 등 영역, [문토 개발자 앱 소개](https://play.google.com/store/apps/details?hl=ko&id=kr.munto.app)의 활동 예시를 참고해 Sliper용으로 구성했다. 경쟁 서비스의 분류를 그대로 복제한 목록은 아니다. 문토 홈페이지의 동적 화면에서는 최신 상위 분류를 직접 확인하지 못했으므로 공식 앱 설명의 활동 예시만 참고했다.

## 행사장 위치 등록

일반 모집글은 내 행사 관리에서, 템플릿 개설은 개설 양식에서 공개 행사장 좌표를 등록할 수 있다. 현재 위치가 실제 행사장일 때만 현재 위치 버튼을 사용한다. 다른 장소는 지도에서 확인한 위도·경도를 직접 입력한다. 공동 이벤트 맵(`/map`)에서는 NAVER Maps SDK의 주소 검색과 지도 위치 선택으로 공유 장소를 등록하고, 해당 장소를 선택해 번개 작성창에 미리 채울 수 있다. [설정과 사용법](EVENT_MAP.md)을 참고한다.

장소 미등록 기존 글은 기존 목록에 계속 표시하되 반경·거리순에서는 제외한다. 날짜·참가비 필터에는 해당 설정이 있는 행사만 포함한다. 무료라는 표시용 문자열을 임의로 결제 금액으로 추정하지 않고 행사 설정의 실제 금액을 사용한다. 신청 가능 조건은 접수 중, 시작 전, 정원 미충족을 함께 확인하며 확정 참가와 아직 만료되지 않은 유료 예약이 자리를 차지한다. 외부 사후 확인 요청은 정원을 예약하지 않는다.

기존 좌표가 없는 행사는 처음 한 번 위치를 추가할 수 있다. 좌표 지정 후 참가 내역이 생기면 좌표 변경/삭제를 제한한다. 좌표는 공개 행사장의 위치이며 회원의 개인 위치가 아니다. 일반 모집을 이야기로 바꿔 과거 행사 설정이 감사 이력으로 남더라도 일반 글의 공개 응답에서는 좌표·행사 날짜·비용·번개 배지를 제거한다.

## API와 DB

- `POST /api/lightning`: 인증·동일 출처 검사 후 빠른 번개 개설. `activityCategory`와 `activityTags`를 함께 저장한다. 기존 클라이언트의 카테고리 생략은 `other`, 태그 생략은 빈 배열로 처리한다. 클라이언트의 작성자 ID 위조를 거절한다. applicationUrl은 기존 공통 http/https 검증을 사용하고 priceKRW는 0~10,000,000원 정수이며 양수 금액에는 외부 링크가 필수다. 기존 요청은 0원·직접 신청 기본값을 유지한다.
- `GET /api/community`: `sort=nearest`, `latitude`, `longitude`, `radiusKm`, `eventOnly`, `meetupType`, `fromDate`, `toDate`, `minPriceKRW`, `maxPriceKRW`, `availableOnly`를 지원한다. 위도/경도는 함께 제공하고 반경·거리순에는 좌표가 필요하다. `meetupType=lightning`일 때 `activityCategory`, 기존 `tag`·`search`와 조합할 수 있다. 활동 카테고리를 일반 피드에 지정하면 검증 오류를 반환한다.
- `PUT /api/participation/events/{postId}/settings`: 기존 행사 설정에 선택적인 `venue: {latitude, longitude}` 또는 `null`을 제공한다. 필드 생략은 기존 좌표를 유지한다.
- `POST /api/library/{id}/host`: 선택적인 `venue`로 새 템플릿 행사에 위치를 함께 등록한다.

마이그레이션 0016은 `event_settings`에 모임 종류·위도·경도·인덱스와 좌표 쌍/범위·번개 규칙을 추가한다. 0017/0018은 모임 종류·참가 후 위치 변경·번개 게시글 계약을 DB 트리거로 보장한다. 현재 전체 스키마는 60개 테이블이며 기존 데이터와 비공개 스키마/RLS 경계를 유지한다. 0038은 기존 행사 설정에 번개 전용 `activity_category`와 허용값/모임 종류 제약·부분 인덱스를 추가한다. 기존 번개의 NULL 분류는 조회할 때 `other`로 제공하고, `other` 필터에는 NULL과 명시적인 `other`를 모두 포함한다. 기존 글의 제목을 읽어 임의로 분류하거나 데이터를 덮어쓰지 않는다.

0054는 번개 외부 신청·결제를 허용한다. 기존 2~12명·7일 이내·15분~12시간·좌표 범위 CHECK는 유지하고 유료 번개에 외부 링크가 필수인 별도 트리거를 추가한다. 기존 행사 설정 트리거를 변경하지 않아 참가 후 장소·일정 보호와 취소 후 재개 방지 등을 보존한다. 0018의 번개 게시글 트리거는 외부 링크 금지만 요청에 맞게 완화하고 직접 신청의 무료·모집글 조건은 유지한다. 기존 적용된 마이그레이션 파일을 수정하지 않는다.

거리 계산과 전체 결과의 정렬/반경 검사는 DB에서 수행한다. 거리 커서는 원래 거리 값·PostgreSQL 마이크로초 시각·UUID를 보존하고 위치·반경·모임 종류·활동 카테고리·태그·검색어·날짜·금액·회원 조회 범위에 묶는다. 다른 조건의 커서를 재사용하면 거절한다. 게시글 반응·댓글 변경 후에도 현재 검색 위치로 거리를 재계산해 기존 목록과 필터를 유지한다.
