# 수상한 경매장

2026-10-31 · 웹 게임 `/games` · 신규 게임 `auction`

## 진행

호스트는 Sliper 로그인 후 게임 선택에서 **수상한 경매장**을 선택하고 라운드 수·시작 머니·입찰 시간을 설정한다. 참가자는 기존 링크·QR과 기기 쿠키로 로그인 없이 선착순 입장하고 닉네임을 저장한 뒤 준비한다. 호스트는 진행 전용이다.

- 최소 3명, 최대 30명. 실제 참가자 수보다 라운드 수가 반드시 많아야 한다. 최대 120라운드.
- 시작 머니는 모두 동일하며 500~10,000G 범위, 100G 단위. 화면에서는 500/1,000/2,000/5,000/10,000G를 제공한다.
- 입찰 시간은 30/60/90/120초. 기본은 60초.
- 정해진 참가 순서대로 판매자가 바뀐다. 물건은 서버의 24개 목록을 섞어 배정하고 목록을 소진하면 다시 섞는다. 감정가는 매 라운드 새로 무작위 배정하므로 물건 이름으로 고정 감정가를 외울 수 없다.

1. 판매자가 물건의 감정가를 부담하고 소개한다. 감정가는 판매자만 받으며 ‘감정가 보기’로 확인한다.
2. 호스트가 소개 완료 후 공개 입찰을 연다. 판매자를 제외한 참가자들이 현재 최고가보다 최소 10G 높은 금액을 10G 단위로 제시한다. 본인 보유 머니를 초과할 수 없고, 이미 최고가인 사람은 추가 입찰하지 않는다.
3. 동시에 같은 가격이 제출되면 방 행 잠금 안에서 먼저 처리된 유효 입찰 하나만 인정한다. 실제 돈을 쓰는 서비스가 아니며 게임 머니는 현금 교환·결제에 사용하지 않는다.
4. 마감 직전 5초 안에 새 입찰이 있으면 5초를 확보하도록 연장하되, 최초 마감 시각에서 최대 30초까지만 연장한다. 호스트의 명시적 조기 마감도 가능하다.
5. 시간 종료 또는 호스트 마감 때 최고 입찰자에게 낙찰하고, 구매자에게 가격을 차감해 판매자에게 지급한다. 감정가와 판매자/구매자의 차익을 공개한다.
6. 호스트가 다음 물건을 연다. 마지막 라운드까지 끝나면 현금 + 구매 물건 감정가를 합산해 최종 순위를 공개한다. 같은 자산은 공동 순위/공동 우승이다.

라운드 중 공개 자산표는 **직전 정산 기준**이다. 판매자의 매입금이 바로 공개 잔액에 반영되면 감정가가 역산되므로 이를 보정해 표시한다. 본인만 현재 쓸 수 있는 실제 잔액을 받는다. 판매자의 이익은 판매가−감정가, 구매자의 이익은 감정가−낙찰가다.

## 예외 처리

- 유찰: 거래와 물건 보유를 만들지 않고 판매자에게 해당 매입금을 환급한다.
- 잔액 부족: 판매자는 감정가만큼 선차감하여 음수 잔액을 허용한다. 판매 차례를 건너뛰지 않으며 낙찰 대금을 음수 잔액에 더한다. 유찰이면 선차감한 금액만큼 정확히 환급한다. 구매자는 보유 잔액을 초과해 입찰할 수 없다.
- 중도 퇴장: 이미 제출한 유효 최고 입찰은 취소되지 않고 동결된 시작 명단에 따라 정산한다. 퇴장자는 방 상세·비공개 경매 데이터를 받지 않는다.
- 게임 중단: 진행 중인 물건의 매입금만 환급하고 미완료 입찰을 취소한다. 이미 완료한 거래는 결과에 남는다. 공개하지 않은 물건은 제거한다.
- 재준비: 같은 설정으로 시작 머니·명단·거래 내역을 새로 초기화한다.
- 새로고침/재접속: 서버에 저장된 상태를 복원하며, 기존 대기열·방 만료·입장 정책을 유지한다.

## 데이터와 보안

- `sliper.game_rooms.auction` nullable JSONB에 해당 방의 설정·판매 순서·잔액·물건·최고 입찰·최근 입찰 20건·정산 내역을 저장한다. 기존 MBTI/라이어 상태와 별도다.
- Drizzle 생성 마이그레이션 `0077_auction_game.sql`은 선택형 열 하나만 추가한다. 기존 행/계정/글/신청/메시지를 수정하지 않는다. 전체 마이그레이션 78개, 테이블 수 90개 유지.
- 기존 게임방 행 `FOR UPDATE` 트랜잭션에서 입찰·감정가 매입·낙찰·환급·라운드 전환을 직렬화한다. 입찰의 실제 차감은 낙찰 정산 때만 수행하고 라운드별 이력 중복을 차단한다.
- 호스트 작업은 소유자 권한과 revision·라운드를 확인한다. 참가자 요청은 서명 기기 식별·입장 상태·판매자 여부·라운드·서버 시각·잔액을 확인한다. 기존 요청 제한·동일 출처 검사·RLS/직접 브라우저 역할 접근 차단을 유지한다.
- 응답은 역할별 DTO로 만든다. 호스트/구매자는 마감 전 감정가와 판매자의 차감 후 잔액을 받지 않는다. 대기자·미입장자·퇴장자·닫힌 방에는 경매 뷰를 제공하지 않는다. 물건 전체 목록과 덱은 클라이언트 번들에 포함하지 않는다.
- 실시간 전파는 기존 SSE와 변경 힌트 버스를 사용한다. 원본은 PostgreSQL이다. 화면의 250ms 타이머는 로컬 카운트다운이며 매 tick마다 서버나 DB를 호출하지 않는다. 마감 시 한 번 서버 상태를 요청하고, 서버 읽기/작업 요청에서 서버 시각으로 정산한다. 모든 접속이 끊겨 있으면 다음 접속 때 정산되며 별도 고주파 스케줄러를 추가하지 않는다.
- 실제 결제·입출금·외부 유료 API를 추가하지 않는다.

## 검증

- 경매 SQL/규칙 테스트 15개: 비공개 감정가 및 잔액 역산 방지, 참여 권한, 실제 인원 기준 라운드 제한, 동시 동일 입찰, 잔액 초과·재입찰, 중복 정산, 서버 마감, 유찰 환급, 중도 퇴장, 중단/초기화, 순서 반복, 공동 우승, 연장 상한·입찰 이력 제한, 60라운드 자산 보존.
- 기존 게임방·MBTI·제시어 라이어 SQL 회귀 26개 통과.
- 전체 검사 1,157개 통과: 비밀정보·포맷·타입·테스트·Drizzle 일관성.
- 실제 SQL/SSE 브라우저 흐름 5개 통과: 호스트+참가자 3명, 비공개 카드, 실시간 입찰/동률 거절, 정산·음수 잔액·유찰의 정확한 환급·마감 연장·최종 순위·새로고침. 320/393/720/721/1440px 점검, 런타임 오류 없음.
- 실제 휴대폰 하드웨어에서의 추가 다인 수동 플레이는 수행하지 않았다.

## 운영 반영

- 운영 주소: https://sliper.kr/games → 게임 선택 → 수상한 경매장.
- 최종 릴리스: `20261031-auction-game-02`. 판매자 잔액이 감정가보다 적어도 차감 후 음수로 판매를 진행하며, 유찰 시 차감한 감정가만큼 정확히 환급하는 최종 규칙이다.
- 서울 Supabase 마이그레이션 78개 적용. 추가 nullable JSONB 열 한 개이며 기존 계정·글·공지 메시지 수는 유지됐다. 기존 게임 테이블의 RLS·브라우저 역할 직접 접근 차단·실행 역할 접근을 재확인했다.
- Linux 빌드·타입 검사·trace 128개 통과. standalone 4,393파일, 금지 파일·예상 밖 링크 0개.
- 운영용 미리보기와 공개 도메인 화면 검사 **각 35개** 통과. 320/393/720/721/1440px에서 생성·소개·음수 잔액·입찰·정산·순위·중단을 확인했다. 화면 검증은 합성 참가자 응답을 사용하며 실제 운영 방/참가/결제 기록을 생성하지 않았다.
- 실제 SQL 경로는 미리보기의 존재하지 않는 방 접속 요청이 정상 `404 NOT_FOUND`를 반환하는지 확인했다. 이 경로는 새 열을 포함한 실행 DB 조회를 확인하며 방/참가자를 삽입하지 않는다.
- 공통 스크롤 애니메이션이 자동 클릭 중 좌표를 움직이는 변수를 제거하기 위해 공개 화면 QA는 클릭 직전 버튼을 즉시 화면 중앙에 배치한다. pointerdown/up/click/submit과 PATCH 요청을 함께 확인했다. 실제 다인 SQL/SSE 게임 검사는 별도로 통과했다.
- 웹만 최종 버전으로 전환했다. 알림 PID 3452422·영상 PID 3452423, 감시·TLS·Nginx와 기존 별도 사이트는 유지했다. Sliper health·기존 사이트 모두 HTTP 200.
- 신규 빌드의 compiler cache를 최종 릴리스에서 제외했다. 최종 릴리스 약 1.16GiB. 배포 후 루트 디스크 43%, 가용 약 26.79GiB. 기존 보존 릴리스는 삭제하지 않았고, 처음 규칙을 검증했던 미사용 `20261031-auction-game-01`도 보관 중이다. 자동 릴리스 정리는 이번 작업에 포함하지 않았다.
