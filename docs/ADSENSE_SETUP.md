# Sliper AdSense 연결

2026-10-14 기준. 게시자 ID와 광고 단위 ID를 아직 발급하지 않아, 실제 Google 광고 요청은 꺼둔 상태로 연결 구조를 준비했습니다.

## 실제 연결 시작하기

2026-10-15에 다시 확인한 로컬 설정에는 공개 HTTPS 주소·게시자 ID·광고 단위 ID가 없고, 실제 광고는 꺼져 있습니다. 코드 연결 준비와 Google의 계정/사이트 승인은 별도 단계입니다.

| 순서 | 직접 할 일                                                                                        | 프로젝트에서 처리할 일                                                                     |
| ---- | ------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 1    | [AdSense](https://adsense.google.com/start/)에 본인 Google 계정으로 가입하거나 기존 계정에 로그인 | 현재 광고 공간과 연결 코드는 준비됨                                                        |
| 2    | 실제 접속할 공개 사이트 주소와 배포 서비스 결정                                                   | 배포 대상의 HTTPS·DB·인증·환경 설정 확인. 로컬 설정을 그대로 공개하지 않음                 |
| 3    | 계정 → 설정 → 계정 정보에서 게시자 ID 확인                                                        | 해당 계정의 게시자 ID와 실제 사이트 주소로 확인용 설정 적용                                |
| 4    | 사이트 추가에서 공개 URL 등록. 연결 방법으로 메타 태그 또는 ads.txt 선택                          | 실제 광고를 끈 채 홈페이지 메타 태그와 /ads.txt 응답을 확인                                |
| 5    | Google 화면의 계정/지급 정보·본인 확인 안내를 직접 완료하고 사이트 검토 요청                      | 공개 페이지 접근과 확인용 코드 확인. Google 비밀번호·신분증·지급 정보는 채팅으로 받지 않음 |
| 6    | 사이트 상태가 준비됨인지 확인. 광고 → 광고 단위 기준 → 디스플레이 광고 생성                       | 본문은 반응형, PC 왼쪽/오른쪽은 각각 고정 160×600 단위 연결                                |
| 7    | 사이트 자동 광고를 끈 상태로 유지                                                                 | 승인 후 실제 광고 활성화·재배포. 공개 목록과 모바일 배치, 개인 화면 제외 확인              |

게시자 ID는 계정 정보에서는 pub-로 시작하고, 웹 광고 코드에서는 ca-pub-로 시작합니다. 둘 중 준비된 값을 알려주면 코드용 형식을 맞출 수 있습니다. 광고 단위 ID는 광고 코드의 data-ad-slot 값입니다. 본문 단위부터 연결할 수 있으며 PC 좌우 단위는 나중에 추가해도 됩니다.

처음 연결에 필요한 정보는 **공개 사이트 주소, 배포 서비스 이름, 게시자 ID**입니다. 승인 여부와 광고 단위 ID는 준비된 범위만 전달하면 됩니다. 전체 .env 파일이나 Google 로그인 정보는 필요하지 않습니다. 아직 공개 주소가 없다면 사이트 배포부터 진행하고, 현재 127.0.0.1:3000 주소를 심사용 주소로 등록하지 않습니다.

공식 절차: [계정 만들기](https://support.google.com/adsense/answer/7402253?hl=ko), [게시자 ID 찾기](https://support.google.com/adsense/answer/105516?hl=ko), [메타 태그·ads.txt로 사이트 연결](https://support.google.com/adsense/answer/7584263?hl=ko), [디스플레이 광고 단위 생성](https://support.google.com/adsense/answer/9274025?hl=ko).

## 배치

- 공개 목록인 홈, 이야기, 번개 모임, 통합 아카이브, 주제 탐색에 기존 광고 공간을 사용합니다.
- 본문 광고는 모바일에서도 페이지 흐름 안에 표시하며, 데스크톱 좌우 광고는 별도 광고 단위를 사용합니다.
- 실제 AdSense 광고에는 자동 넘김·주기적 새로고침·강조 애니메이션을 적용하지 않습니다. 기존 자체 광고 바텀시트에 Google 광고를 넣지 않습니다.
- 공지방, 개인정보·알림·관리·결제·글 작성 화면, 회원 전용 행사 기록과 개인 포트폴리오, 게시글·자료 상세는 초기 적용 범위에서 제외합니다.

실제 광고는 명확한 광고 표기로 구분합니다. 클릭·신청·닫기 버튼과 겹치지 않으며, 보이지 않는 좌우 공간은 광고 요청을 보내지 않습니다. 이 배치는 Google의 [광고 게재 위치 정책](https://support.google.com/adsense/answer/1346295?hl=ko)을 기준으로 정했습니다.

## 발급 후 설정

1. AdSense에서 실제 서비스 도메인을 등록하고 게시자 ID를 확인합니다. 본문용 반응형 디스플레이 광고와 좌우용 고정 160×600 디스플레이 광고를 만들어 광고 단위 ID를 준비합니다. 좌우 단위는 선택 사항입니다. [공식 반응형 광고 안내](https://support.google.com/adsense/answer/9183363?hl=ko)
2. 배포 환경변수 또는 Git에서 제외된 프로젝트 루트의 .env.local에 아래 값을 입력합니다. ca-pub-로 시작하는 게시자 ID와 숫자로 된 광고 단위 ID는 공개 식별자이며 API 비밀키가 아닙니다. 전체 .env 파일을 공유할 필요는 없습니다.

```dotenv
APP_ORIGIN=https://실제서비스도메인
LOCAL_DATABASE=0
SLIPER_ADSENSE_ENABLED=false
SLIPER_ADSENSE_CLIENT_ID=
SLIPER_ADSENSE_SLOT_INLINE=
SLIPER_ADSENSE_SLOT_LEFT=
SLIPER_ADSENSE_SLOT_RIGHT=
```

3. 먼저 게시자 ID와 도메인만 입력하고 SLIPER_ADSENSE_ENABLED=false를 유지한 채 운영 모드로 배포합니다. 이때 계정 확인 메타 태그와 ads.txt로 사이트 소유 확인을 준비하고 실제 광고는 요청하지 않습니다. NODE_ENV는 Next.js의 build/start가 production으로 설정하므로 별도로 개발 환경을 production으로 바꾸지 않습니다. 사이트 승인 후 광고 단위 ID를 입력하고 SLIPER_ADSENSE_ENABLED=true로 전환하면 광고를 활성화할 수 있습니다. 게시자·본문 단위·공개 HTTPS 도메인이 모두 올바르게 설정되어야 합니다. 값을 변경하면 서버를 재시작하거나 다시 배포합니다.
4. 실제 도메인의 /ads.txt를 열어 올바른 게시자 정보가 표시되는지 확인합니다. 운영 환경의 유효한 게시자 ID와 도메인이 있으면 광고 활성화 전에도 Google 형식의 한 줄을 자동으로 제공합니다. [공식 ads.txt 가이드](https://support.google.com/adsense/answer/12171612?hl=ko)
5. 이 구현은 수동 디스플레이 광고용입니다. **AdSense 사이트 설정의 자동 광고(Auto ads)를 끄세요.** Google 계정에서 자동 광고를 켜면 Sliper의 경로·개인 화면 제외 정책 밖에 광고가 생길 수 있습니다. AdSense에서 사이트 검토와 승인 상태를 확인합니다. 승인·광고 재고·브라우저 차단 여부에 따라 광고가 비어 있을 수 있으며, 코드 설정만으로 Google의 사이트 승인이 완료되는 것은 아닙니다. 개인정보처리방침의 광고·쿠키 안내도 실제 운영에 맞게 갱신합니다.

## 설정 규칙과 검증 범위

설정은 서버에서 읽고, 공개 식별자와 선택한 도메인만 광고 컴포넌트에 전달합니다. 다른 환경변수는 전달하지 않습니다. 왼쪽·오른쪽을 비워 두면 해당 공간에 Google 광고를 요청하지 않습니다. 잘못된 광고 단위 ID는 실제 광고 연결을 비활성화하며, 유효한 게시자·도메인의 사이트 확인은 유지합니다. 게시자 ID나 도메인이 잘못되면 사이트 확인도 제공하지 않습니다. mine·used·내 글·북마크·글 작성 등 개인 화면을 선택하는 URL 조건과 알 수 없는 URL 조건에서도 실제 광고를 제외합니다.

개발 서버, LOCAL_DATABASE=1, 다른 호스트 및 미설정 상태에서는 Google 스크립트와 광고 요청이 없습니다. 로컬 /ads.txt는 404를 반환하며, 코드에 예시 게시자나 가짜 광고 단위가 자동 삽입되지 않습니다. 단위 검사는 가상의 값을 메모리에서만 검증하고 Google 서버에 접속하지 않습니다.

현재 단계는 연결 준비입니다. 실제 계정 발급, 사이트 승인, 광고 수익 확인은 실제 서비스 도메인과 본인 AdSense 계정에서 진행해야 합니다. 자동 광고는 사용하지 않습니다. 이미 실행된 외부 스크립트는 React 화면 전환으로 되돌릴 수 없으므로 이 구현은 비공개 화면에서 광고 단위를 만들거나 요청하지 않는 방식이며, 외부 스크립트가 완전히 제거되었다고 보장하지 않습니다.

EEA·영국·스위스 방문자에게 개인 맞춤 광고를 제공할 때에는 Google 인증 TCF CMP 설정이 필요합니다. AdSense의 개인정보 보호 및 메시지 메뉴에서 Google의 유럽 규정 메시지 등을 설정하고 실제 수신 범위를 확인하세요. 임의의 체크박스나 비개인 맞춤 광고 설정이 이 요건을 자동으로 대체하지 않습니다. [Google CMP 안내](https://support.google.com/adsense/answer/13554116?hl=ko)

현재의 검색 noindex 정책은 유지합니다. 승인 검토 시 공개 페이지가 Google 광고 크롤러에 접근 가능한지 확인하고, 회원 전용 본문이나 자료는 공개하지 않습니다. 승인용 설정과 검색 노출 범위는 별도로 검토합니다.

## 로컬 검증

- 전체 보안·서식·TypeScript·869개 단위/DB 검사·Drizzle 검사 통과. 새 광고 검사는 설정/공개 범위 9개와 표시 크기/중복 요청/Observer 정리 10개입니다.
- 실제 Next HTTP 검사 1개 통과: 홈·이야기·번개·아카이브와 개인 보기·이의신청·정보 안내에서 로컬 Google 스크립트/광고 단위/가짜 게시자 정보가 없으며 `/ads.txt` GET·HEAD가 404/no-store인 것을 확인했습니다.
- 광고 단위는 화면에 보이는 Placeholder만 두었다가 Google 코드가 준비된 뒤 올바른 크기의 위치에 생성합니다. 숨겨진 양옆 단위가 다른 단위의 Google 큐에 잡히지 않도록 처리했습니다. 동일 페이지/동일 영역에서 모달 재진입이나 StrictMode로 DOM이 다시 만들어져도 반복 요청하지 않습니다.
- 글 작성·상세 모달·내 글·북마크·개인/운영 사례 아카이브와 빈 목록은 새 광고 요청을 막습니다. 새 페이지/공개 필터로 이동할 때만 광고 단위의 새 요청을 허용합니다. 실제 광고를 주기적으로 회전시키는 타이머는 없습니다.

로그: `.local/adsense-check.log`, `adsense-focused-tests.log`, `adsense-http.log`, `adsense-build.log`. 실제 광고 계정·승인·수익·모바일 광고 렌더링·CMP 동작은 아직 검증하지 않았습니다. 연결 준비 검증과 실제 광고 게재 검증을 구분합니다.

운영 빌드와 서버 trace 107개 검사도 오류 0개로 통과했습니다. 빌드 후 로컬 서버를 0.0.0.0:3000으로 복구하고 같은 HTTP 검사를 다시 통과했습니다.
