# 로컬 테스트 로그인

카카오·구글 OAuth와 정식 회원가입을 연결하기 전, 개발용 계정 하나로 로그인·글쓰기·참가 신청·마이페이지와 알림 안내 흐름을 확인할 수 있다. 기존 샘플 작성자와 다른 UUID의 `auth.users` 행과 `테스트플레이어` 프로필을 사용한다. OAuth 버튼은 여전히 실제 공급자 인증에 연결되지 않았다.

## 계정 준비와 사용

로컬 DB를 시작하고 마이그레이션을 적용한 `C:\Sliper`에서 실행한다.

```powershell
npm run auth:test:setup
npm run dev
```

최초 실행은 새 계정을 생성하고 아이디와 무작위 비밀번호를 **한 번만** 출력한다. 출력된 정보를 따로 보관한 뒤 `/login`에서 입력한다. 닉네임·연락처와 정보 저장 동의가 아직 없으면 첫 로그인 후 `/signup`으로 이동해 기본정보를 완성한다. 저장한 정보는 이후 행사 신청에서 자동으로 사용하고, 마이페이지에서 수정할 수 있다. 번호는 형식만 확인하며 문자 인증은 아직 연결하지 않았다. 기본정보를 완료한 계정은 홈 또는 원래 접근하던 화면으로 이동한다. 마이페이지와 활동 기록은 이 테스트 프로필에 연결된다. 알림 권한을 자동으로 요청하지 않고 기존 기기별 알림 안내를 이어서 표시한다. [기본정보와 참가 질문 사용법](APPLICATION_FORMS_AND_PROFILES.md)을 참고한다.

이미 유효한 계정 파일이 있으면 기존 계정과 비밀번호를 유지한다. 스크립트를 다시 실행해도 새 비밀번호를 발급하거나 기존 비밀번호를 복구해 출력하지 않는다. 파일이 손상된 경우 임의로 초기화하지 않고 오류를 반환한다. 평문 비밀번호를 DB·설정 파일·문서에 저장하지 않는다.

## Wi-Fi에서 접속

`SLIPER_LAN_HOST`에는 개발 PC의 정확한 사설 IPv4 주소를 설정한다. 허용하는 대역은 `10.x.x.x`, `172.16.x.x`~`172.31.x.x`, `192.168.x.x`이며 포트는 `3000`이다.

```powershell
# 아래 주소는 예시이며 실제 PC의 Wi-Fi 주소로 바꾼다.
$env:SLIPER_LAN_HOST = '192.168.0.10'
npm run dev:lan
```

같은 Wi-Fi의 휴대폰에서 해당 주소의 `/login`을 열고 발급받은 아이디·비밀번호로 로그인한다. 서버는 `127.0.0.1:3000`, `localhost:3000`, **현재 설정된 정확한 LAN 주소:3000**만 허용한다. 사설 IP라는 이유만으로 다른 주소의 로그인을 허용하지 않는다. 환경값을 변경한 뒤 서버를 다시 시작해야 한다.

LAN에서 비밀번호를 입력하지 않은 사용자는 비회원이다. 기존 쿠키 없는 loopback 접속의 고정 작성자 fixture는 로컬 기능 검증을 위해 유지하지만 LAN으로 확장하지 않는다. 테스트 로그인 쿠키가 있으면 fixture보다 우선하며, 잘못되거나 만료된 쿠키가 있는 요청을 fixture 사용자로 대체하지 않는다.

**HTTP LAN 주소에서는 웹푸시를 연결할 수 없다.** 테스트 계정은 Wi-Fi에서 일반 사이트 기능과 로그인 흐름을 확인하기 위한 것으로, HTTP를 보안 컨텍스트로 바꾸지 않는다. 휴대폰의 실제 푸시에는 HTTPS, 지원 브라우저와 알림 허용이 필요하고 iOS는 홈 화면 웹앱 실행이 필요하다. 현재 이 로컬 로그인 어댑터는 임의의 공개 HTTPS 호스트를 허용하지 않는다. 운영 HTTPS 주소에서는 실제 회원 인증을 연결해야 한다. [웹푸시 설정](WEB_PUSH.md)을 참고한다.

## 저장·세션·보안 경계

- Git에서 제외한 `.local/test-account.json`에 무작위 salt와 **scrypt 비밀번호 해시**, 세션 HMAC 비밀키, 계정 버전 nonce를 보관한다. 계정 파일이나 비밀키를 클라이언트로 보내지 않는다.
- 인증 세션은 HMAC-SHA256으로 서명한 `HttpOnly`, `SameSite=Lax`, host 전용 쿠키다. HTTPS 요청에서는 `Secure`도 설정한다. 세션은 **7일** 유효하며 다른 호스트에서 재사용할 수 없다. 현재 로그인에는 자동 연장 기능이 없다.
- 헤더의 로그아웃은 쿠키를 삭제하는 대신 **서명된 비회원 세션으로 교체**한다. 이를 통해 loopback의 고정 fixture로 자동 전환되는 것을 막는다. 비회원 쿠키도 7일 유효하다.
- 로그아웃은 현재 브라우저 쿠키를 교체한다. 기존 인증 토큰을 서버에서 일괄 폐기하는 다중 기기 로그아웃 기능은 없으며, 별도 저장된 기존 토큰은 원래 만료 시각까지 유효할 수 있다.
- 로그인 쓰기는 동일 출처 요청만 받는다. 잘못된 로그인은 계정 전체 기준 1분에 최대 5회로 제한하고 동시에 비밀번호 검증을 중복 실행하지 않는다. 이 제한은 단일 개발 서버의 메모리에 유지되며 서버 재시작 시 초기화된다.
- `NODE_ENV=development`, `LOCAL_DATABASE=1`, `SLIPER_AUTH_MODE=development`와 정확한 `127.0.0.1:55432/sliper_dev` PostgreSQL 주소가 모두 일치해야 활성화된다. 운영 빌드·원격 DB·다른 호스트에는 이 계정이 인증을 제공하지 않는다.

테스트 계정 한 개는 실제 사용자 간 OAuth 인증이나 여러 회원의 권한 경합 테스트를 대신하지 않는다. 운영에는 검증된 Supabase 세션과 별도 회원 정책을 연결한다.

## 관련 코드

- `scripts/test-account-setup.ts`: 계정·프로필 준비, 최초 비밀번호 출력
- `src/server/local-test-auth.ts`: 계정 파일 검증, scrypt 검증, 서명 세션·만료·호스트 검사
- `src/server/local-test-access.ts`: 환경·정확한 호스트 제한, 로그인 요청 제한
- `src/server/identity.ts`: 테스트 세션 우선 처리와 기존 loopback fixture
- `src/app/api/auth/test/[[...path]]/route.ts`: 로그인·로그아웃·세션 조회 API
- `src/components/login-page.tsx`, `src/components/test-account-controls.tsx`: 로그인 양식·헤더 계정 상태
- `tests/local-test-auth.test.ts`, `tests/local-test-access.test.ts`: 환경·서명·만료·호스트·요청 제한 검증

## 로그인 HTTP 검증

개발 서버가 실행 중일 때 새 비밀번호를 현재 터미널 프로세스에만 지정해 검사한다. 비밀번호를 `.env`나 소스 파일에 기록하지 않는다.

```powershell
$env:SLIPER_TEST_PASSWORD = '<발급받은 테스트 비밀번호>'
$env:SLIPER_LAN_HOST = '<현재 서버와 동일한 Wi-Fi IPv4>'
npm run test:auth-api
Remove-Item Env:SLIPER_TEST_PASSWORD
```

이 검사는 잘못된 비밀번호·다른 출처·조작된 입력과 쿠키·다른 호스트의 세션 재사용을 차단하고, 로그인 후 별도 프로필 조회·LAN 글쓰기·로그아웃 후 비회원 상태를 확인한다. 테스트용 글만 생성 후 소프트 삭제한다. 실제 휴대폰 화면의 직접 조작이나 잠금 화면 푸시 수신을 검증하는 테스트는 아니다.
