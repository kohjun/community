# D — 주제별 연결과 자료 조건 탐색

2026-10-12 · 주제 작성·역탐색 동선까지 보완. E 행사 이후 할 일·기록·재개최도 [구현·검증](COMMUNITY_EVENT_AFTERCARE.md)했으며 다음 제품 단계는 F 신뢰 운영과 공개 준비입니다.

## 사용자 동선

상단 메뉴의 **주제 탐색**(`/topics`)에서 추리와 심리 게임, 미션 레이스, 소셜 파티를 선택합니다. `/topics/{slug}`에는 이야기·모임·진행 자료 탭이 있고 각각 12개씩 독립적으로 페이지를 넘깁니다. 모바일에서는 같은 탭으로 요약을 읽습니다. 아카이브에도 주제 탐색 링크를 제공합니다.

관련성은 글·자료에 작성자가 등록한 태그의 명시적인 별칭만 사용합니다. 예를 들어 `추리`, `추리게임`, `마피아`, `크라임씬`은 추리 주제에, `미션레이스`, `미션 레이스`, `런닝맨`은 레이스 주제에 연결합니다. 공백·대소문자·앞의 `#`를 정리하며 여러 별칭이 있어도 한 콘텐츠를 중복 표시하지 않습니다. 제목·본문·카테고리만으로 관계를 추정하지 않습니다. 세 주제와 별칭은 `src/domain/topics.ts`의 코드 관리 목록이며, 별도 운영자 편집 화면이나 주제 DB는 아직 만들지 않았습니다.

**내 관심 글**은 기존 카테고리·호스트 구독과 주제 태그의 교집합입니다. 익명 글을 호스트 구독으로 골라 작성자를 추론할 수 없게 합니다. 비회원·구독이 없는 회원에게는 전체 주제 글과 설정 안내를 제공합니다. 이 화면을 보는 것으로 푸시 구독을 추가하지 않습니다. 진행 자료 탭은 해당 주제의 공개 소개 전체를 유지합니다.

스포일러 글은 C의 태그 검색 정책에 맞춰 주제 관계·개수에서 제외합니다. 숨김·삭제·초안·차단·탈퇴 상태도 같은 조건으로 목록과 개수를 계산합니다. 주제 DTO에는 본문 문서·이미지·영상·연락처·신청 답변·유료 운영 계획·회원 전용 행사 기록을 포함하지 않습니다. 주제별 메타데이터에는 운영자가 정한 소개만 사용합니다.

## 작성과 관련 주제 이동

이야기·모집 작성과 자료 편집에 **주제 연결** 버튼을 제공합니다. 주제를 누르면 대표 태그를 추가하고, 연결될 주제와 현재 태그 수를 즉시 보여줍니다. 카테고리로 관계를 추정하지 않으며 자유 입력 태그는 유지합니다. 글·자료의 기존 최대 5개 제약을 지키고, 이미 별칭으로 연결된 주제의 버튼은 중복 추가되지 않습니다.

주제 탭의 **이야기 쓰기 / 모임 열기 / 자료 올리기**에서 이동하면 해당 주제의 카테고리와 대표 태그를 새 작성 화면에 채웁니다. 이야기와 모집은 종류까지 유지하고 작성 모달을 엽니다. 기존 글·자료를 편집할 때는 원래 값이 우선입니다. 비회원은 로그인 후 같은 작성 종류와 주제로 돌아갑니다. 주소의 알 수 없는 주제·중복 주제는 작성 초기값에서 무시하며 임의의 값을 태그로 저장하지 않습니다.

공개 글과 발행 자료의 상세에는 **관련 주제** 링크가 생겨 같은 취향의 이야기·모임·자료로 돌아갈 수 있습니다. 스포일러 글과 비공개 초안에는 이 링크를 제공하지 않습니다. 자료 본문과 구매 권한에는 변화가 없습니다.

관심 피드 변경·다른 주제 이동·섹션 페이지 이동에서 선택한 탭을 주소의 해시로 유지합니다. 해시가 없는 주소는 이야기 탭으로 복원하며 페이지 링크의 해시와 실제 패널 ID를 일치시켰습니다. 아카이브의 운영 사례 로그인 안내도 사용자가 지정한 검색 조건을 복귀 주소에 유지합니다.

## 아카이브 조건

| 조건 | 의미 |
| --- | --- |
| 참가 인원 | 최소 인원 ≤ 예정 인원 ≤ 최대 인원, 1~5000명 |
| 최대 진행 시간 | 자료의 진행 시간 ≤ 조건, 5~1440분 |

| 회원 공개 운영 사례 있음 | 이 회원이 현재 열람할 수 있는 발행된 완료 기록이 존재 |
| 준비 난이도 | 작성자가 공개한 쉬움/보통/높음 |

필터·검색·자료 유형·내 자료·다음 페이지 위치를 주소에 유지합니다. 조건을 바꾸면 이전 커서를 제거합니다. 커서는 모든 필터와 현재 열람 회원에 묶여 있어 다른 조건·다른 회원의 목록 위치로 재사용할 수 없습니다. 한 요청은 기존처럼 24개를 반환합니다. 잘못된 주소나 오래된 커서는 화면에서 첫 목록과 복구 안내를 제공하며 API는 잘못된 조건·중복 조건을 거절합니다.

## 공개 정보와 원본 보존

`library_entries.discovery_metadata`는 선택적인 공개 JSON입니다. 준비 난이도·환경·추가 스태프만 담고 DB 제약과 입력 검증을 적용합니다. 기존 자료는 `null`로 남으며 유료 `eventPlan`의 예산·미션·장소를 추출하거나 추정하지 않습니다. 입력이 없는 조건은 **미입력**으로 표시하고 해당 필터 결과에서 제외합니다.

작성·수정 화면에서 공개 정보를 직접 입력합니다. 공개본 수정은 초안으로 보관되고 발행할 때만 목록 조건이 바뀝니다. 과거 클라이언트가 새 필드를 보내지 않아도 기존 값을 유지하며, 명시적 `null`은 공개 메타데이터를 철회합니다. 발행 버전은 당시 값을 보존합니다. 이전 버전에 없던 키를 일괄 추가하지 않고, 이미 개설된 행사의 진행 사본도 변경하지 않습니다.

`visibleUseCases`는 **현재 회원에게 보이는 운영 사례 수**입니다. 기존 완료 참가 집계 `recordedEvents`/`recordedPlayers`와 구분합니다. 비회원에게는 사례 수를 0으로 제공하고 사례 필터 사용 시 로그인을 안내합니다. 사례는 기존 운영 사례 상세와 동일한 `recordVisible` 및 원본·발행 버전·행사 당시 스냅샷 조건을 공유합니다. 단순 작성 예시·초안·공개 철회·숨김·샘플·취소·차단·탈퇴 기록이나 잘못 연결된 버전을 포함하지 않습니다. 관계가 있다고 유료 자료 본문을 열거나 회원 기록 권한을 얻지 않습니다.

원본은 PostgreSQL입니다. Redis·푸시·결제·미디어 처리 방식을 변경하지 않았습니다. 마이그레이션 `0058_bright_karen_page.sql`은 nullable 컬럼과 형태 제약만 추가하며 격리 로컬 DB에 적용했습니다.

## 조회 API

- `GET /api/topics`: 세 주제 목록.
- `GET /api/topics/{slug}?focus=all|interests&storiesPage=1&recruitmentPage=1&libraryPage=1`: 세 섹션과 현재 필터·권한에 맞는 개수. 각 페이지는 1~100, 12개 단위이며 동일 시각은 ID로 정렬합니다. 최대 1200개까지 접근하는 탐색 화면입니다.
- `GET /api/library`: 기존 `kind/category/search/mine/cursor`와 `players/maxDurationMinutes/price/used/difficulty/environment/maxStaff`를 조합합니다.
- 기존 작성·초안·발행·버전·행사 개설 API는 선택 필드 `discoveryMetadata`를 함께 보존합니다.
