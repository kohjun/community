# Sliper E — 행사 이후 할 일과 재개최

구현·검증 기준일: 2026-10-12. [커뮤니티 개선 계획](COMMUNITY_IMPROVEMENT_IMPLEMENTATION_PLAN.md)의 E 단계입니다. 신규 DB 테이블·마이그레이션·푸시 작업 없이 기존 완료·행사 기록·제작진·자료 버전 데이터를 연결했습니다.

## 화면과 사용 흐름

- `/management`: 운영하는 행사의 완료 확인, 회고 작성, 제작진 수락·정정 요청을 보여줍니다.
- `/mypage`: 위 운영 작업과 본인의 인증 후기, 제작 경력 확인 요청을 함께 보여줍니다.
- 두 화면에서 ‘해야 할 일 / 전체 흐름’을 전환하고 20개 단위 번호 페이지와 새로고침을 사용할 수 있습니다. 실패한 요청은 기존 목록을 유지하고 다시 시도합니다. 이전 요청이 늦게 도착해 새 목록을 덮어쓰지 않습니다.
- 완료·전적·제작진·후기 버튼은 기존 화면의 해당 영역으로 연결합니다. 회고는 주최자만 편집·발행하며, 지정 담당자에게 편집 버튼을 제공하지 않습니다.

| 대상과 상태 | 표시와 다음 행동 |
| --- | --- |
| 종료 시각이 지난 미완료 행사 | 담당자가 참가 확인을 정리하고 완료 확인 |
| 완료된 행사에 기록 초안이 없는 기존 데이터 | 완료 재확인으로 기존 완료 시각을 유지하며 초안 복구 |
| 주최자의 초안·공개 철회 기록 | 회고 작성·검토 후 직접 발행 |
| 제작진 수락 대기 | 담당자는 확인 요청 관리, 본인은 기여 내용 검토·수락 |
| 제작진 정정 요청 | 담당자의 해야 할 일에 표시; 요청자에게는 정정 대기 이력 |
| 발행한 행사 기록 | 운영 회고·자료 개선·다음 행사 준비 |
| QR 입장·참가 확정·종료·미작성 인증 후기 | 기존 인증 후기 화면으로 이동 |
| 담당자 확인 출석 또는 실제 참석 후 환불 | 참가 전적 확인; 새 인증 후기 권한을 추가하지 않음 |

후기 자격은 기존 API를 그대로 따릅니다. 현재 QR 입장과 확정 상태가 필요하며, 담당자 확인만 있는 참가나 환불 후 참가에는 새 인증 후기 작성 버튼이 없습니다. 실제 참석 전적은 금전 상태와 구분해 유지합니다. 주최자는 자신의 행사에 참가 인증 후기를 작성할 수 없고, 미참석 전적은 참가 작업에서 제외됩니다.

## 기록에서 자료 개선과 새 행사로

행사 기록의 ‘회고로 템플릿 초안 만들기’를 재사용합니다. 주최자가 자신의 운영 회고를 비공개 초안으로 검토하고 편집·발행할 수 있습니다. 현재 사용한 자료가 보이는 기록에는 ‘사용한 자료로 다음 행사 준비’를 제공합니다.

재개최 주소는 `/archive/{자료ID}/host?fromRecord={행사ID}`입니다. 회원·기록·현재 자료 이용 권한을 각각 확인하고, 실제 당시 자료 또는 그 회고에서 만들어진 자료만 출처로 연결합니다. 무관한 행사 ID와 잘못된 주소는 404입니다. 비회원은 동일한 재개최 주소를 보존한 로그인 동선으로 이동합니다.

새 개설 화면은 당시 제목과 공개 가능한 장소를 참고 정보로 제공합니다. 이전 일정은 채우지 않고 새 미래 일정을 입력해야 합니다. 참가비·정원·장소·일정 확인 항목을 선택해야 화면에서 제출할 수 있습니다. 개설 API는 기존 일정·금액·정원·이용 조건 검사를 유지합니다. 참가자·신청 답변·공지방·회고 본문·사진·영상·진행 자료를 복사하지 않습니다.

현재 발행된 자료 버전과 당시 운영 버전을 구분해서 안내합니다. 새 행사는 현재 허용된 자료 버전으로 별도 개설되고, 이전 행사에 보관된 진행 사본과 참가 조건은 바뀌지 않습니다. 기록 링크는 유료 자료 이용 권한을 부여하지 않습니다.

## 원본 데이터와 권한

`GET /api/event-aftercare`는 `scope=all|hosting|participation|credits`, `view=pending|all`, `page=1..1000`을 받습니다. 중복 조건과 API에 전달된 알 수 없는 조건은 거절합니다. 결과는 `items, page, hasMore, total, pendingTotal`이며 페이지당 20개입니다. 범위를 넘어선 유효 페이지 요청은 해당 목록의 마지막 페이지로 맞춥니다. 수치는 행사 성과 지표가 아니라 현재 조회자의 활동 흐름 개수입니다.

서버가 기존 원본에 현재 권한을 적용한 후 단일 SQL 조회로 작업·건수·페이지를 계산합니다. 취소·샘플·삭제·운영 숨김·주최자 탈퇴/제한·양방향 차단을 제외합니다. 제작진 대상의 차단·계정 상태도 확인하며 여러 역할은 제작진의 행사별 한 항목으로 묶습니다. 읽기 요청은 완료·초안·전적·제작진·발행·점수·알림을 변경하지 않습니다.

응답은 작업 제목·분야·종료 시각·역할·단계·안내·권한에 맞는 링크만 제공합니다. 타 회원의 내부 ID, 연락처, 신청 답변, 원문, 미디어와 진행 자료를 반환하지 않습니다. 완료 후 행사 제목·분야·일정은 당시 스냅샷을 사용합니다. 회고 공개·철회와 숨김·차단 정책을 그대로 유지하며, 일반 참가자에게 초안·철회 기록 링크를 제공하지 않습니다.

재개최 참고 정보 역시 기록 서비스가 허용한 요약만 사용합니다. 장소 공개 정책으로 가려진 주소를 새 폼에 채우지 않습니다. 기록 페이지·원본 미디어·자료 구매의 기존 서버 접근 검사는 유지됩니다.

PostgreSQL이 원본입니다. Redis는 기존 공지방 갱신 용도로 유지합니다. 이번 단계는 사이트 안의 작업 안내만 제공하며 별도의 반복 안내·푸시 발송을 추가하지 않았습니다.
