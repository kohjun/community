# 비밀값과 Git 보호

2026-10-11 점검. 서버 비밀값은 저장소 루트의 `.env` 또는 배포 환경의 비밀변수에서 읽습니다. `.env`, `.env.*`(빈 `.env.example` 제외), `.local`, 개인키·인증서·서비스 계정 파일은 `.gitignore`로 제외합니다. `NEXT_PUBLIC_` 변수에는 브라우저에 공개해도 되는 값만 설정합니다.

## 이번 점검과 변경

- `tests/image-storage.test.ts`의 고정 Supabase 모양 문자열은 실제 발급 키가 아닌 메모리 어댑터 테스트 예시였습니다. 실행마다 만드는 임시값으로 교체했습니다. 해당 테스트는 Supabase에 연결하지 않으며 실제 `.env` 키를 사용하지 않습니다.
- 배포 준비 검사에서도 서버키 모양의 예시와 Redis 테스트 비밀번호를 실행마다 생성합니다. 실제 서버 설정은 기존 환경변수 경로를 유지합니다. 공유용 `.env.example`의 비밀변수는 빈 값입니다.
- `.env`와 `.local/test-account.json`이 Git 제외 대상이며 추적 파일이 아님을 확인했습니다.
- `npm run security:secrets`: 추적 파일과 제외되지 않은 미추적 파일의 알려진 비밀키 형태, 개인키, 연결 비밀번호, 현재 로컬 환경의 서버 비밀값과 일치하는 내용을 검사합니다. 로컬 환경값과 일치 검사에는 8자 이상 값만 사용합니다. 8MB 초과 파일과 바이너리는 텍스트 값 검사의 대상이 아닙니다. 비밀 파일 경로 자체는 빈 파일이어도 거절합니다.
- `npm run security:staged`: 작업 폴더 대신 Git index에 저장된 파일 내용으로 검사합니다. 파일을 편집해 키를 지운 뒤 다시 스테이징하지 않은 경우도 차단합니다. 검사 실패 출력에는 경로·줄번호·이유만 포함하며 비밀값을 출력하지 않습니다.
- `.githooks/pre-commit`을 이 로컬 저장소에 연결했습니다. 훅 파일은 `.gitattributes`로 LF 줄바꿈을 고정합니다. `npm run check`에도 비밀값 검사를 포함했습니다.

## 감사 범위

현재 소스·스크립트·테스트·설정 501개와 이 저장소에서 접근 가능한 Git 커밋 3개의 텍스트 파일 스냅샷 1,319개를 값 비출력 방식으로 검사했습니다. 실제 발급된 비밀키 노출은 확인하지 못했고, 발견된 형태는 의도적인 테스트 예시였습니다. 브라우저 컴포넌트의 정적 import 경로에서는 DB 접근이 `use server` 및 `server-only` 경계를 통하는 것을 확인했습니다. 외부 원격 저장소, 삭제되어 접근할 수 없는 Git 객체, 실제 서비스 계정은 조사하지 않았습니다.

## 다른 체크아웃에서 적용

```powershell
npm install
git config --local core.hooksPath .githooks
npm run security:secrets
```

Git 훅은 로컬 설정이므로 새 체크아웃에는 다시 연결해야 합니다. 이미 별도 훅을 쓰는 저장소는 기존 훅을 보존하고 그 안에 `npm run security:staged`를 연결합니다. Git hook을 우회할 수 있으므로 운영 저장소 CI에도 `npm run security:secrets`를 실행해야 합니다.

## 검증

비밀값 탐지·이미지 저장·배포 설정 검사 30개와 격리된 Git 스테이징 검사 4개가 통과했습니다. 전체781개 검사 및 운영 빌드도 통과했습니다. 브라우저용 빌드 자산68개에서 현재 설정된 서버 비밀값과 일치하는 내용을 찾지 못했습니다.

## 실제 키가 이미 게시되었다면

환경변수로 옮기거나 `.gitignore`를 추가해도 이전 커밋·PR·로그의 값은 사라지지 않습니다. 해당 서비스에서 실제 키를 폐기·재발급하고 배포 환경을 갱신한 다음, 원격 저장소 기록 정리 여부를 협의합니다. 이번 작업에서는 키 폐기, Git 기록 재작성, 커밋 또는 원격 푸시를 하지 않았습니다. 패턴 검사 통과는 모든 종류의 비밀값이 없다는 보증이 아닙니다.
