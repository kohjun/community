## 완료한 기준선

- 기존 Ncloud 서버의 별도13000 포트에서 Sliper 웹·알림·영상 워커와 공인 IP HTTPS 운영.
- Google·Kakao 실제 계정 로그인 성공과 Android Chrome 실기기의 테스트 푸시 도착을 사용자 확인.
- 경량 감시 배포, 실제 BetterStack 장애 이메일 수신 확인, 감시200·자동 점검 복구 확인.
- DB115테이블·private5파일 암호화 캡처와 새 로컬 PostgreSQL18의 논리 복원·해시/구조 검증.
- 서버 설정·VAPID·인증서의 별도 암호화 캡처와 복호화/경로 검사.
- 직전 전체 검사1,093개와 Python 감시 검사5개 통과.

테스트 푸시 수신은 실제 댓글·공지 알림 전체를 검증했다는 뜻이 아니다. 로컬 DB 복원은 새 Supabase 프로젝트에서 관리형 Auth·Storage·Realtime을 복구한 결과와 구분한다.

## 보류 범위

사용자가 보류한 작업은 **정기 백업 자동화와 별도 보관처 설정**이다. 기존 암호화 백업과 실제 복원 기록은 유지한다. 정기 일정·저장소·키 사본을 임의로 추가하지 않는다.

카메라 실기기 검증은 사용자 요청으로 보류한다. 테스트 모임 일정은 변경하지 않고 임시 담당자 권한을 회수했다. 사용자의 재개 요청 전에는 카메라 검증이나 이를 위한 일정 변경을 진행하지 않는다.

새 Supabase 프로젝트에서의 관리형 서비스 복구는 별도 미완료 항목이다. 사용자 보류 범위를 자동으로 확대하지 않으며, 별도의 빈 프로젝트와 연결 설정이 필요한 의존 작업으로 기록한다.

## 바로 다음에 권장하는 묶음

**1번 실제 회원 통합 검증과2번 실기기 알림을 함께 진행**한다. 이미 구현된 화면을 실제 행사 흐름으로 연결해야 수정할 결함과 추가 구현이 필요한 부분을 구분할 수 있다.

1. 서로 다른 테스트 계정으로 주최자·참가자 역할을 분리한다. Google/Kakao 로그인 성공만으로 서로 다른 회원임을 가정하지 않는다.
2. 무료 테스트 모임을 만들고 사진·영상·질문을 넣는다. 실제 업로드→압축 워커→본문 재생·영상 탐색과 타인 파일 접근 거부를 확인한다.
3. 신청·담당자 승인·공지방 참가와 공지 발송을 진행한다. 댓글 알림과 행사 공지 알림을 각각 실제 이벤트로 확인한다.
4. QR 출석·취소·행사 완료·회고·경력 수락·검색을 확인하고, 결과와 필요한 수정을 같은 검증 기록으로 남긴다.
5. iPhone을 확보하면 설치/알림·카메라·지도 경로를 실제 기기에서 확인한다. Chrome의 모바일 화면 검사를 실물 iPhone 검증으로 기록하지 않는다.

실제 회원 계정 로그인·권한 승인·카메라/푸시 확인에는 사용자 협조가 필요하다. 모임/미디어/역할의 검증 데이터와 결과를 구분해 관리한다.

## 후속 의존 조건

- iPhone 검증: 사용할 실기기와 사용자 동작 필요.
- 정식 주소: 도메인 확보와 DNS/허용 주소 설정 필요. 기존 사이트의 도메인은 Sliper 운영의 필수 정보가 아니다.
- 외부 결제: 사용할 업체와 테스트/운영 연결 설정 필요. 현재 무료 번개·담당자 승인 흐름을 활용할 수 있다.
- 광고: 실제 광고 단위와 사이트 승인 필요. 게시자 ID 확보만으로 게재 완료로 표시하지 않는다.
- 새 Supabase 복구: 소스와 분리된 빈 프로젝트·백업 전용 설정이 필요. 현재 운영 프로젝트를 복원 대상으로 사용하지 않는다.
- 정기 백업·별도 보관처: 사용자 재개 요청 전까지 보류한다.
