# 가입 기본정보와 행사 참가 질문

## 회원의 기본정보 등록

현재 `/signup`은 **이미 로그인한 회원이 기본정보를 완성하는 화면**이다. 카카오·구글 OAuth와 정식 신규 계정 발급은 후속 연동 단계이며, 개발 환경에서는 기존 테스트 계정으로 로그인한다. 비회원이 `/signup`을 열면 먼저 로그인하도록 안내한다.

1. `/login`에서 로그인한다. 기본정보가 없는 테스트 계정은 `/signup`으로 이동한다.
2. **닉네임(2~24자), 휴대폰 번호, 내 계정에 정보 저장 동의**를 입력한다.
3. 활동 지역·관심 콘텐츠·연령대·성별은 선택적으로 입력한다.
4. 저장하면 마이페이지 또는 원래 신청하려던 행사 화면으로 돌아간다.

휴대폰 번호는 한국 휴대폰 번호 형식을 검사하고 공백·하이픈 등을 정리해 저장한다. **문자 인증이나 번호 소유 확인은 아직 연결하지 않았다.** 입력한 번호를 인증된 번호로 표시하지 않으며, 현재 기본정보 완료는 본인인증 완료를 의미하지 않는다. 연령대·성별도 자기 기입 정보다.

마이페이지에서 연락처와 기본정보를 수정하거나 `/signup`에서 다시 확인할 수 있다. 번호가 바뀌면 이전 번호의 인증 상태는 해제된다. 연락처·연령대·성별은 공개 플레이어 프로필에 포함하지 않는다.

## 행사 담당자가 질문 만들기

모집글의 `/management/events/{postId}`에서 **행사 설정 → 참가자에게 물어볼 질문**을 연다. 모집글 등록자가 질문을 편집하고 행사 설정을 저장한다.

| 설정           | 제공하는 방식                  |
| -------------- | ------------------------------ |
| 질문 수        | 최대 10개                      |
| 답변 방식      | 직접 입력 또는 하나 선택       |
| 필수 여부      | 질문마다 필수·선택 설정        |
| 질문 내용      | 최대 160자                     |
| 직접 입력 답변 | 최대 1,000자                   |
| 선택지         | 2~8개, 각 80자 이내, 중복 금지 |

**질문 추가**로 새 질문을 만들고, 질문 내용과 답변 방식을 선택한다. 선택형 질문은 선택지를 추가·삭제할 수 있다. 닉네임·연락처는 회원정보에서 전달되므로 같은 항목을 질문으로 다시 요구할 필요가 없다.

관리 대시보드의 **참가 현황 → 질문 답변 · 요청사항**을 펼치면 해당 신청 당시의 질문, 답변, 요청사항을 확인할 수 있다. 참가자의 답변이 아직 제출되지 않은 외부 확인 요청은 **답변 대기**로 표시하며 승인 버튼을 사용할 수 없다.

## 회원이 참가하기

`/events/{postId}`에서 등록된 닉네임과 마스킹된 연락처를 확인하고 행사 질문에 답변한다. 참가 신청 화면에는 닉네임·연락처를 매번 적는 입력란이 없다. 기본정보가 없으면 **기본정보 등록하기**로 이동해 한 번 저장한다.

신청서에는 다음 항목을 제출한다.

- 담당자가 준비한 질문 답변
- 참가 요청사항(선택)
- 해당 행사 담당자에게 닉네임·연락처·답변·요청사항을 제공하는 동의
- 일정이 정해진 유료 행사라면 한국 날짜 기준 환불 정책 확인

서버가 인증된 회원의 프로필에서 닉네임과 연락처를 읽어 **신청 당시 값으로 복사**한다. 클라이언트가 다른 참가자의 이름이나 연락처를 요청 본문에 넣어 대체할 수 없다. 이후 내 프로필을 수정해도 이미 제출된 행사 신청 정보가 자동으로 바뀌지 않는다.

질문에는 버전 검사를 적용한다. 회원이 신청서를 작성하는 사이 담당자가 질문을 바꾸면 오래된 질문으로 신청을 확정하지 않고 최신 질문을 불러와 다시 확인하도록 안내한다. 이미 제출된 신청의 질문·답변은 원래 내용으로 보관한다.

무료 행사는 신청 완료 후 바로 참가를 확정한다. Sliper 내부 유료 신청은 기존 결제 대기·외부 플랫폼 결제 확인 흐름을 유지한다. 개인정보와 답변은 **신청한 본인과 해당 행사의 등록자·지정 담당자**만 확인할 수 있으며, 일반 참가자나 공개 글 목록에는 표시하지 않는다. 선택적으로 입력한 연령대·성별 전체를 참가 신청서에 복사하지 않는다.

## 외부 플랫폼에서 신청한 행사

외부 신청 링크가 있는 모집글은 해당 플랫폼에서 먼저 신청·결제한다. Sliper의 참가 확인 요청은 외부 신청 번호와 Sliper 회원을 연결하고 행사 공지방에 참여하기 위한 절차다. Sliper에서 동일한 참가 신청이나 결제를 다시 받지 않는다.

외부 신청·결제를 완료한 뒤 **외부 신청 · 결제를 완료했어요**를 눌러 신청 번호, 질문 답변, 요청사항과 정보 제공 동의를 제출한다. 이미 결제 연동 알림으로 신청 번호가 연결된 경우 그 번호를 다시 입력하지 않고 **참가 질문에 답변하기**를 이용한다.

질문이 있는 행사에서 결제 확인 알림이 먼저 도착하면 답변 제출 전에는 `pending_approval` 상태로 남기며 공지방 초대를 보류한다. 질문 답변과 동의를 제출한 뒤에는 다음과 같이 처리한다.

- **수동 승인 행사:** 담당자가 외부 플랫폼의 신청 번호·신청자·결제 내역과 답변을 확인한 후 승인한다.
- **자동 승인 행사:** 검증된 결제 연동 내역, 행사 정원과 승인 조건을 만족하면 자동으로 참가를 확정한다.

필수 질문을 비운 채 신청서를 제출할 수 없다. 질문이 있는 행사는 외부 신청 번호나 결제 확인 알림만으로 공지방을 열지 않고 답변 제출 절차를 먼저 마친다. 정원이나 결제 내역에 확인이 필요한 경우에는 담당자 확인 상태를 유지한다. 실제 결제·환불·정산은 계속 외부 플랫폼에서 진행한다.

## 마이페이지 알림 설정

마이페이지의 **내 알림 설정**을 펼치면 왼쪽에 정렬된 알림 종류 설명과 각 항목의 **ON/OFF** 스위치를 볼 수 있다. 공지방·댓글 및 답글·참가 확정/환불 완료 알림을 계정별로 선택한다. 기기 연결 상태는 알림 종류 설정과 별도로 표시하며, 새 기기를 사용하면 그 기기도 연결해야 한다.

환경에 따라 알림 허용, iOS 홈 화면 추가 또는 권한 복구 방법을 안내한다. **HTTP Wi-Fi 로컬 주소에서는 웹푸시를 연결할 수 없다.** 같은 Wi-Fi에서 로그인·기본정보·참가 신청 등 일반 기능을 확인할 수 있지만, 실제 휴대폰 푸시 수신에는 HTTPS와 지원 환경이 필요하다. 푸시·문자·OAuth의 실제 서비스 연동 및 기기 수신을 이번 기본정보·신청서 기능으로 검증했다고 간주하지 않는다.

## 데이터와 코드

회원 기본정보는 PostgreSQL `profiles`, 행사 질문은 `event_settings.questions`, 신청 당시 정보·답변·버전은 `event_applications`에 보관한다. 마이그레이션 `0021`과 `0022`를 적용하며 기존 신청의 완료 상태와 참가 내역을 보존한다.

- `src/domain/profile.ts`, `src/domain/validation.ts`: 기본정보 형식·신청 가능 상태 검증
- `src/server/profile-service.ts`: 본인의 기본정보 조회·수정·가입 정보 완료 처리
- `src/domain/application-questions.ts`: 질문·선택지·답변 검증과 제출 당시 내용 보존
- `src/server/participation-service.ts`, `src/server/event-management-service.ts`: 프로필에서 참가 정보 복사, 질문 버전 검사, 외부 승인과 공지방 권한
- `src/components/profile-onboarding.tsx`: 기본정보 입력 화면
- `src/components/application-question-fields.tsx`, `src/components/event-question-editor.tsx`: 참가 질문 답변·관리 편집
- `src/components/push-settings.tsx`: 접는 알림 설정과 기기 연결

관련 문서: [로컬 테스트 계정](TEST_ACCOUNT.md), [참가 승인·결제·공지방](PARTICIPATION.md), [웹푸시 설정](WEB_PUSH.md).

## 최근 검증

2026-10-02: 전체 회귀 테스트 240개, 새 신청서 HTTP 통합 1개, 로그인 HTTP 2개, 기존 커뮤니티 HTTP 9개·자료/플레이어 HTTP 2개·번개 HTTP 1개·푸시 HTTP 6개, 실제 PostgreSQL 마지막 좌석 경합 1개를 확인했다. 테스트용 프로필 정보는 검사 후 복원하고 임시 글만 삭제한다. 공개 페이지의 개인정보 비노출, 신청 당시 질문·연락처의 보존, 외부 결제 후 답변 누락 시 방 초대 차단을 포함한다. 휴대폰 직접 조작·실제 SMS 발송·잠금 화면 푸시 수신은 별도 검증이 필요하다.

추가 HTTP 검증은 개발 서버 실행 후 비밀번호를 현재 터미널 프로세스에만 전달해 실행한다. 실제 비밀번호를 소스·문서·`.env`에 기록하지 않는다.

```powershell
$env:SLIPER_TEST_PASSWORD = '<발급받은 테스트 비밀번호>'
npm run test:application-forms
Remove-Item Env:SLIPER_TEST_PASSWORD
```
