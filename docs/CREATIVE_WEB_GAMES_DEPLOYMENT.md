# 낙서톡·단서각 운영 반영 안내

2026-11-15 `20261115-creative-games-01`을 sliper.kr에 배포했다. 마이그레이션0082~0084, 새 웹·기존 영상/알림 워커, 그림 게이트웨이와 게임 전용 Redis를 반영했다. 실제 서비스 검증과 보존 범위는 [배포 결과](CREATIVE_GAMES_DEPLOYMENT_2026-11-15.md)를 참고한다.

## 구성과 저장 위치

- Next.js: 방·참가자·점수·단계·비공개 제출은 PostgreSQL `sliper` 스키마에 저장한다. 기존 Supabase 인증과 서명된 게스트 쿠키를 사용한다. IP는 참가자의 신원이 아니다.
- `game_assets`: 게임 미디어의 부모 방·진행 회차·소유자·상태·만료 정보. 개인 파일은 기존 비공개 Storage와 권한 검사 API로 제공한다. GET/HEAD/Range에도 같은 접근 검사를 적용한다.
- `game_runs`: 종료 결과를 방의 다음 게임과 분리해 저장한다. 당시 참가 연결 또는 호스트만 읽을 수 있다. 재시작해도 지난 결과 링크는 유지된다.
- Redis: 단계별 그리기 권한, 제한된 벡터 스트로크, Pub/Sub 전달을 담당한다. PostgreSQL의 점수·결과 원본을 대체하지 않는다. 임시 스트로크는 재연결 시 복원하며 저장 완료된 그림은 WebP로 보관한다.
- 기존 영상 워커: 새 게임의 소리·짧은 영상을 비동기로 압축한다. 기존 알림/정리 워커는 게임 종료 후 24시간이 지난 미디어와 결과를 정리한다. 사진은 브라우저 사전 압축과 서버 재검증·WebP 변환·메타데이터 제거를 거친다.
- 기본 문제: 서버 전용 정답 은행과 정적 사진 20개·자체 제작 합성 소리 10개. 라이선스는 `/games/credits`와 `CLUE_PACK_LICENSES_2026-11-14.md`에서 확인한다. 개인 자료에는 정적 공개 경로를 사용하지 않는다.

## 반영 순서

1. 운영 DB 백업과 복원 점검 상태를 확인한다. 기존 웹·미리보기·각 워커·정상 롤백 릴리스 경로와 여유 공간을 기록한다. 현재 링크만으로 실제 워커 사용 경로를 판단하지 않는다.
2. 새 릴리스를 별도 경로에 빌드하고 검사한다. 기존 게임 여섯 종류와 신규 게임 두 종류가 모두 포함되는지 확인한다. `npm run build`의 postbuild가 실제 standalone 산출물에서 환경 파일·로컬 작업 복사본을 제거하는지 확인한다. `next build`만 실행하고 postbuild를 생략한 폴더를 배포하지 않는다. 빌드에는 공개 설정만 사용하고 비밀 환경 파일을 릴리스에 복사하지 않는다.
3. 기존 마이그레이션 명령으로 `0082_creative_web_games`, `0083_game_media_cleanup`, `0084_creative_game_results`를 순서대로 적용한다. RLS를 켜고 anon/authenticated 직접 접근 권한을 제거하는 구문을 포함한다. 실제 서버용 DB 역할에 필요한 권한이 있는지 배포 DB 검사로 확인한다. 기존 행·점수·모집·결제 테이블을 삭제하거나 초기화하지 않는다.
4. 기존 비공개 Storage와 영상·알림 워커가 정상인지 확인한다. 새 코드가 포함된 워커 릴리스로 갱신해야 새 게임 자료의 인코딩·만료 정리가 동작한다. 삭제 정리는 기존 durable object-cleanup 큐를 통해 이루어진다.
5. `deploy/native/sliper-game-ink.service`를 검토하고 기존 환경 파일 경로와 실행 경로를 실제 서버 구성에 맞춘다. `current/worker`에 새 스크립트와 의존성 `tsx`, `ws`, `redis`가 포함되어야 한다. 스크립트는 127.0.0.1:13004에만 바인딩하며 기본 한도는 8방·128연결, 프레임 16KB, 사용자당 초당 12회다.
6. 기존 sliper.kr HTTPS 서버 블록 안에 `sliper-game-ink.nginx.conf`의 `/ws/games` 정확 일치 경로를 추가한다. Nginx 설정 검사 성공 후에만 재로드한다. 기존 다른 도메인·upstream은 변경하지 않는다. Redis와 13004번 포트를 외부 ACG에 개방하지 않는다.
7. Next.js·그림 게이트웨이에 같은 `APP_ORIGIN=https://sliper.kr`과 기존 `VISITOR_HASH_SECRET`을 제공한다. Redis URL은 `GAME_REDIS_URL` → `TOWN_REDIS_URL` → `REDIS_URL` 순서로 선택된다. 이번 운영 구성은 기존 타운 ACL이 Pub/Sub을 허용하지 않아 별도 게임 Redis를 사용한다. `sliper-game-redis.service`와 `game-redis.conf`를 먼저 반영하고, 웹의 `sliper-game-web.conf`와 그림 게이트웨이 양쪽에 `/etc/sliper/game-ink.env`를 연결한다. GAME_REDIS_URL은 루프백13005이며 Redis 저장은 끄고 메모리는128MB로 제한한다. 키·채널은 `sliper:game-ink:*`에 한정한다. 기존 타운 Redis 설정과 프로세스는 변경하지 않았다. 공개 WS URL은 기본 `wss://sliper.kr/ws/games`로 계산하므로 일반적으로 `GAME_INK_PUBLIC_URL`은 비워둔다. 로컬 전용 ws 주소를 운영에 복사하지 않는다.
8. 새 웹·워커·그림 게이트웨이의 정상 응답을 확인한 뒤 트래픽을 전환한다. 헬스 체크, 기존 사이트, 로그인·공지방·기존 게임·미디어를 함께 점검한다.

## 실제 서비스에서 확인할 항목

- Android/iPhone 두 대 이상으로 QR/링크 입장, 호스트 참가, 준비 유지, 모바일 그리기와 다른 휴대폰의 실시간 수신.
- 비공개 첫 그림은 지정된 해석자에게만 보이고, 라이브 그림은 해당 단계 참가자에게만 보이는지 확인.
- 새로고침·통신 단절 후 재연결, 시간 종료 시 자동 그림 저장, 유사 답 판정·최초 정답 순서와 점수.
- 실제 Naver Maps SDK의 사진 위치 선택·결과 마커·연결선. 격리 브라우저 검사는 SDK 대체 구현을 사용하지만, 이번 배포 후 추가 검사는 실제 sliper.kr에서 Naver SDK·지도 클릭·결과 마커를 확인했다. 물리적 Android/iPhone 검사는 별도로 남아 있다.
- 소리/영상 업로드가 처리 중→준비 완료로 바뀌고, 출제자와 사진 제출자가 자기 문제 채점에서 제외되는지 확인.
- 비참가자·이전 단계·다른 방의 미디어와 결과 직접 URL이 거부되는지 확인. 결과 만료 24시간 후 API 차단과 정리 큐를 확인.
- 그리기 연결 수·Redis 메모리·워커 지연·DB 연결 수를 관찰한다. 로컬 부하 테스트 결과를 Ncloud의 실제 수용량으로 간주하지 않는다.

## 롤백과 리소스 보존

웹과 워커는 실제 참조 경로를 확인한 정상 릴리스로 되돌릴 수 있다. 새 마이그레이션은 추가형이므로 장애 시 새 테이블을 즉시 삭제하지 않는다. 진행 중인 게임과 결과를 보존한 상태로 코드 롤백의 호환성을 먼저 점검한다. 사용 중 릴리스·워커·직전 정상본은 보존하고, 이전 릴리스 정리는 별도 목록 보고·승인 절차를 유지한다.
