# 글 상세·통합 검색·크루

2026-10-05에 추가한 기능과 실제 저장 경계다. 실서비스 연동 준비는 [별도 문서](PRODUCTION_INTEGRATION.md)에 정리했다.

## 글 주소와 공유

글 목록·주목받는 콘텐츠·인기 이야기의 제목은 /posts/글ID 링크다. 일반 클릭은 기존 모달을 열고 Ctrl/Cmd 클릭·중클릭은 새 탭에서 상세 페이지를 연다. 모달과 페이지는 동일한 본문·댓글·투표·반응·수정/삭제·신고 컴포넌트를 사용한다.

공유 버튼은 기기 공유, 링크 복사, 수동 복사 안내 순으로 제공한다. 공유 취소 시 자동 복사하지 않는다. 조회수는 SSR에서 증가시키지 않으며 실제 본문을 연 클라이언트가 기존 방문자 하루 1회 규칙으로 집계한다. 상세 페이지에서는 메인 피드와 추천 polling을 시작하지 않는다.

삭제·운영 숨김·방문자가 차단한 작성자 글은 상세 데이터와 방문자의 메타데이터에서 제외한다. 공유 미리보기는 공개 제목·카테고리·종류·작성 시각만 사용하고 본문·연락처·익명 작성자 ID·첨부 사진을 조회하지 않는다. 제목의 일반 휴대폰 번호·이메일·URL도 공유용 제목에서 치환한다. 임의의 모든 개인정보 표기를 탐지하는 기능은 아니다.

canonical은 검증한 APP_ORIGIN을 사용하고 요청 Host/forwarded 값을 신뢰하지 않는다. /posts/글ID/opengraph-image는 로컬 한글 폰트로 1200×630 이미지를 생성하고 지원하지 않는 글자는 □로 표시한다. 외부 폰트/이모지 서버를 호출하지 않는다. 공개 준비 전이므로 noindex 정책을 유지한다.

## 통합 검색

헤더의 통합 검색 및 메인 검색창 안의 통합 버튼으로 /search에 이동한다. 기존 메인 게시판 검색·취향 이벤트 필터도 유지한다.

| 조건     | 동작                                            |
| -------- | ----------------------------------------------- |
| q        | 최대 100자, 한 글자 한국어 가능, 빈 검색은 안내 |
| type     | all / story / recruitment / rulebook / template |
| category | 기존 카테고리                                   |
| page     | 1~50, 한 페이지 20개                            |

이야기 범위에는 후기·투표도 포함한다. 글은 공개 제목·검색용 본문·태그, 자료는 공개 제목·소개·태그만 검색한다. 유료 시나리오·규칙·준비물·진행자 멘트, 신청 연락처/답변은 검색하지 않는다. 상태·숨김·작성자 차단을 필터하고 인증 ID를 반환하지 않는다. SQL %/_는 문자로 검색하며 제어문자·잘못된 Unicode·중복/알 수 없는 API 쿼리 키는 거부한다.

검색 수와 결과는 repeatable-read 읽기 트랜잭션으로 집계하고 서버 응답은 private,no-store다. 0034는 immutable search_tags 함수와 pg_trgm GIN 인덱스를 준비한다. 확장이 없는 테스트 엔진에서는 ILIKE 기능을 유지한다. 한두 글자 검색은 인덱스 효과가 제한적일 수 있다. 실제 부하·데이터 크기별 성능 검증은 아직 하지 않았으며 Redis나 외부 검색 엔진을 사용하지 않는다.

## 지속적 크루

기존 '함께 만드는 크루' 게시판은 협력자를 찾는 글 공간이다. 크루는 멤버를 모집하고 지속적으로 활동하는 팀이다. 탐색 메뉴는 **플레이어·크루**로 통합하고, `/players`에서 플레이어 탭과 크루 탭을 선택한다. 크루 목록은 `/players?tab=crews`이며 기존 `/crews` 목록 주소도 이곳으로 이동한다. 크루 생성 `/crews/new`, 팀 상세 `/crews/{id}`, 개별 플레이어 `/players/{publicId}`와 기존 API는 유지한다. 개인 전적과 팀 활동 데이터는 각자의 공개 설정과 권한을 그대로 적용한다.

크루 이름·소개·주제·지역·최대 2~100명·모집 여부를 설정한다. 생성 시 닉네임/프로필 아이콘 공개를 안내하고, 가입에는 참여 메시지와 공개 동의가 필요하다. 공개 명단에는 전화번호·인증 ID를 제공하지 않는다. 프로필 사진의 공지방 전용 인가는 유지하므로 크루 명단은 기존 프로필 아이콘을 표시한다.

- 리더/운영진: 가입 승인·반려, 정보 수정, 공지, 실제 담당하는 행사 연결.
- 리더: 운영진 지정/회수, 멤버 제외, 기존 멤버에게 리더 양도, 보관.
- 멤버: 자신의 신청 철회·탈퇴. 리더는 먼저 양도하거나 보관한다.
- 보관: 이력은 유지하고 변경·새 가입을 막는다. 내 크루에서 보관된 팀도 확인할 수 있다.
- 가입 메시지: 본인의 신청 또는 운영진 대기열에서만 제공하며 공개 활동에 기록하지 않는다.

정원과 역할 변경은 크루 행 잠금으로 직렬화하고 계정 탈퇴와 프로필 잠금 순서를 맞춘다. 활성 크루 리더는 계정 탈퇴 전에 양도/보관해야 한다. 탈퇴 시 멤버십·신청 메시지를 정리하고 활동 이력은 남긴다. 수정은 마이크로초 revision으로 오래된 정보 덮어쓰기를 차단한다. 생성·가입·공지 등의 요청 제한은 PostgreSQL에서 집계한다.

행사 연결은 크루 운영진이 실제 주최하거나 공지방 관리자로 지정된 모집글만 가능하다. 기존 행사 신청·결제·공지방 흐름을 그대로 사용한다. 크루 공지는 공개 활동 기록이며 참가자 전용 행사 공지와 별도다. 크루 공지 푸시 구독은 이번 범위에 포함하지 않는다.

## 검증된 기여와 활동점수

크루 멤버이면서 실제 행사 주최자/관리자인 담당자가 다른 멤버의 MC·진행 스태프·기획 파트너·촬영/편집·디자인·공간/장비 기여를 확인한다.

연결된 행사, 종료 시각 경과, 취소되지 않은 실제 행사, 대상 멤버의 참가 완료(attended)와 일치하는 QR 입장 기록이 필요하다. 예시 콘텐츠·미래 행사·QR 없는 전적은 인정하지 않는다. 참가/행사/회원 조합을 복합 FK로 묶고 자기 확인은 서버·DB에서 차단한다. QR은 현장 담당자의 확인 기록이며 기여 품질 자동 평가나 외부 자격 인증은 아니다.

인증 기록은 크루·행사·멤버당 하나, 점수는 회원·행사당 5점으로 여러 크루에서 같은 행사를 인증해도 한 번만 지급한다. 한국 날짜 기준 하루 최대 10점이며 기존 활동점수 이력과 연동한다.

## 저장과 API

6개 RLS 테이블: crews, crew_members, crew_join_requests, crew_events, crew_activity, crew_contributions. anon/authenticated 직접 접근을 막고 서버 서비스에서 공개 DTO와 운영진 전용 대기열을 분리한다. crew 신고/숨김은 기존 /admin 검토 큐에 연결된다.

API는 /api/crews 이하에서 list/detail/create/update, join/withdraw, requests/decision, members/role/remove, transfer/leave/archive, announcements, events/available/link/unlink, contributions/verify를 처리한다. GET/HEAD는 읽기, POST/PATCH/DELETE는 동일 출처 검사 후 쓰기다. 목록·활동·기여·신청은 20개 페이지, 명단은 최대 100명, 연결 행사는 최대 20개로 제한한다.

```powershell
npm run check
npm run test:search-api
npm run test:crew-api
npm run test:crew-concurrency
npm run test:rich-post-api
npm run build
```

HTTP 검사는 전용 로컬 DB/서버와 기존 테스트 계정만 사용하고 임시 자료를 정리한다. 실제 공급자 로그인·거래·원격 저장소·브라우저 직접 클릭·휴대폰 시각 검증은 별도다.
