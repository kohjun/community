# 함께 만드는 이벤트 맵

`/map`은 유저가 공개 모임 장소를 추가하고 기존 모집·번개 이벤트를 함께 탐색하는 공동 지도다. Sliper의 파랑·흰색·회색을 유지하며 PC에는 상단 검색·필터와 왼쪽 목록/상세, 오른쪽 고정 높이 지도를 제공한다. 모바일에는 지도·목록 전환과 선택한 장소의 상세 카드를 제공하며, 목록은 페이지 스크롤로 읽는다. 실제 장소 정보는 PostgreSQL에 저장하고 NAVER Maps SDK는 지도와 주소 변환을 담당한다.

## NAVER Maps 연결

1. NAVER Cloud 콘솔의 **Application Services → Maps → Application**에서 발급한 애플리케이션을 선택한다. **Dynamic Map(Web Dynamic Map)**과 **Geocoding**을 활성화한다.
2. **Web 서비스 URL**에 사용하는 호스트를 등록한다. 로컬 개발은 `http://localhost`, `http://127.0.0.1`, 모바일 Wi-Fi 테스트는 개발 PC의 현재 주소(예: `http://192.168.123.104`)다. 포트 `:3000`과 `/map` 같은 경로는 제외한다. 운영에서는 실제 서비스 도메인도 등록한다. Wi-Fi 주소가 바뀌면 콘솔에도 새 주소를 등록해야 한다.
3. `C:\Sliper\.env`의 아래 항목에 발급한 **Key ID(Client ID)**를 넣는다.

```env
NEXT_PUBLIC_NAVER_MAP_KEY_ID=실제_Key_ID
```

4. 개발 서버를 다시 시작한다. Wi-Fi 접속을 사용한다면 기존과 같이 현재 PC 주소를 `SLIPER_LAN_HOST`로 지정한다.

```powershell
$env:SLIPER_LAN_HOST='192.168.123.104'
npm run dev:lan
```

운영에서는 배포 환경변수에 같은 항목을 설정한 후 새로 빌드/배포한다. 이 식별자는 브라우저 SDK URL에 전달되며 Client Secret은 사용하거나 노출하지 않는다. 콘솔의 허용 호스트가 실제 접속 주소와 일치해야 한다.

SDK는 `https://oapi.map.naver.com/openapi/v3/maps.js?ncpKeyId=...&submodules=geocoder`로 로드한다. 주소 찾기는 도로명/지번 주소를 좌표로 변환하는 Geocoding이다. 모든 상호의 포털 검색 API를 제공하는 기능은 아니다. 검색 결과 중 주소를 선택하거나 지도에서 직접 위치를 고른다.

지도 키가 없거나 연결/인증에 실패하면 지도 상태 안내와 장소 목록을 제공한다. 가상 지도 타일을 표시하지 않는다. 키 미설정 상태에서도 좌표 직접 입력으로 장소 등록을 사용할 수 있다. 현재 위치는 버튼을 눌렀을 때만 요청하며 브라우저의 보안 연결/권한 정책을 따른다.

공식 참고: [Application 설정](https://guide.ncloud-docs.com/docs/application-maps-app-vpc), [서비스 URL/Geocoding 문제 해결](https://guide.ncloud-docs.com/docs/maps-troubleshoot), [주소와 좌표 검색](https://navermaps.github.io/maps.js.ncp/docs/tutorial-Geocoder-Geocoding.html).

## 사용 흐름

- 상단 **이벤트 맵** 또는 홈의 지도 바로가기를 누른다.
- 전체/추천 장소/모집·번개와 9개 취향 카테고리, 무료 필터, 장소명·주소 검색으로 탐색한다. 지도를 움직이면 표시 범위가 갱신된다.
- 장소를 선택하면 주소·설명·태그·공간 유형·비용 안내·수용 인원·공개 등록자와 추천 수를 확인할 수 있다. 모바일에서는 선택한 상세로 이동하고, 목록으로 돌아가면 목록 시작 위치를 보여준다. PC에서도 목록/상세 전환 시 키보드 포커스를 연결한다. 관련 웹사이트와 NAVER 지도로 연결한다.
- 로그인 후 이름·주소·지도 위치·대표 취향·실내/야외·무료 여부·소개를 입력해 등록한다. 비용 안내·인원·태그·관련 링크는 선택 사항이다. 수정과 삭제는 등록자만 가능하며 삭제 확인 창을 제공한다. 모바일 등록 폼은 바텀 시트로 열리고 좁은 화면에서는 항목을 한 열로 표시한다.
- **여기서 번개 열기**는 등록된 장소를 서버에서 확인한 후 이름·주소·좌표·카테고리를 번개 작성창에 채운다. 주최자는 자신의 일정과 활동 내용을 입력한다. 기존 이벤트 장소는 스냅샷이므로 이후 공유 장소 수정이 이미 개설한 행사를 바꾸지 않는다.
- 모집·번개 마커는 기존 `/events/{id}` 신청 흐름으로 연결된다. 끝난 행사와 예시용 샘플은 공용 이벤트 마커에서 제외한다. 모집 가능 여부는 기존 신청 기준과 동일하게 정원·확정 참가자·유효한 결제 예약·시작/종료 시각을 반영한다. 진행 중인 행사는 지도에 유지하되 모집 종료로 표시한다. 공유 장소는 실제 예약이나 대관 확정을 의미하지 않는다.

## 저장과 데이터 흐름

```text
/map RSC → eventMapService.list → PostgreSQL
              ↓ 공개 DTO
검색/지도 이동 → /api/event-map → 범위·필터 조회 → 목록/마커 갱신
장소 등록·수정·삭제·추천 → 같은 Origin 검사 → 현재 인증 회원
                         → 입력 검증 → 트랜잭션/권한 → DB → 공개 DTO
주소 검색 → NAVER Geocoding → 선택한 공개 장소의 주소/좌표
장소에서 번개 개설 → /lightning?venue={id}&open=1 → 공개 장소 조회
                         → 번개 초안 → 기존 /api/lightning
```

마이그레이션 `0024_community_venues.sql`이 비공개 `sliper` 스키마에 다음 두 테이블을 추가한다. 전체 Sliper 테이블은 33개이며 RLS를 활성화하고 공개 Data API 역할의 직접 접근을 차단한다.

| 테이블                  | 저장 내용                                                                                                       |
| ----------------------- | --------------------------------------------------------------------------------------------------------------- |
| `community_venues`      | 등록자 참조, 이름·주소·소개, 공개 좌표, 카테고리·공간 유형, 이용 정보·태그·링크, 정수 수정 버전, 게시/삭제 상태 |
| `venue_recommendations` | 장소와 추천 회원의 고유한 쌍, 생성 시각                                                                         |

공개 응답에는 등록자의 nickname/publicId/avatar와 장소 정보만 포함한다. 인증 UUID·연락처·행사 신청 답변은 노출하지 않는다. 수정/삭제는 DB 행 잠금과 등록자 확인 후 버전을 비교하며 오래된 요청은 409로 반환한다. 추천은 `liked` 상태를 명시해 중복 요청으로 수가 늘지 않는다. 회원 탈퇴 시 추천은 제거한다. 장소 원장은 보존하지만 탈퇴하거나 현재 이용이 제한된 등록자의 장소는 공개 탐색과 행사 연결에서 제외한다.

방문자의 현재 위치는 프로필이나 장소 DB에 저장하지 않는다. 지도 범위가 조회 API에 전달되며, 등록자가 제출한 행사장 좌표만 공용 장소 정보로 저장한다. NAVER Maps 인증 정보와 지도 사용량은 NAVER Cloud 설정을 따른다.

조회는 최대 200개 핀과 범위/필터의 정확한 전체 수를 반환한다. 결과가 많으면 확대/필터 안내를 표시한다. 장소와 이벤트 모두 있을 때 한 종류만 전체 슬롯을 차지하지 않도록 분배한다. 좌표·카테고리·등록자·추천 인덱스, 읽기 전용 repeatable-read 조회, 250ms 지도 범위 중복 억제와 300ms 클라이언트 조회 지연, 이전 요청 취소를 사용한다. Redis·PostGIS·WebSocket은 추가하지 않았다. 장소 변경 후와 지도 범위 변경 시 다시 조회하며 별도의 실시간 방송 기능은 없다. 등록은 한 회원당 최근 24시간 최대 50개이며 삭제해도 제한이 초기화되지 않는다.

## 검증

```powershell
npm run check
npm run test:event-map-api
npm run build
```

단위·PostgreSQL 서비스 검사는 입력/좌표·범위·카테고리·무료 필터·종료 행사 제외·정확한 수·200핀 한도·공개 DTO·소유권·수정 충돌·추천 중복·RLS·탈퇴와 SDK 생명주기/마커 문자열 처리를 검증한다. HTTP 검사는 로컬 개발 환경에서만 실행하고 검증용 장소의 CRUD, guest 401, 타회원/다른 Origin 403, 이전 버전 409, 삭제 후 404를 확인한 뒤 자신이 만든 검증 장소만 정리한다. 실제 NAVER 인증·타일 표시·주소 검색 및 모바일 지도 터치는 유효한 키와 허용 호스트 설정 후 브라우저에서 확인해야 한다.

## 장소별 완료 행사·운영 팁

일반 모집·번개·템플릿 행사에서 등록 장소를 명시적으로 선택하면 선택 당시의 장소 정보가 보존된다. 완료 회고를 발행하면 장소의 행사 기록에서 실제 사용 사례와 별도 운영 팁을 찾아볼 수 있다. 장소별 이력은 회원 전용이며 기존 좌표로 과거 연결을 추정하지 않는다. [저장·권한·API·검증](PLACE_HISTORY_AND_EVENT_VENUES.md)을 참고한다.
