# Sliper 코드 리뷰 · 2026-10-01

범위: `C:\Sliper`의 메인 커뮤니티, 글/댓글 CRUD, 모집, 투표, 마이페이지, 알림, 업로드, DB 무결성 및 의존성. 기존 화면·데이터 계약을 유지하면서 발견한 오류를 수정하고 공통 코드를 분리했다. 인증 연동은 기존 요청대로 후속 단계로 유지한다.

## 발견하고 수정한 문제

| 우선순위 | 재현 조건과 영향 | 수정 및 근거 |
| --- | --- | --- |
| P1 | 같은 작성자가 다른 글을 동시에 등록하면 외래키 `KEY SHARE`와 활동점수 `FOR UPDATE` 잠금의 교착으로 한 요청이 실패 | `server/activity.ts`를 `FOR NO KEY UPDATE`로 변경. 실제 PostgreSQL 두 연결에서 두 트랜잭션을 외래키 삽입 직후 동기화한 검사: 수정 전 1개만 성공, 수정 후 2개 성공·총 10P |
| P2 | 목록을 불러오는 도중 좋아요·투표·수정·삭제하면 늦은 응답이 최신 상태를 덮어쓰거나 삭제한 글이 돌아옴 | `lib/use-community.ts`와 `community-state.ts`에서 변경 버전·삭제 기록으로 응답을 합성. 활성 북마크·주제 필터 조건 재검사. 삭제 시 인기 영역에서도 제거 |
| P2 | 필터를 바꾼 직후 더 보기를 누르면 이전 목록 커서가 새 필터 요청에 섞임 | 응답이 적용된 필터 키를 추적하고 로딩 중/이전 필터 커서의 페이지 요청 차단 |
| P2 | 마이페이지 방문 적립 응답이 프로필 저장보다 늦게 도착하면 옛 프로필로 돌아감 | `lib/request-sequence.ts`로 가장 최근 요청만 적용, 언마운트 후 응답 무시. 동기 저장 잠금으로 중복 제출 차단 |
| P2 | 자동 전환 영역에 키보드 포커스가 남은 상태로 마우스가 나가면 자동 전환 재개 | 공통 `use-carousel-motion.ts`에서 hover와 focus를 분리하고 탭 가시성·동작 줄이기·수동 일시정지 함께 검사 |
| P2 | 마지막 카드의 스크롤 위치가 카드 간격의 정수 배가 아니면 자동 전환이 끝에서 멈춤 | `lib/carousel.ts`에서 실제 최대 스크롤 위치를 마지막 페이지로 처리하고 다음 이동은 처음으로 순환 |
| P2 | 손상된 multipart 업로드가 사용자 입력 오류 대신 HTTP 500을 반환 | `server/media.ts`에서 파싱 실패를 입력 오류 400으로 변환. 실제 HTTP 회귀 검사 통과 |
| P2 | HEAD 요청을 쓰기로 분류해 공개 목록에서 출처 검사 실패 | API 핸들러에서 HEAD를 GET 의미로 처리. Origin 없는 HEAD 200·빈 본문 확인 |
| P2 | 개발 의존성의 오래된 esbuild로 moderate 보안 경고 4개 발생 | core-utils 하위 esbuild만 Drizzle과 같은 0.25.12로 고정. 깨끗한 설치·변환기·Drizzle 생성 검사·audit로 확인 |

잠금 호환성은 [PostgreSQL 공식 문서](https://www.postgresql.org/docs/18/explicit-locking.html)의 행 잠금 설명을 확인했다. esbuild 경고는 [보안 권고 GHSA-67mh-4wv8-2f99](https://github.com/advisories/GHSA-67mh-4wv8-2f99)에 해당한다.

## 리팩토링

- 서버 모듈 분리: 게시글 조회/집계 `post-reader.ts`, 본인 정보 `profile-service.ts`, 알림 `notification-service.ts`.
- 게시글별 이미지·투표 집계를 Map으로 구성해 DTO 변환 중 반복 탐색 제거. 날짜 포맷터 공유.
- 클라이언트 요청 `api-client.ts` 공통화: JSON/FormData, 취소·시간 제한, 잘못된 응답과 네트워크 실패의 한국어 메시지.
- Server Action 호출을 React transition 안에서 시작하도록 정리.
- 활동점수·일별 한도·안내 문구 정책을 `domain/activity.ts`로 통합. 일별 집계는 날짜 범위 조건 사용.
- Prettier와 미사용 변수/인자 검사를 추가하고 `npm run check`에 포맷 검사를 포함.
- DB 테이블·마이그레이션·기존 게시글은 변경하지 않음. 통합 검사의 임시 글은 소프트 삭제하고 프로필 편집 값은 원복.

## 검증 결과

- `npm run check`: 포맷·TypeScript·회귀/도메인/DB/서비스 62개·Drizzle 메타데이터 통과.
- `npm run test:api`: 실제 PostgreSQL 동시성 및 HTTP 통합 4개 통과.
- `npm run db:generate`: 스키마 변경 없음, 추가 마이그레이션 없음.
- `npm ci`: 잠금 파일로 새 설치 성공.
- core-utils의 동기/비동기 TypeScript 변환: 통과.
- `npm audit`: 개발·운영 전체 알려진 취약점 0개 (점검 시점).
- `npm run build`: 성공. 메인·마이페이지·로그인 응답 200.
- `npm run start`: `canWrite=false`, 본인 정보·투표·글 등록 요청 401. 운영 환경에서 개발 작성자 비활성화 확인.
- 점검 후 개발 서버를 `http://127.0.0.1:3000`으로 재시작하고 개발 모드 쓰기 가능 상태 확인.

## 우선순위에 따른 추가 수정

사용자의 후속 요청에 따라 기존 수정 여부를 확인한 뒤 저장 정확성부터 보완했다. 아래 항목은 모두 코드에 반영했다.

| 순서 | 우선순위 | 문제 및 해결 | 검증 |
| --- | --- | --- | --- |
| 1 | P1 | 여러 탭에서 같은 글을 편집할 때 오래된 내용이 최신 글을 덮어씀. 수정 요청에 열어본 `expectedUpdatedAt`을 필수로 받고 행 잠금 안에서 비교, 불일치 시 409. 응답의 수정 시각은 마이크로초를 보존 | 실제 두 동시 PATCH 중 1개 200·1개 409, 최신 내용 유지. 버전 누락 400. 좋아요 이후에도 내용 버전이 같으면 저장 가능 |
| 2 | P2 | 점수 한도/방문 키는 현재 날짜인데 기록은 트랜잭션 시작 시각이라 자정·잠금 대기에서 날짜가 어긋남. 동일한 실제 적립 시각을 DB에서 캡처하고 명시적으로 저장 | 실제 PostgreSQL에서 오래된 트랜잭션 시작 시각으로 저장되던 실패를 재현한 뒤 수정 후 통과 |
| 3 | P2 | DB 세션에 서머타임이 있으면 날짜 시작에 interval 1 day를 더한 일별 한도 범위가 23/25시간이 될 수 있음. KST 다음 날짜를 별도로 변환해 양끝 계산 | 미국 시간대의 봄·가을 전환일과 연도 경계에서 24시간·UTC 15시 경계 확인 |
| 4 | P2 | 늦은 상세 응답이 요청 중 완료된 좋아요·댓글 수정·삭제를 덮어씀. 상세 응답에 요청 이후 변경 기록을 합성하고, 이전 추천 응답은 최신 목록을 덮어쓰지 못하게 차단 | 최신 반응·답글·부모 답글 수·삭제 상태 유지, 다른 글 댓글 제외, 페이지 커서 유지 및 삭제 글 무시 검사 |

최종 검사: `npm run check`의 회귀/도메인/DB/서비스 66개와 실제 DB·HTTP 통합 6개 모두 통과, 프로덕션 빌드 성공. 프로덕션의 인증 없는 PATCH 401·읽기 전용 목록과 페이지 200을 확인했고 개발 서버를 다시 실행했다. DB 스키마 변경이나 마이그레이션은 없다. 인증 연동은 기존 요청대로 후속 단계다. 수정 API의 필수 버전 계약은 [CRUD 문서](crud-and-local-db.md)에 기록했다.

## Chrome 모달 오류 후속 수정

서버의 실제 클릭 로그에서 조회수 POST 403을 확인했고 localhost 주소로 재현했다. Origin/Host가 일치하는 개발용 로컬 주소를 허용하고, 본문 조회와 방문 집계를 분리했다. 클릭 즉시 모달을 열며 로딩·실패·재시도를 표시하고 닫힌 모달의 진행 중 요청을 취소한다. 프로덕션 및 외부 주소 검사는 유지한다. 최신 검사 수는 일반 71개 + 실제 DB/HTTP 7개, 총 78개다. 자세한 경로와 결과는 [CRUD 문서](crud-and-local-db.md)를 참고한다.

## 검증 범위의 한계

브라우저 자동화는 이 환경의 접근 정책으로 수행하지 못했다. 화면의 시각적 회귀, 실제 키보드/터치 조작, 모바일 스와이프는 자동 검증하지 않았으며 로직 회귀 테스트와 HTTP 렌더링 검사까지 확인했다. 실제 Supabase 연결·OAuth·회원 간 부하 검증은 별도 후속 작업이다.
