# 번개 참가 승인과 신청 화면 정리 — 2026-10-18

## 참가 방식

사이트에서 직접 여는 번개는 사전 결제를 사용하지 않는다. 신청자가 프로필에 저장한 닉네임·연락처를 사용하고 참가 질문·요청사항·정보 제공 동의를 제출하면 **담당자 승인 대기**가 된다. 주최자 또는 지정 담당자가 승인해야 참가가 확정되고 기존 전용 공지방에 입장할 수 있다. 담당자만 공지를 작성하며 참가자는 읽기 전용이다. 현장에서 발생한 비용은 참석자끼리 정산한다. 슬리퍼가 현장 비용을 수금·보관·자동 정산하는 기능은 아니다.

새 번개 개설 화면에서는 외부 결제 링크와 선결제 금액 선택을 제거했다. 서버도 신규 번개에 외부 신청 링크·0원이 아닌 선결제 금액을 허용하지 않는다. 직접 번개는 일반 글 수정·행사 설정으로 외부 결제 모집이나 자동 승인으로 바꿀 수 없다. 목록·상세·지도·검색 조건·신청 내역에서는 ‘무료’와 ‘사전 결제 없음’을 구분해 안내한다.

## 신청·승인·취소

1. 모집글의 신청하기 → 모임 요약(일정·장소·비용·정원) 확인.
2. 기존 기본정보 확인 → 참가 질문·요청사항 → 정보 제공 동의 → ‘참가 요청 보내기’.
3. 승인 대기 상태에서는 결제·환불 동의·QR 발급을 요구하지 않는다. 대기 중에는 같은 신청서를 반복해서 표시하지 않고 신청 취소를 제공한다.
4. 내 행사 관리에서 신청 내용 확인 후 승인 또는 사유를 적어 반려한다. 승인 대기자는 정원을 선점하지 않으며 승인 시 확정 인원을 잠금 안에서 확인한다.
5. 승인 후 ‘공지방 입장하기’로 이동한다. 기존 참가 상태 알림·푸시 설정·공지방 권한 처리를 사용한다. 승인 대기는 화면이 보일 때15초 간격과 창 복귀 시 갱신하며, 결제용3초 조회와 구분한다.
6. 취소·반려 후 새 요청을 보낼 수 있다. 승인·반려 재시도는 기존 처리 시각·사유를 덮어쓰지 않으며, 취소된 신청으로는 공지방을 열 수 없다.

## 신청 화면 구성

직접 신청과 외부 신청 화면을 ‘모임 요약 → 진행 순서 → 입력 또는 현재 상태 → 다음 행동’ 순서로 정리했다. 일반 무료 모임은 참가 확정, 유료 모임은 결제 확인, 번개는 담당자 승인으로 두 번째 단계를 구분한다. 외부 신청은 먼저 외부 플랫폼에서 신청한 뒤 신청 번호와 질문 답변으로 내역을 연결하도록 안내한다. 일반 행사의 기존 결제·취소·환불·QR 경로는 유지한다.

운영 설정과 변경·취소·추가 안내는 접을 수 있는 영역으로 배치했다. 모바일 번개 관리에서는 신청자별로 상태와 승인·반려 버튼이 함께 보이며, 처리 영역으로 화면이 이동한다.

## 데이터와 호환성

새 번개 신청은 기존 `event_applications`에 site·0원·pending_approval로 저장하고 결제 주문을 생성하지 않는다. 별도 결제 서버·테이블·알림 시스템을 추가하지 않았다. `/api/participation/applications/{id}/site-decision`을 추가했으며 기존 외부 결제 확인용 `/decision`과 구분한다.

`0068_lightning_manual_approval`은 기존 트리거 함수3개만 교체한다. 기존 `application_source` CHECK와 일반/외부 결제 검증은 유지한다. site 행이 비어 있지 않은 시각을 요구하는 기존 CHECK에 맞춰 번개는 행사 종료 시각을 내부 앵커로 보관한다. 결제 만료 처리는 pending_payment에만 적용하며, 0원 site 신청의 API 응답에는 결제 기한을 제공하지 않는다. 승인 대기를 결제 대기로 처리하지 않는다.

이전 버전에서 생성한 외부 결제 번개의 확인·환불 이력은 계속 읽고 처리할 수 있게 보존했다. 실제 연결 대상에는 적용 전 공개 글24개·직접 번개1개·외부 번개0개·신청0개가 있었으며 기존 데이터 일괄 변경은 하지 않았다. Supabase 마이그레이션 원장69개와 파일 해시, 기존 source CHECK 불변을 확인했다. 실행 역할·RLS·브라우저 역할 격리 점검은 PASS12/WARN1/FAIL0이다.
