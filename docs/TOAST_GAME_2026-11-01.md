# 건배의 눈치 (2026-11-01)

## 규칙과 설정

‘몇 명이 건배?’를 **건배의 눈치**로 추가한다. 호스트는 진행만 맡으며 기존 링크·QR 입장, 대기열·닉네임·준비 확인을 이용한다. 참가자 3~30명, 기본/심화 모드, 라운드 1~10(기본 2), 선택 제한시간 15/30/60/90초(기본 30초)를 설정한다. 참가자 모두 한 번씩 질문하면 1라운드이며 최대 300차례다. 질문 순서는 시작 시 입장 순서로 고정한다.

- 기본: 질문자가 추천 질문 3개 중 선택/수정하거나 5~160자 질문을 직접 작성해 공개한다. 질문자도 건배/패스와 자신을 포함한 예상 인원 0~N을 한 번에 제출한다. 다른 참가자는 건배/패스만 제출한다.
- 심화: 질문자에게만 무작위 목표 0~N을 미리 알려주고 목표에 맞을 질문을 만들게 한다. 질문자는 예측 대신 다른 사람들과 같은 건배/패스를 제출한다. 목표는 결과 때 공개한다.
- 전원 제출 또는 서버 기준 시간 종료 때 자동 집계한다. 사용자가 확정한 방식대로 **미응답은 자동 패스**다. 기본 질문자가 예측을 내지 못하면 0점이다. 예상/목표가 총 건배 인원과 정확히 같으면 질문자 +1점, 아니면 0점.
- 질문 준비 단계에서만 호스트가 0점으로 차례를 건너뛸 수 있다. 선택 중 조기 집계는 제공하지 않는다. 종료 뒤 동점은 공동 순위로 표시한다.
- 1등은 다른 참가자와 과거 공개 질문을 하나 골라 ‘마지막 한마디’를 보낼 수 있다. 공동 1등은 각자 한 번씩 보내며 순서를 정해 말로 대화한다. 개인 답을 공개하거나 점수를 바꾸는 기능이 아니다.
- ‘건배’는 선택 버튼의 이름이다. 실제 음주는 자유이며 물·음료로도 플레이할 수 있다.

## 개인정보와 동시성

게임 상태의 원본은 PostgreSQL의 기존 `sliper.game_rooms`이며 새 nullable JSONB `toast` 컬럼 하나만 추가한다. `0078_toast_game`은 Drizzle로 생성했으며 기존 78개 마이그레이션 해시 일치 후 적용한다. 기존 RLS·역할별 권한은 유지하고 브라우저의 직접 테이블 접근은 허용하지 않는다.

기존 서비스의 방 행 잠금·트랜잭션·5초 statement timeout·접속 권한·분당 요청 제한을 재사용한다. 집계는 행 잠금 안에서 처리하고, COMMIT 뒤 방 UUID만 갱신 신호로 전파한다. 제출 중복·이전 차례·마감 뒤 제출·다른 사람의 질문 작성·비호스트 진행을 검증한다. 상태 변경과 집계의 외부 네트워크 호출은 없다.

개인별 답은 자신의 화면에만 전달한다. 진행자·다른 참가자·대기자에게 선택/기본 예측/심화 목표를 전달하지 않는다. 참가자별 제출 여부도 공개하지 않고 총 제출 인원만 보여준다. 집계/중단하면 현재 `responses`를 지워 게임 상태에는 질문·전체 인원·점수만 남긴다. 결과·히스토리·마지막 한마디의 DTO에 개인 답이 없다. 마지막 한마디에는 공개 질문과 지목 대상만 저장한다. 단, 0명·전원 건배 등 집계값 자체로 가능한 추론까지 차단하는 방식은 아니다.

기존 서버 읽기/실시간 재조회 및 클라이언트 마감 재조회를 통해 서버 시각으로 집계한다. 백그라운드 상태로 지연됐더라도 다음 읽기에서 확정하며 클라이언트의 타이머 값으로 점수를 계산하지 않는다. 진행 중인 멤버는 시작 명단으로 고정된다. 접속이 끊긴 질문자는 호스트가 준비 단계에서 건너뛸 수 있다.

직접 입력한 질문은 기존 커뮤니티 텍스트 정책을 통과해야 한다. 자동 추천 30개는 서버의 정적 질문 목록을 사용하며 외부 AI 호출·유료 API를 추가하지 않는다.
