## 검증과 변경 범위

- 삭제 전에 current·PID·실제 cwd·open fd·메모리 매핑·구성 참조·마운트·하드링크·파일 트리 지문과 점유량을 재검사했다. 정확한 승인 경로만 하나씩 삭제했다.
- 웹·타운·Redis·알림·영상·모니터·Nginx의 PID와 cwd가 전후 동일하다. 웹·타운·Redis·알림·영상의 서비스 시작 시각도 동일하다.
- 기존 Contenido 사이트 PID와 실행 경로를 보존했고 HTTP 200을 확인했다. Nginx 설정 검사도 통과했다.
- 보존 릴리스 3개의 du 점유량과 소스 manifest가 전후 동일하다. current 대상도 같다. 삭제한 릴리스를 붙잡고 있는 열린 파일은 없다.
- 공개 `/games`, `/games/town`, `/ops/health`, `/api/health`, `/api/town/health`가 모두 HTTP 200이다. 현재 게임 카탈로그 해시가 로컬 배포 소스와 동일하다.
- 처음 점검 시 잘못 지정한 `/town`은 404였으며 실제 경로인 `/games/town`으로 고쳐 200을 확인했다. 서비스 변경은 하지 않았다.
- 이전 실패 빌드 `sliper-build-toast-game-01.service`만 PID 0·Restart=no·트리거 없음 확인 후 reset-failed 처리했다. 서비스 실행·중지·재시작은 하지 않았다.
- runtime·incoming·ops·공용 웹 캐시·업로드·DB·Redis·환경 설정·인증서·기존 사이트 파일은 삭제하지 않았다. 애플리케이션이나 DB 변경도 없다.
- 이번 검증은 파일 보존·프로세스·HTTP 운영 점검이며, 실제 참가자 계정으로 모든 게임을 다시 플레이하는 검사는 수행하지 않았다.

## 재발 방지

자동 삭제 타이머는 이번 작업에서 설치하지 않았다. 다음 배포부터는 current·실제 실행 프로세스 참조·직전 정상 롤백본을 우선 보존하고, 나머지에 대해서 경로·파일 트리·데이터 여부를 확인한 dry-run 결과를 남기는 정책이 필요하다. 단순히 날짜순 최근 N개만 남기면 오래된 실제 워커를 지울 수 있으므로 사용하지 않는다.

배포 전후 `df`·릴리스별 `du`를 기록하고 디스크 80% 경보를 별도로 연결하는 개선이 남아 있다.
