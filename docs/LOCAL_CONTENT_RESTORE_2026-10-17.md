# 기존 공개 글의 Supabase 이전 — 2026-10-17

## 사라져 보인 이유

Supabase 실행 환경으로 전환할 때 스키마와 기본 카테고리만 준비했고, 기존 로컬 글·댓글·파일은 복사하지 않았다. 로컬 자료가 삭제된 것이 아니라 사이트가 다른 DB를 조회하면서 나타난 차이였다.

읽기 전용 비교에서 이전 로컬 DB는 전체 글 109개 중 공개 상태 23개, 삭제 상태 86개였다. 공개 글 중 19개는 샘플 표시가 있었다. 전환 후 Supabase에는 새 투표 글 1개가 있었다. 사용자는 샘플 표시를 유지하고 공개 글 23개 모두를 이전하도록 선택했다.

## 복원 범위와 결과

- 공개 글 23개, 연결 댓글 11개, 첨부 이미지 5개와 모집 설정 6개를 이전했다. 현재 Supabase의 공개 글은 기존 1개를 합해 24개, 샘플 19개다.
- 제목·본문·리치 문서·태그·종류·카테고리·익명·샘플·기존 ID와 작성 시각을 보존했다. 가져온 콘텐츠의 갱신 시각은 이전 처리 시각이다.
- 이미지는 기존 UUID와 경로를 유지해 비공개 Supabase Storage로 옮기고 5개 모두 SHA-256을 대조했다. 새 미디어 메타데이터는 supabase backend만 가리킨다. 참가자 전용 행사 기록의 미디어를 공개 글로 옮기는 입력은 거절한다.
- 작성자 이름은 `imported_author_name`에 저장하고 화면에는 ‘이전 작성자’로 구분한다. 익명 글은 이름을 저장·노출하지 않는다. 실제 로그인 계정·프로필을 복제하지 않고 새 OAuth 계정에 글 소유권을 부여하지 않았다.
- 예전 모집은 일정이 모두 지났으므로 마감 상태로 보존했다. 완료·참가 인증·전적은 이번 복원으로 새로 생성하지 않았다.
- 삭제 글과 비공개 콘텐츠, 개발 계정의 좋아요·북마크·투표 이력, 신청·결제·공지방·활동 전적은 복원 대상에서 제외했다. 원본 로컬 DB와 파일은 남아 있다.

## 무결성과 권한

0067 마이그레이션은 posts/comments에 nullable 표시 이름 컬럼 2개와 제약을 추가한다. 표시 이름은 로그인 작성자 ID가 없고 비익명인 경우만 허용한다. 원래의 로그인 작성자 필수·소유권 변경 금지·미디어 소유권 트리거는 유지한다.

복원 도구는 기존 생성 트리거를 지키기 위해 트랜잭션 안에서만 기존 회원 ID를 임시 연결한 후, 커밋 전에 글·댓글·이미지의 로그인 소유권을 모두 제거한다. 이 과정은 새 계정을 생성하거나 글 작성 알림을 보내지 않는다. 원래 글에 대한 새 계정의 수정 권한은 생기지 않는다. 소유권 연결이 필요하면 실제 작성자를 별도로 검증해야 한다.

기존 ID가 일부만 겹치거나 내용이 다르면 중단하며 기존 행을 덮어쓰지 않는다. 이미 정확히 복원된 경우는 읽기만 하고 종료한다. 시각 비교는 DB 세션 시간대가 달라도 같은 시각으로 판정하며 마이크로초 6자리를 보존한다. 시간대 차이와 1마이크로초 불일치를 각각 검사했다.

이번에 별도 원격 계정 전체 데이터를 로컬로 내보내지 않았다. 백업은 승인한 공개 콘텐츠와 연결 정보에 한정해 암호화했으며, 원본과 키·복원 보고서는 Git 제외된 `.local/`에 보관한다. 기존 Supabase 글·프로필·참가 신청은 유지한다.

- 최종 전체 검사968개·서식·비밀값·타입·Drizzle·운영 빌드가 통과했다.
- PC Chrome와 Android 에뮬레이션20개 동작에서 일반 목록21개(첫 페이지20개·두 번째1개)와 별도 추천3개, 글 클릭·모달·상단 메뉴 이동을 확인했다. 실제 단말 검사를 뜻하지 않는다.

- 실제 Supabase 실행 역할의 읽기 전용 DB 점검은 PASS12/WARN1/FAIL0이며, 전체68개 마이그레이션의 순서·시각·파일 해시가 원장과 일치했다. WARN은 pooler 접속 지점 이후 DB 백엔드 TLS를 pg_stat_ssl로 관측하지 못한다는 항목이다. 앱→pooler의 클라이언트 TLS 확인과는 별개이며 공급자 내부 연결 설정 확인이 필요하다.
- 로컬 원본 DB의 글·댓글·파일은 변경하거나 삭제하지 않았다. 기존 새 Supabase 글과 두 회원 프로필, 참가 신청 데이터도 유지했다.
