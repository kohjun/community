# 협업형 아카이브 — 수정 제안과 연결된 연구

구현 기준일: 2026-10-08 · 성숙화 계획 4단계.

회원의 운영 경험과 연구 내용을 자료에 연결하고, 작성자가 검토한 개선을 새 발행 버전으로 남긴다. PostgreSQL이 제안·판정·관계의 원본이며 Redis에 이 데이터를 저장하지 않는다.

## 이용 흐름

1. 발행된 룰북·이벤트 템플릿 상세에서 **함께 개선하는 아카이브**를 연다.
2. 자료 열람 권한이 있는 회원이 최신 버전의 한 항목을 선택하고 수정 후 내용·개선 이유·반영 동의를 제출한다.
3. 작성자는 받은 제안에서 기준 버전과 제안 내용을 나란히 비교한다.
4. 처리 사유와 발행 동의를 확인하고 **승인하고 새 버전 발행**을 누른다. 반려도 가능하다.
5. 제안자는 처리 전 제안을 철회할 수 있다. 승인·반려·철회 후 제출 내용과 판정은 변경하지 않는다.

편집 가능한 항목은 **제목·소개·시나리오·규칙·진행자 가이드** 다섯 가지다. 한 제안은 한 항목만 수정한다. 자신의 자료에는 제안을 보내지 않고 기존 초안 편집을 사용한다. 동일 회원이 같은 기준 버전의 같은 항목에 검토 대기 제안을 중복 제출할 수 없다.

가격·외부 구매 링크·자료 유형·카테고리·준비물·라운드·인원과 시간·이용 조건·파생 및 상업적 이용 권한·출처는 제안으로 변경하지 않는다. 제안에는 자동 알림 발송이나 외부 공개 기여자 경력 부여를 추가하지 않았다.

## 승인과 버전 보존

자료 행을 잠근 뒤 제안 행을 잠그며, 제안과 자료의 정확한 수정 시각으로 동시 편집을 검사한다. 승인은 기존 자료 초안 저장·발행 로직을 같은 트랜잭션에서 사용한다.

- 제안이 이미 처리됐거나 수정 시각이 다르면 충돌로 반환한다.
- 기준 버전 이후 새 버전이 발행됐거나 작성 중인 자료 초안이 있으면 승인을 차단한다.
- 원본 발행본에 제안된 한 항목만 반영하고 기존 배포 조건과 출처 권한을 다시 검사한다.
- 새 불변 버전과 현재 발행본을 저장하고, 제안의 승인 판정과 해당 버전 ID를 함께 기록한다.
- 어느 과정이든 실패하면 새 버전·초안·판정 변경을 모두 롤백한다.

승인으로 기준 버전 다음 번호의 새 버전을 만든다. 기존 발행본은 수정하지 않는다. DB 트리거도 새 버전이 같은 자료의 다음 버전인지, 담당 작성자가 발행했는지, 내용이 원본에서 제안 항목 하나만 바뀐 결과인지 검사한다. 반복 승인은 새 버전을 만들지 않는다. 반려·철회도 새 버전을 만들지 않는다.

## 지식·연구 글 연결

공개된 **이야기** 글 중 `knowledge`(지식) 또는 `lab`(콘텐츠 연구소) 카테고리의 글을 자료의 특정 발행 버전에 연결한다. 자료 작성자 또는 이야기 작성자가 연결을 관리한다.

연결 검색은 카테고리를 선택하고 서버의 이야기·카테고리 필터를 사용한다. 결과는 20개 단위로 탐색한다. 자료 상세에는 연결 글의 제목·작성자 표시·자료 버전이 나오며, 해당 이야기에도 정확한 버전으로 돌아가는 자료 링크를 제공한다. 한 자료·글·버전 관계는 중복 저장하지 않는다. 자료별 연결 목록과 글의 역방향 링크는 각각 최대 50개만 반환한다.

연결은 열람 권한을 부여하지 않는다. 유료 자료의 구체적인 내용이나 비공개 원본을 이야기 링크에서 노출하지 않는다. 익명 이야기의 작성자는 계속 **익명**으로 표시한다.

## 권한과 개인정보

- 협업 목록·제안 제출·비교·판정·연결 API는 현재 이용 가능한 로그인 회원에게 제공한다.
- 제안 내용과 이유, 원본 비교, 처리 메모는 제안자와 자료 작성자만 볼 수 있다. 다른 회원은 연결된 공개 이야기만 탐색할 수 있다.
- 제안 상세를 읽을 때 기준 버전의 열람 권한을 다시 검사한다. 유료 자료 구매 승인이 회수되면 상세 내용은 차단한다.
- 권한이 회수된 제안자도 자신의 대기 제안을 목록에서 철회할 수 있다. 철회 응답에는 상세 내용을 넣지 않는다.
- 자료 작성자·제안자·이야기 작성자의 탈퇴 및 현재 이용 제한, 양방향 차단, 콘텐츠 숨김·삭제를 조회와 수정에 적용한다. 작성자가 없는 이야기의 새 연결을 허용하지 않는다.
- 제안 목록은 20개 단위 요약만 반환한다. 수정 내용·이유·처리 메모·인증 UUID를 요약 응답에 포함하지 않는다.
- 변경 요청은 동일 출처와 JSON 크기를 검사한다. 제안 제출·글 연결에는 기존 DB 기반 요청 제한을 적용한다.
- 응답은 `private, no-store`다. 새 테이블은 RLS를 사용하며 공개 DB 역할의 직접 접근을 금지한다.

## 데이터와 API

| 데이터                     | 역할                                                                      |
| -------------------------- | ------------------------------------------------------------------------- |
| `library_suggestions`      | 자료·기준 버전·제안자·수정 항목·내용·이유·판정·담당자·처리 시각·반영 버전 |
| `library_discussion_links` | 자료·이야기·정확한 발행 버전·연결 담당자·연결 시각                        |
| 기존 `library_versions`    | 승인 시 추가하는 불변 발행본과 기존 출처 정보                             |

`0050_perfect_squadron_supreme.sql`은 테이블·외래키·대기 제안 중복 방지 인덱스·상태 및 크기 제약·RLS를 추가한다. `0051_collaboration_integrity.sql`은 제출 내용과 최종 판정의 불변성, 담당자 및 승인 발행본의 일치, 연결 출처 일치와 공개 DB 역할의 접근 제한을 적용한다.

| 요청                                                  | 기능                                           |
| ----------------------------------------------------- | ---------------------------------------------- |
| `GET/HEAD /api/library/{자료ID}/collaboration?page=1` | 내 제안 또는 작성자의 받은 제안 20개와 연결 글 |
| `POST /api/library/{자료ID}/collaboration`            | 최신 버전 기반 수정 제안 제출                  |
| `GET/HEAD /api/library/{자료ID}/suggestions/{제안ID}` | 권한이 있는 제안의 원본·수정 내용 비교         |
| `POST /api/library/{자료ID}/suggestions/{제안ID}`     | 승인·반려·철회 및 낙관적 수정 시각 검사        |
| `POST/DELETE /api/library/{자료ID}/discussions`       | 특정 버전의 이야기 연결·해제                   |
| `GET/HEAD /api/posts/{글ID}/library-links`            | 공개 이야기의 자료 버전 역방향 링크            |

협업 목록의 알 수 없는 검색 키와 중복 키는 거부한다. 제출 스키마는 허용한 키만 받으며, 가격·출처·권한 필드 등을 임의로 추가할 수 없다.

## 검증과 후속

- `tests/library-collaboration.test.ts`: 단위·DB 회귀 10개. 스키마·개인정보·차단·동의·기존 버전 보존·중복·반려/철회·초안/오래된 기준 버전·유료 권한 회수·연결·RLS·페이지를 검사한다.
- `npm run test:collaboration`: 실제 PostgreSQL 1개. 독립 연결의 동시 승인에서 새 발행본이 하나만 생성되는지 검사한다.
- `npm run test:collaboration-api`: 실제 Next HTTP 1개. 회원/비회원·동일 출처·유료 자료 보호·승인·정확한 버전 연결·HEAD·캐시 정책을 검사한다.
- 최종 `npm run check`: 형식·타입·전체 회귀/DB **668개**와 Drizzle 검사 통과. 처음 실행은 기존 크루 UI 테스트가 Windows sandbox의 경로 접근 제한(EPERM)으로 중단됐으며, 같은 검사를 정상 파일 접근 환경에서 다시 실행해 모두 통과했다.
- `npm run build`: 표준 Turbopack 운영 빌드와 서버 trace **85개, 오류 0개** 검사 통과. 로컬 DB에 0050~0051을 적용했다. 홈·아카이브·기록·플레이어·번개·자료 상세 HTTP200과 상세의 협업 패널 렌더링도 확인했다.
- 기존 실제 PostgreSQL 행사 완료·QR·포트폴리오·회원 미디어 **2개**, 자료 재사용·동시 발행 **2개**도 통과했다. 테스트가 생성한 임시 자료·제안·연결·계정은 정리했다.

다음 성숙화 단계는 **5. 템플릿 시장 고도화**다. 기존 외부 구매 승인에 이용 조건·검증된 운영 사례·구매 권한·분쟁 처리와 재운영 기록을 연결한다. 실제 운영 인증·외부 결제·모바일 브라우저 검증은 별도 연동 단계에서 진행한다.
