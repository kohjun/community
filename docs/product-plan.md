# Sliper 제품 및 개발 계획

- 기준일: 2026-10-01
- 계획 상태: 확정
- 구현 상태: **PostgreSQL CRUD·참가 승인/공지방·룰북/템플릿·플레이어·환불 요청·전체 UI 구현, 인증·Supabase 원격·실제 결제 플랫폼은 후속 연동**
- 이 문서는 확정된 요구사항과 후속 개발 순서를 기록한다. 계획에 포함된 기능이나 화면을 구현 완료로 간주하지 않는다.

## 1. 서비스 목적과 대상

Sliper는 예능 콘텐츠를 바탕으로 한 오프라인 이벤트와 파티를 소개하고, 관심 있는 사람들이 이야기를 나누는 커뮤니티다. 주요 대상은 20~40대다.

초기 MVP는 커뮤니티 게시글을 중심으로 시작했다. 후속 요청에 따라 행사 참가와 외부 결제 확인·승인·공지방, 룰북 배포, P2P 템플릿 개설, 플레이어 전적과 한국 달력 날짜 기준 환불 요청으로 확장했다. 실제 결제·환불·정산은 연결할 외부 플랫폼이 담당한다. 티켓 발급·검증은 범위에 포함하지 않는다.

## 2. 디자인과 사용자 경험

### 브랜드 원칙

- 공식 로고는 제공받은 `KakaoTalk_20260929_233726187.png` 원본을 보존한다.
- 시그니처 색상은 **#0A84FE**이며 검정, 흰색, 회색을 함께 사용한다.
- 당근의 쉬운 탐색 구조를 참고하되 당근의 로고, 이미지, 아이콘 등 브랜드 자산을 복제하지 않는다.
- 직선 위주의 레이아웃과 얇은 구분선으로 콘텐츠를 명확하게 구분한다.
- 모바일 우선 반응형 화면으로 구성한다.
- MVP는 라이트 모드만 지원한다.

### 화면 구성 계획

- 홈에서 인기 콘텐츠는 카드로 강조하고, 나머지 게시글은 목록으로 표시한다.
- 카테고리의 현재 선택 상태는 파란색 인디케이터로 구분한다.
- 작은 에피소드 라벨과 인기 콘텐츠 카드를 통해 예능 기반 커뮤니티의 분위기를 표현한다.
- 모바일 하단 탭은 **홈 · 카테고리 · 알림 · 마이**로 구성한다.
- 버튼, 입력창, 메뉴 등은 Tailwind CSS와 shadcn/ui를 기반으로 브랜드 색상과 구분선 스타일을 적용한다.

위 디자인을 Next.js·Tailwind CSS 기반 미리보기 화면에 적용했다. 인증과 원격 데이터 저장을 포함하는 운영 서비스와 구분한다.

## 3. MVP 기능

| 영역        | 확정 범위                                                        |
| ----------- | ---------------------------------------------------------------- |
| 인증        | Supabase Auth를 통한 카카오·구글 로그인                          |
| 작성자 표시 | 로그인한 회원의 선택적 익명 작성                                 |
| 글쓰기      | Markdown 에디터와 이미지 업로드                                  |
| 게시판      | 9개 카테고리를 통한 게시글 분류 및 탐색                          |
| 댓글        | 깊이 제한 없는 중첩 댓글                                         |
| 게시글 반응 | 좋아요와 북마크                                                  |
| 조회수      | 게시글별로 같은 브라우저 방문자는 한국 표준시 기준 하루 1회 집계 |
| 알림        | 댓글 알림                                                        |

### 익명 작성

익명 작성은 인증된 회원이 작성자 표시 방식을 선택하는 기능이다. 비회원 익명 작성 기능은 포함하지 않는다. 실제 작성자와 게시글·댓글의 소유 관계는 서버에서 유지하고, 공개 화면과 응답에서는 익명 표시 정책에 맞게 작성자 정보를 제공한다.

### 조회수

조회수는 로그인 계정이 아닌 **브라우저 방문자**를 기준으로 중복을 제외한다. 동일 게시글을 동일 브라우저에서 반복 열람해도 한국 표준시(KST, Asia/Seoul) 기준 같은 날짜에는 한 번만 집계한다. 날짜가 바뀌면 다시 집계할 수 있다. 이 값은 서로 다른 브라우저나 기기를 합산한 실제 인원수를 의미하지 않는다.

### 아직 제공하지 않는 범위

- 실제 카카오·구글 로그인과 Supabase 클라우드 연결
- 특정 결제 플랫폼의 API·정산 연동 (공통 서명 브리지와 외부 처리 확인은 구현)
- 티켓 발급·검증
- 자동 플레이어 매칭
- 다크 모드

## 4. 기술 구성

| 영역                    | 선택                                                      |
| ----------------------- | --------------------------------------------------------- |
| 프레임워크              | Next.js App Router, TypeScript                            |
| 스타일                  | Tailwind CSS, shadcn/ui                                   |

인증 확인, 소유권 검사, 입력 검증과 데이터 변경 규칙은 서버에서 처리한다. 두 호출 방식에 동일한 비즈니스 로직을 중복 구현하지 않도록 서비스 계층을 공유한다.

## 5. 1단계 작업 범위

이 절은 초기 DB 스키마·타입 정의 단계의 기록이다. 최신 구현은 12절과 연결 문서를 참고한다. 다음 요구사항을 데이터 구조에 반영한다.

- Supabase Auth 사용자와 커뮤니티 회원 정보의 연결
- 9개 카테고리와 게시글의 관계
- Markdown 게시글, 이미지 정보, 선택적 익명 표시
- 부모 댓글을 참조하는 중첩 댓글 구조
- 게시글 좋아요 및 북마크의 중복 방지
- 게시글·브라우저 방문자·KST 날짜를 기준으로 한 조회수 중복 방지
- 댓글 알림의 수신자 및 관련 콘텐츠 관계
- 서버 내부 데이터와 공개 응답에 필요한 TypeScript 타입

스키마, 제약 조건, 관계와 타입을 먼저 정리하고 다음 단계의 인증 및 기능 구현에서 사용한다. 실제 Supabase 환경 적용과 기능 동작 확인 여부는 구현 결과에 따라 별도로 기록한다.

## 7. 1단계 검증 결과

- 9개 테이블, 2개 SQL 마이그레이션, 9개 카테고리 시드 작성

- TypeScript 검사 통과

- Drizzle 마이그레이션 메타데이터 검사 통과, 스키마 재생성 시 추가 변경 없음
- 공식 로고 원본을 `assets/sliper-logo-original.png`에 복사하고 SHA-256 일치 확인

실제 Supabase 연결, OAuth 왕복, Storage 업로드 및 운영 배포는 아직 수행하지 않았다. [Supabase 연결 준비](supabase-setup.md)는 사용자가 인증 연동을 시작할 때 참고한다.

- Next.js App Router 16, React 19, Tailwind CSS 4, Radix 기반 shadcn/ui 스타일 컴포넌트
- 공식 로고·파란색과 인기 카드/목록형 커뮤니티, 데스크톱 사이드바 및 모바일 하단 탐색
- 9개 카테고리, 게시글 12개, 예시 댓글·알림과 생성 이미지 3개
- 카테고리 필터, 검색, 최신순/인기순, 북마크 목록, 내 글 목록
- Markdown 에디터·안전한 렌더링, 2 MiB 이하 이미지 1장, 선택적 익명과 중첩 답글
- 브라우저 저장소에 글·댓글·좋아요·북마크·조회 날짜·알림 읽음 상태 보존
- 데이터는 Zod로 검증하며 저장소 용량 부족 시 화면에 안내

로컬 미리보기는 세션 인증·서버 권한 검사·실제 회원 간 동기화를 제공하지 않는다. 행사명, 이미지, 활동 수치는 예시임을 화면에 표시한다. 브라우저 테스트에서 저장한 `[미리보기 확인]` 글·댓글은 해당 테스트 브라우저에만 남는다.

## 9. 실제 CRUD 연결 (2026-09-30)

최신 구현 현황은 [CRUD/API 및 로컬 DB](crud-and-local-db.md)에 정리했다. 위 7·8절은 이전 단계의 기록이다. 현재 화면은 브라우저 저장소 대신 PostgreSQL을 사용한다. 임시 작성자는 로컬 개발 환경에만 허용되며 Supabase/OAuth 연동을 대신하지 않는다. 글과 댓글 수정·삭제, 이미지 업로드, 검색·페이지 처리, 반응, 조회, 알림을 공통 서비스로 구현했다. 글 목록·부모별 댓글·알림의 커서 페이지 처리를 구현했다. 운영 저장소·인증 통합과 실제 다중 사용자 부하 검증은 남아 있다.

## 10. 목록·댓글·알림 안정화 및 폴더 이동 (2026-09-30)

프로젝트 위치를 `C:\Sliper`로 변경했다. 기존 DB와 업로드 파일을 유지한다. 최신순·인기순 목록은 정렬 조건에 맞는 커서로 이어 읽고, 댓글은 최상위 목록과 부모별 답글을 독립적으로 불러온다. 알림은 페이지 크기와 별도로 전체 미읽음 수를 표시한다. 좋아요·댓글·읽음 처리 이후 이미 불러온 페이지를 유지하고 오래된 요청 응답이 새로운 댓글 또는 읽음 상태를 덮어쓰지 않도록 검사한다. 인증 연동은 계속 후속 단계로 둔다.

## 11. 커뮤니티 확장 (2026-09-30)

글쓰기 옵션을 단계별로 정리하고 직접 모집 정보·투표·태그를 추가했다. 메인에는 광고 공간, 자동/수동 콘텐츠 순환과 핫한 이야기, 브랜드 슬로건을 적용했다. 지식(실전 노하우), 콘텐츠 연구소(작품 기법·미션·각색), 함께 만드는 크루(MC·진행·파트너) 게시판을 세부 주제로 탐색한다. 마이페이지는 편집 가능한 프로필과 DB 활동점수·레벨·성취를 제공한다. 로그인 화면은 구현했으며 인증 연동은 사용자 요청에 따라 계속 미룬다. 이 시점의 직접 모집은 댓글 문의 방식이었다. 후속 요청에서 참가 신청·결제 확인·공지방 흐름을 추가했다.

## 12. 행사 운영과 P2P 플랫폼 확장 (2026-10-01)

외부 링크 모집글은 외부 플랫폼에서 신청·결제하고, Sliper 담당자 승인 또는 검증된 플랫폼 알림 후 공지방에 참여한다. 외부 링크가 없는 글은 내부 참가 신청과 유료 정원 예약·외부 결제 확인을 사용한다. 행사 관리 대시보드는 개인정보 접근을 담당자로 제한하고 승인·반려·설정·공지·환불·전적 기록을 제공한다.

통합 아카이브는 룰북과 이벤트 템플릿을 자료 종류로 구분해 한 목록과 작성·상세 화면에서 제공한다. 시나리오·규칙·준비물·멘트·타이머·Markdown 배포와 유료 외부 구매 확인을 유지한다. 일반 회원은 템플릿의 진행 사본을 보존하며 참가비·장소·일정을 지정해 행사를 개설한다. 플레이어 전적과 매너 온도는 담당자 확인 및 실제 공동 참가자의 평가를 집계하고 허구 샘플은 제외한다. 한국 달력 날짜로 5일 전까지 100%, 이후 80/60/40/20%, 당일 이후 0%를 계산하고 요청 당시 금액을 보존한다.

모든 서비스 화면은 Sliper 로고와 파란색을 유지하며 흰색 헤더·간결한 탐색·회색 구분선·모바일 목록/폼으로 정리했다. 실제 OAuth·결제 플랫폼 API·Supabase 클라우드·배포는 사용자와 후속 연결한다. 최신 검증 결과와 사용법은 [룰북·플레이어 문서](PLAYBOOKS_AND_PLAYERS.md)와 [행사 운영 문서](PARTICIPATION.md)를 참고한다.

## 13. 번개와 위치·취향 검색 (2026-10-01)

무료·2~12명·7일 이내 번개를 한 번의 양식으로 개설하고 기존 참가 확정·공지방을 재사용한다. 메인 검색창 왼쪽에 취향 이벤트 찾기를 추가해 카테고리·종류·한국 날짜·금액·신청 가능 조건을 설정한다. 위치 동의 후 반경 검색과 가까운순을 사용하고 공개 행사장 좌표는 관리 화면/템플릿 개설에서 등록한다. 검색 위치는 프로필에 저장하지 않는다. 실제 HTTP/DB 검사와 운영 빌드를 통과했으며 자세한 사용법은 [번개·위치 검색 문서](LIGHTNING_AND_DISCOVERY.md)에 기록했다.

## 14. 공유·통합 검색·크루와 실서비스 준비 (2026-10-05)

고유 글 상세 URL과 한글 공유 미리보기, 이야기·모집·룰북·템플릿 통합 검색, 지속적으로 운영하는 크루를 구현했다. 크루는 공개 닉네임 동의·가입 승인·운영진 관리·공지·담당 행사 연결·QR 입장 및 완료 전적을 근거로 한 기여와 활동점수를 제공한다. private Supabase Storage 어댑터, 행별 저장소 구분과 비밀값을 출력하지 않는 운영 설정 점검을 준비했다.

사용자는 Supabase·결제 플랫폼·서비스 도메인이 아직 준비되지 않았다고 답했다. 따라서 실제 외부 인증·저장소·거래·배포는 활성화하지 않으며 준비된 기능을 로컬에서 검증했다. 사용법과 접근 경계는 [글·검색·크루](SHARING_SEARCH_AND_CREWS.md), 다음 연결 순서는 [실서비스 준비](PRODUCTION_INTEGRATION.md)에 정리했다.
