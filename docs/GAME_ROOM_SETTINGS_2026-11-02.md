# 게임방 안에서 옵션 변경

## 동작

호스트는 대기실의 ‘게임방 설정 → 설정 변경’에서 방 이름·정원·시작 최소 인원과 해당 게임의 옵션을 편집하고 저장한다. **사용자가 정정한 요구대로 설정 저장은 참가자의 준비 상태를 초기화하지 않는다.** 닉네임·자기소개 MBTI·입장 순서도 유지한다. 참가자에게는 현재 옵션과 변경 알림을 보여주되 편집 버튼은 제공하지 않는다.

- 건배의 눈치: 기본/심화, 라운드, 선택 제한시간.
- 수상한 경매장: 라운드, 시작 머니, 입찰 시간.
- 제시어 라이어: 카테고리·라이어 방식.
- MBTI 자기소개: 진행 라운드.
- 기존 MBTI 위장 방: 라이어 정체 알림 여부.
- 자유 대기실: 공통 방 정보와 인원.

게임 종류는 같은 방에서 바꾸지 않는다. 플레이 중·종료 상태에서는 수정할 수 없고 ‘다음 라운드 준비’로 대기실에 돌아온 뒤 수정할 수 있다. 이 기존 재시작 작업은 준비를 초기화하지만 **설정 저장 작업은 그렇지 않다.** 정원을 늘리면 기존 대기열의 첫 참가자부터 입장하며 새 입장자의 초기 준비 상태는 미완료다. 기존 참가자보다 정원을 줄여 강제로 내보내는 기능은 제공하지 않는다.

## API·저장·동시성

기존 호스트 PATCH API에 `action: settings`를 추가했다. 기존 방 행 잠금·트랜잭션·권한 확인·요청 제한·텍스트 정책을 재사용한다. 제목/정원/최소 인원과 해당 게임의 JSONB 상태에 옵션을 저장하며 별도 테이블·컬럼·마이그레이션은 추가하지 않는다. Supabase 마이그레이션 79개를 유지한다.

공개 옵션을 스키마로 정규화해 SHA-256 구성 지문 `settingsVersion`을 만든다. 참가자 입장·준비·하트비트에는 이 지문이 바뀌지 않아 호스트의 미저장 편집을 방해하지 않는다. 다른 창에서 옵션을 먼저 변경했으면 원본 지문이 달라져 덮어쓰기를 차단하고 ‘최신 설정 불러오기’를 제공한다. 지문은 인증 토큰이 아니며 개인 식별자·역할/정답/건배 선택·목표 인원을 포함하지 않는다.

실제 저장은 대기실 여부·소유 호스트·현재 옵션 지문·인원 범위를 행 잠금 안에서 확인한다. 경매 라운드가 현재 입장 인원과 최소 인원보다 많아야 한다. 같은 옵션을 다시 저장하면 불필요한 설정 갱신과 준비 변경을 하지 않는다. 저장·시작이 동시에 실행되어도 둘을 같은 방 잠금으로 직렬화한다. 준비 중인 자기소개 정보는 새 옵션 상태에 보존한다.

- 새 SQL 검사 8개: 모든 게임 옵션과 시작, 준비/MBTI 보존, FIFO 승격, 입장/준비 변경과의 독립성, 동시 편집·동일 저장, 권한·진행 단계·게임 종류 제한, 정책/범위, 공개 데이터 보호.
- 실제 SQL/SSE 브라우저 검사 5개: 호스트 저장, 참가자 옵션 수신·준비 유지, 다른 창 충돌, 새 인원 입장, 재접속, 진행 중 잠금, 자기소개 정보 보존, 경매/라이어/자유 게임 옵션과 시작. 320/393/720/721/1440px 편집 화면 가로 넘침도 확인했다.
- 전체 검사 1,177개와 비밀정보·포맷·타입·Drizzle 일관성 검사 통과.
