# 모바일 UI·UX 개선

기준: 2026-10-25. 기존 파란색·Pretendard·라이트 테마와 PC 구성을 유지하며 모바일 공통 탐색과 입력 흐름을 정리했다.

## 구현한 화면과 동작

1. **공통 하단 메뉴**: 홈·모임·탐색·알림·마이를 공통 레이아웃에 배치했다. 홈에서 다른 서비스 화면으로 이동해도 메뉴를 사용할 수 있다. 경로와 모집/저장 글 등의 쿼리 상태로 현재 위치를 표시한다. 로그인·가입·결제·관리자·별도 작성/편집 화면은 해당 작업에 집중하도록 제외한다.
2. **탐색 바텀시트**: 번개·이야기·아카이브·이벤트 맵·모임 제안·내 행사, 취향별 카테고리, 조건 저장·참가 현황·플레이어/크루를 한곳에서 찾는다. 검색·닫기·내부 스크롤·키보드 포커스와 Escape 닫기를 제공한다. 짧은 화면에서도 닫기와 스크롤 영역을 유지한다.
3. **검색과 첫 화면**: 모바일 헤더와 중복 메뉴를 줄이고 취향 필터·검색 입력칸을 같은 행에 배치했다. 빠른 동선은 세 개의 작은 카드로 정리했다. 320px에서는 통합 검색 보조 링크를 숨기며 탐색창의 통합 검색은 유지한다. 긴 로그인 닉네임은 헤더에서 숨기고 로그인/로그아웃 버튼을 확보한다.
4. **읽기와 터치**: 목록 제목·요약·모임 정보·주요 입력칸을 읽기 편하게 조정했다. 주요 메뉴·닫기·이동 버튼의 터치 영역을 확보하고 가로 카테고리는 스크롤로 탐색한다. 입력칸은 16px로 조정하고 확대 제한을 걸지 않는다.
5. **페이지 이동**: 모바일은 이전/다음과 현재 페이지 입력·이동을 제공한다. 범위를 검증하고 이동 시 입력 포커스를 해제한다. PC의 번호형 페이지 탐색은 유지한다.
6. **글쓰기**: 게시글 목록을 읽을 때만 플로팅 글쓰기 버튼을 보여 추천 카드와 겹치지 않게 한다. 비회원에게도 글쓰기 진입을 제공하고 현재 주소를 포함한 로그인으로 연결한다.
7. **입력과 모달**: 입력 중에는 하단 메뉴를 잠시 숨기고 검색 제출 시 다시 보인다. 모달은 화면 높이 안에서 스크롤되며 닫기를 확대하고 열린 모달 뒤의 하단 메뉴·글쓰기 버튼을 숨긴다. 기기 하단 안전 여백과 동적 화면 높이를 반영했다. Android의 지원 브라우저에는 키보드에 맞춰 콘텐츠 화면을 줄이도록 viewport를 설정했다.
8. **알림**: 기존 미읽음 알림 드롭다운과 더 보기를 재사용해 하단 메뉴 위에서 열리도록 했다. 별도 알림 폴링이나 저장 경로를 추가하지 않았다.

## 변경 위치

- `src/components/mobile-navigation.tsx`, `src/domain/mobile-navigation.ts`: 공통 메뉴와 탐색 시트, 현재 위치 분류.
- `src/app/layout.tsx`, `src/app/mobile-experience.css`: 공통 연결·viewport·모바일 표현.
- `src/components/sliper-community.tsx`: 검색·글쓰기·기존 홈 전용 하단 메뉴 교체.
- `src/components/community-pagination.tsx`: 모바일 페이지 입력.
- `src/components/event-discovery.tsx`, `src/components/test-account-controls.tsx`: 모바일 필터 이름과 계정 헤더.
- `tests/mobile-navigation.test.ts`: 경로/쿼리 선택 상태와 작업 화면 제외 회귀 검사.

DB 스키마·저장 데이터·OAuth·신청·결제·알림 발송 권한은 변경하지 않았다.

## 검증

- 전체 검사 **1,023개 통과**. 비밀값·서식·타입·Drizzle 검사 통과. 마지막 UI 조정 후 타입 검사와 최종 운영 빌드도 통과했다.
- 실제 로컬 서버를 Chrome의 Android 화면 설정 **320·390·430px**에서 검사했다. 공통 메뉴, 검색/포커스, 탐색 열기·닫기, 아카이브/모집 이동, 알림, 페이지 이동, 글 상세·닫기, 비회원 글쓰기·로그인, 번개 화면의 **30개 시나리오**를 통과했다. 페이지 오류·가로 넘침 0개였다.
- 추가 **3개 시나리오**: 320px 긴 닉네임/로그아웃, 1440px PC 표시 유지, 390×420 짧은 화면 탐색창. 계정 화면 검사는 브라우저에서 가짜 세션/로그아웃 응답을 사용했고 실제 회원이나 인증 상태를 변경하지 않았다. 다른 변경 API도 차단해 검증 중 데이터 쓰기는 없었다.
- 운영 빌드 성공, 서버 추적 **116개** 검사에서 오류·비밀 설정·워커 의존성 0개. 빌드 사본의 src/public/drizzle과 원본이 일치했다. standalone **2,540개 파일**에서 비밀 설정 파일·외부 링크·영상 워커 패키지를 발견하지 않았다.
- 실제 Android/iPhone, Safari, OS 키보드를 띄운 상태의 현장 검증은 별도다. 짧은 viewport 검사는 실제 OS 키보드 검증을 대신하지 않는다.

## 확인 동선

로컬 홈을 휴대폰 크기로 열고 하단 `탐색`에서 다른 페이지로 이동한다. 검색 입력 중에는 메뉴가 숨고 제출하면 돌아온다. 게시글 목록까지 내려가 글쓰기를 누르면 비회원은 로그인으로 이동한다. 목록 끝에서 페이지 번호를 직접 입력해 이동한다. 로그인 후에는 알림·마이·참가 현황에서도 공통 메뉴를 사용할 수 있다.
