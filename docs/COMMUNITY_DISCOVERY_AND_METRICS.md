# 커뮤니티 첫 개선: 이용 현황·홈·기간별 인기

기준일: 2026-10-11 · 프로젝트: C:\Sliper · 범위: 보완 계획의 A1/B1/B2

이번 변경은 기존 커뮤니티·신청·공지·자료·기록 기능 위에 이용 현황과 발견 동선을 추가한다. PostgreSQL을 원본으로 사용하며 Redis의 공지방 갱신 역할은 변경하지 않는다. 실제 사용자 전환율 개선이나 실서비스 준비 완료를 의미하지 않는다.

## 확인할 화면

- `/admin` → **커뮤니티 이용 현황** → `/admin/metrics`: admin 권한 전용. moderator·일반 회원·비회원은 집계를 열람할 수 없다.
- `/`: 모임 찾기 / 이야기 나누기 / 기획 자료 찾기. 다가오는 모임 → 오늘 반응이 좋은 이야기 → 완료 행사 기록 순서.
- `/stories?sort=popular&period=today`: 오늘 / 이번 주 / 전체와20개 단위 페이지. 모집 목록·카드 전환과 기존 글 상세 모달·새 탭 링크 유지.
- 모바일 광고: 기존 공통 좌우/모바일 광고 공간 유지. 자동 시트는 보이는 화면에서 이용 가능한 시간이30초 누적된 뒤 세션1회.

## 관리자 지표 정의

7일/28일의 신규 가입·신청·확정·완료·후기는 각 원본의 발생 시각을 기준으로 집계한다. 날짜 경계는 한국 시간이며 종료점은 조회 시각이다. 현재 테스트 제외 표시가 있는 계정, 운영 역할 계정, 탈퇴·유효 이용 제한 계정과 샘플/취소 행사를 제외한다. 제재 만료 및 탈퇴/정정 때문에 과거 합계도 달라질 수 있는 현재 원본 기준 통계다.

| 지표 | 원본과 의미 |
| --- | --- |
| 신규 가입 | profiles.created_at. 같은 기간 제외 계정 수를 별도 표시 |
| 가입7일 내 활동 확인 | 현재 남아 있는 북마크·공개 댓글·사이트 신청 중 가입 후7×24시간 내 행동이 있는 회원. 최초 행동 이벤트를 별도로 저장하지 않으므로 삭제 댓글·해제 북마크를 놓칠 수 있는 하한값 |
| 가입 다음 날~7일 내 재방문 | 수집 시작 이후 가입한 회원의 한국 날짜 방문 기록. 가입 당일은 재방문에서 제외 |
| 최근28일 반복 방문 | 서로 다른 한국 날짜2일 이상 방문한 회원. 수집 시작 후28일이 안 지났으면 ‘수집 중’ 표시 |
| 참가 신청 접수 | event_applications.created_at. 사이트 신청·외부 확인 요청, 클릭은 제외 |
| 참가 확정 처리 | confirmed_at 기준. 이후 환불과 별도이며 현재 유효 참가 정원 지표가 아님 |
| 완료 행사·참가 연인원 | 명시적 completed_at이 있는 행사와 attended 전적. QR 입장 여부로 QR/담당자 확인을 나누고 미참석 제외, 실제 참석 후 환불은 유지 |

가입 행동·재방문 비율은 **7일 관찰이 끝난 이전7일/28일 가입 집단**을 사용한다. 한국 시간 오늘0시에서7일을 뺀 시각보다 먼저 가입한 집단을 선택하고 시작·종료 시각을 화면/API에 반환한다. 회고 비율도 선택한 완료 기간을7일 앞당겨 관찰이 끝난 행사만 분모로 삼는다. 신규 가입/현재 완료 수와 이 비율의 분모는 서로 다른 집단이므로 나누어 전환율을 만들지 않는다. 분모가 없으면0%가 아닌 ‘관찰 중’이다.

## 저장·권한·보관

추가 마이그레이션: `0056_mighty_weapon_omega.sql`.

- `analytics_state`: 단일 수집 시작 시각과 마지막 정리 날짜. 마이그레이션 재실행 시 시작점을 바꾸지 않는다.
- `analytics_activity_days`: 회원ID + 한국 날짜의 기본키. 중복 탭/요청은 같은 행으로 합쳐진다. 방문 경로·본문·사진·연락처·위치·기기 식별자를 추가 저장하지 않는다.
- `profiles.analytics_excluded`: 운영과 구분되는 테스트/샘플 회원 표시. 일반 프로필 수정 API로 변경할 수 없다.
- `post_likes_period_idx`: 게시글/좋아요 시각/회원 인덱스.
- 새 테이블은 RLS를 켜고 기존 신뢰된 서버 DB 연결에서만 접근한다. 회원 API는 개별 활동 날짜나 관리 통계를 반환하지 않는다.

```mermaid
flowchart LR
    Screen[화면이 보이는 회원 방문] --> Visit[동일 출처 POST /api/analytics/visit]
    Visit --> Actor[서버 세션·활성 회원·제외 계정 검사]
    Actor --> Days[(PostgreSQL 회원별 활동 날짜)]
    Original[(가입·신청·출석·기록 원본)] --> Aggregate[관리자 권한으로 집계]
    Days --> Aggregate
    Aggregate --> Dashboard[/admin/metrics]
```

클라이언트는 날짜나 회원ID를 제출하지 않는다. 서버가 현재 세션과 시각을 정하고 한국 날짜별로 중복을 막는다. 수집은 글쓰기/신청과 별도 요청이며 실패해도 사용자의 원래 작업을 실패시키지 않는다. 탈퇴와 같은 프로필 잠금 아래에서 수집·삭제하므로 탈퇴 직후 기록이 다시 생기는 경쟁도 막는다.

활동 날짜는90일 범위로 보관한다. 유효 회원의 다음 수집에서 한국 날짜별 한 번 오래된 자료를 삭제한다. 장기간 수집이 전혀 없으면 정리가 그만큼 지연되므로 실서비스에는 운영 작업의 정기 실행을 붙여야 한다. 조회는 필요한 최근 기간만 읽으며, 탈퇴 시 활동 날짜를 즉시 삭제한다. 별도1년 rollup이나 전환 이벤트 원장은 이번 단계에서 만들지 않았다. 기존 거래/게시글 원본의 보관 정책은 변경하지 않는다.

`GET /api/admin/metrics?days=7|28`은 admin 권한만 허용하고 `private, no-store`로 응답한다. 개별 회원ID·본문·신청 답변은 DTO에 포함하지 않는다.

## 인기글·홈의 기준

오늘은 한국 시간0시, 이번 주는 월요일0시부터 기준 시각까지 받은 좋아요 수다. 글 작성일이 오래되어도 그 기간에 반응을 받으면 올라온다. 동률은 글 작성 시각·UUID 내림차순으로 정렬한다. 기간별 점수 `popularityScore`와 기존 전체 좋아요 `likes`를 분리했다. 전체 정렬은 기존 누적 좋아요 정렬과 호환하며 반응이 없는 글도 게시판 목록 끝에 남는다. 기간 인기/홈의 인기 영역은 반응이 없는 글로 채우지 않는다.

기간 인기는 현재 유효한 회원 좋아요를 세고 테스트 제외 계정의 좋아요를 제외한다. 기존 게시글 숨김·작성자 차단·익명 DTO 정책을 유지한다. 홈 인기에는 이야기·후기·투표를, 다가오는 모임에는 시작 시각이 있고 신청 가능한 실제 모집을 보여준다. 샘플은 실제 활동으로 추천하지 않는다. 없는 영역은 안내 문구를 표시한다.

`period=today|week|all`, `rankingAt`, `page`, 정렬·게시판 필터가 URL에 남는다. 기간 커서는 같은 기준 시각을 다시 보내야 하며 기간/시각이 바뀌면 거절한다. 페이지를 넘기는 사이의 날짜 경계는 고정하지만 좋아요 취소·차단·숨김까지 영구 스냅샷으로 얼리는 것은 아니다. ‘지금 기준으로 새로 보기’로 새 기준 시각을 선택한다. 현재 기기 위치 좌표는 공유 URL에 저장하지 않는다.

## 모바일 광고

기존 닫기와 한국 날짜 기준 오늘 하루 숨김을 유지한다. 실제 노출 즉시 세션에 표시해, 다른 모달이 광고를 닫거나 페이지를 이동해도 다시 자동으로 열리지 않는다. 저장소가 막힌 경우에는 메모리 상태로 유지한다.

로그인·가입·인증·계정 설정·내 정보·운영·행사 관리·참가 현황·공지방·행사 신청/결제·QR·작성/편집 경로에서는 열지 않는다. 다른 대화상자나 텍스트 입력에 집중 중일 때도 열지 않는다. 백그라운드 시간은 제외한다. PC 사이드 광고와 기존 수동 콘텐츠 자동 전환/동작 줄이기 정책은 유지한다.

## 로컬 준비와 다음 순서

`npx tsx scripts/analytics-local-prepare.ts`는 LOCAL_DATABASE=1 및127.0.0.1:55432/sliper_dev를 확인한 뒤 마이그레이션을 적용하고, 알려진 seed ID와 기존 테스트 로그인 계정만 집계에서 제외한다. 기존 글·신청·권한·비밀번호를 변경하지 않는다. 새 seed와 테스트 계정 생성 스크립트도 제외 표시를 넣는다. 실서비스에서 모든 회원을 제외하는 일괄 작업은 없다.

C 이야기 말머리·답변 대기/해결됨·관심 피드·스포일러 표시와 질문24시간 내 답변 지표를 구현했다([구현 내역](COMMUNITY_DISCUSSIONS.md)). 다음은 D 주제/자료 조건 검색, E 종료 후 할 일/재개최 동선, F 운영·외부 연동·실기기·백업 복원 검증을 이어간다. 사용자5~8명 관찰, 실제 휴대폰 시각·터치 검증, 서비스 부하 검사는 별도다.
