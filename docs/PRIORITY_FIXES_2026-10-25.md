대상: 종합 리뷰의 R0–R10과 후속 운영 의존성 감사. 이번 수정은 기존 기능의 권한·상태 전환·미디어 처리에 집중했다. 기존 사용자·행사 데이터를 되돌리거나 샘플로 덮어쓰지 않았다.

## 파일 삭제 작업과 운영 방법

PostgreSQL에 object_cleanup_jobs를 추가했다. 원본 파일 경로는 서버 전용 테이블에만 보관하고 브라우저 역할에는 열람/수정 권한을 주지 않는다. Redis에 삭제 작업을 맡기지 않는다.

- 업로드: 삭제 의도를 먼저 영속 저장 → private Storage 업로드 → DB 트랜잭션에서 메타데이터 저장과 의도 제거. 실패하면 기존 의도로 파일을 다시 찾는다. 미완료 업로드에는 1시간 유예를 둔다.
- 프로필 교체·삭제·탈퇴: 기존 주소를 지우는 트랜잭션 안에서 정리 작업도 기록한다. 참조가 남은 파일은 삭제하지 않는다.
- 워커: 기존 알림 워커가 30초 간격으로 최대 5개를 처리한다. 행 잠금/SKIP LOCKED, 2분 임대와 작업 토큰으로 중복/중단을 처리한다. 실패 시 지수 간격으로 최대 8회 시도한 뒤 failed로 남긴다.
- 관리자 /admin/health에서 파일 삭제 재시도 대기·처리·실패 수를 확인한다. 파일 경로나 키는 이 화면에 반환하지 않는다.

```sh
npm run push:worker
npm run object:cleanup
npm run object:cleanup -- --retry-failed
```

두 번째 명령은 최대 20개를 수동 처리하며, 세 번째는 실패 작업을 다시 대기시킨 뒤 처리한다. 기존 30일 미첨부 미디어 보관/정리와 별개다. 이전 코드에서 이미 주소가 사라진 과거 고아 파일을 자동 복구했다는 뜻은 아니다.

## DB 반영

- 추가 마이그레이션: drizzle/0073_object_cleanup_outbox.sql, 원장 총 74개.
- Supabase 적용 완료: RLS 켬, anon/authenticated 권한 없음, 서버 실행 역할 권한 있음.
- 적용 전후 profiles/posts/event_applications/event_settings/media_assets/profile_photos/video_assets의 행 수·내용 해시가 일치했다. 기존 데이터 변경 없음.
- Supabase 비공개 임시 객체 16KiB로 2바이트와 1,024바이트 범위를 확인한 뒤 객체와 테스트 정리 작업을 제거했다. 실제 회원의 파일을 사용하지 않았다.

격리된 운영 빌드 사본으로 개발 서버와 환경파일을 분리했다. 배포 산출물의 소스 일치와 비밀파일·워커 바이너리·외부 링크 포함 여부를 별도 감사했다. 재현 로그는 Git 제외 .local/priority-* 파일에 보관한다. 개발 서버의 초기 컴파일 시간을 운영 환경 성능으로 보고하지 않는다.

재현 명령:

```sh
npm run check
npm run test:browser
node --conditions=react-server --import tsx --test tests/cache-media.integration.ts
npm audit --omit=dev
npm run build -- --webpack
```

npm run check는 비밀값 검사·서식·타입·기본 테스트·마이그레이션 일관성을 포함한다. 브라우저 검사는 별도 명령이며 기본적으로 설치된 Chrome을 사용한다. 다른 실행 환경에서는 Playwright Chromium과 SLIPER_BROWSER_CHANNEL 설정이 필요할 수 있다.

브라우저 회귀는 실제 신청/대기/작성/로그인 링크 컴포넌트를 격리된 테스트 서버에 올리고 외부 API를 대체했다. 실제 OAuth·결제·회원 신청 데이터를 변경하는 종단간 검사와 구분한다. 별도의 실제 로컬 공개 화면 점검에서도 변경 API를 차단했다.
