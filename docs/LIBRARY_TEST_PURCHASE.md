# 유료 가이드 구매 화면과 로컬 테스트 구매

기준일: 2026-10-08 · 프로젝트: C:\Sliper

유료 자료의 안내·가격·제공 자료·구매 입력을 한 카드로 정리했다. 데스크톱은 자료 설명과 입력을 두 열로, 모바일은 세로로 배치한다. 이용 동의 체크박스는 구매 카드 전용 스타일을 사용하고 사이트의 자체 호스팅 Pretendard와 #0A84FE를 유지한다.

## 로컬에서 사용하기

1. 로컬 개발 서버에 로그인하고 다른 회원의 유료 자료를 연다.
2. ‘테스트 구매’와 ‘실제 결제 없음’을 확인한다. 외부 사이트로 이동하거나 구매 번호를 입력하지 않는다.
3. 선택적 메모와 이용 조건 동의 후 **테스트 구매하고 열람하기**를 누른다.
4. 같은 페이지에서 시나리오·규칙·준비물·진행자 가이드·타이머가 열린다. 내 구매에서는 가격과 당시 버전/조건, 테스트 내역을 확인한다.

실제 결제·금액 청구·환불·정산은 발생하지 않는다. DB에는 `local-test`로 구분된 테스트 구매와 권한, 처리 이력이 남는다. 반복 요청이나 동시에 두 번 클릭해도 진행 중인 테스트 구매를 중복 생성하지 않는다.

이미 실제/수동 구매 확인이 대기 중이거나 승인된 자료의 기록을 테스트 구매로 바꾸지 않는다. 대기 내역은 ‘내 구매’ 또는 담당자 확인으로 처리한다. 자신의 자료와 무료 자료에는 테스트 구매가 필요하지 않다.

## 활성 조건과 서버 처리

외부 자료 결제 설정이 없고 아래 조건을 모두 만족할 때만 화면과 서버의 테스트 구매가 활성화된다.

- `NODE_ENV=development`
- `LOCAL_DATABASE=1`, `SLIPER_AUTH_MODE=development`
- DB 주소가 정확한 격리된 `127.0.0.1:55432/sliper_dev` PostgreSQL
- `LIBRARY_PAYMENT_PROVIDER`, `LIBRARY_PAYMENT_WEBHOOK_SECRET` 모두 비어 있음

운영 빌드·원격 DB·외부 연동 또는 일부 설정만 입력한 환경에서는 서버가 테스트 구매를 거부한다. 클라이언트의 테스트 모드 지정으로 활성화할 수 없다. 일반 외부 구매 확인과 서명 브리지는 기존 동작을 유지한다.

`POST /api/library/{entryId}/test-purchase`는 로그인·같은 출처·활성 회원·자료 공개 상태·차단·정확한 버전·이용 동의를 검사한다. 입력은 `version`, 선택적 `note`, `consent:true`만 허용하며 가격·회원·주문 번호·승인 상태를 받을 수 없다.

자료 잠금과 동일 DB 트랜잭션 안에서 서버가 테스트 주문 번호와 결제 확인 이벤트를 생성하고, 기존 구매 원장·권한·감사 이력·이벤트 접수 흐름으로 처리한다. 실제 외부 API는 호출하지 않는다. 권한 승인 실패 시 전체 거래를 롤백한다. 기존 실제 구매 또는 과거 승인 권한을 덮어쓰지 않는다.

## 검증

- 환경·입력·소유권·버전·동의·차단·숨김·탈퇴 및 기존 실제/수동 구매 보호 검사
- 실제 Next HTTP에서 비회원/외부 출처/금액 위조 차단, 동일 자료 동시 테스트 구매 한 건, 즉시 본문 열람, 영수증의 테스트 안내 확인
- 승인 실패 시 구매·이벤트·감사 이력이 남지 않고 이전 권한이 복원되는 DB 검사

단위/DB 검사: `npx tsx --test tests/library-test-purchase.test.ts`.
실제 개발 서버 검사: `npm run test:market-api`.
운영 결제 연동 계약과 당시 구매 조건 보존은 [템플릿 시장 문서](TEMPLATE_MARKET.md)를 참고한다.
