# 장소 데이터 축적 — 행사와 장소 이력

구현 기준일: 2026-10-08 · 성숙화 계획 3단계.

등록 장소를 실제 행사와 연결하고, 선택 당시의 장소 정보와 완료 행사의 운영 경험을 보존한다. 좌표가 같다는 이유로 장소를 자동 연결하지 않는다.

## 이용 흐름

1. 일반 모집글·번개·템플릿 행사 개설에서 **공유 장소에서 선택**을 누르고 이름이나 주소로 검색한다.
2. 선택한 장소의 이름·주소·좌표가 채워진다. 직접 장소나 좌표를 수정하면 공유 장소 연결은 해제된다.
3. 담당자가 행사 종료 후 완료를 확인하면 당시 장소 스냅샷을 행사 기록에 복사한다.
4. 주최자가 회고의 **장소 운영 팁**을 작성하고 회원에게 발행한다.
5. 이벤트 맵의 **이 장소의 행사 기록**, 회고의 장소 링크에서 장소별 완료 행사와 운영 팁을 탐색한다.

장소 화면은 `/places/{장소ID}`다. 현재 장소 정보와 각 행사에 보존된 당시 정보는 구분해서 표시한다. 완료 행사 / 운영 팁 탭, 행사 제목·팁 검색, 카테고리 필터와 20개 페이지를 제공한다. 운영 팁 탭은 전체 공개 기록 중 팁이 있는 행사를 서버에서 조회한다.

## 저장과 불변 기준

PostgreSQL이 원본이며 Redis에는 장소 기록을 저장하지 않는다.

| 데이터                       | 저장 내용                                       |
| ---------------------------- | ----------------------------------------------- |
| event_venue_links            | 행사별 1개 등록 장소 ID와 선택 당시 JSON 스냅샷 |
| event_records.snapshot.venue | 공식 완료 시 선택 스냅샷을 그대로 복사          |
| event_records.venue_tips     | 주최자가 별도로 작성한 최대 2,000자 운영 팁     |

스냅샷은 장소 ID·이름·주소·좌표·공간 유형·무료 여부·비용 안내·정원·선택한 버전·선택 시각을 담는다. 등록자의 인증 UUID나 연락처는 포함하지 않는다.

같은 장소를 유지한 채 행사 설정을 수정하면 저장된 버전을 유지한다. 수정된 장소를 명시적으로 다시 선택하면 현재 버전과 좌표를 확인하고 갱신한다. 참가 내역이 있는 장소 변경은 기존 운영 제한에 따라 차단한다. 완료 후에는 연결 추가·삭제·변경을 허용하지 않는다.

서버는 행사·설정 행을 먼저 잠근 뒤 장소 공유 잠금을 사용한다. 장소를 수정하는 요청과 선택 요청이 동시에 실행돼도 하나의 일관된 버전만 저장한다. 마이그레이션 0048은 관계와 팁 필드를 추가하고, 0049는 완료 연결 불변·트랜잭션 종료 시 좌표 일치·완료 스냅샷 일치를 DB에서도 검증한다. 새 테이블은 RLS를 활성화하고 공개 DB 역할의 직접 접근을 금지한다.

기존 행사와 전적은 수정하지 않는다. 기존 좌표로 연결을 추정하거나 과거 완료 행사에 새로운 장소 출처를 붙이지 않는다.

## 조회와 지표

`GET/HEAD /api/places/{장소ID}/history`는 `q`, `category`, `tab=records|tips`, `page`를 받는다. 잘못된 값·알 수 없는 키·중복 키를 거부한다. 응답은 `private, no-store`다.

현재 이용 가능한 회원과 장소의 공개 권한을 확인하고, 명시적 장소 연결과 공식 완료 스냅샷이 일치하는 **회원 공개 회고**만 반환한다. 초안·공개 철회·샘플·취소·숨김 기록은 제외한다. 미참석자는 참가 지표에서 제외하며 실제 참가 후 환불된 경우에는 금전 상태와 참가 이력을 구분한다.

완료 행사 수와 참가 연인원, QR 확인 인원, 담당자 확인 인원, 팁 작성 기록 수를 표시한다. 같은 사람이 두 행사에 참가했다면 연인원에 두 번 포함된다. 통계는 현재 회원이 볼 수 있는 공개 기록 전체를 기준으로 하며 검색이나 탭·페이지에 따라 줄어들지 않는다. 조회 트랜잭션은 repeatable read로 통계·총수·목록의 기준을 일치시킨다.

목록 응답은 행사 요약·당시 장소 정보·별도 운영 팁만 담는다. 참가자 명단·연락처·신청 답변·전체 회고 문서·미디어는 포함하지 않는다. 기록 링크가 참가 명단이나 유료 자료의 열람 권한을 추가하지 않는다.

## 접근 정책

- 비회원은 로그인 안내만 보며 기록 API는 401을 반환한다. 공유 메타데이터에는 장소별 회원 전용 기록을 넣지 않는다.
- 장소 또는 행사 작성자의 탈퇴·현재 이용 제한, 양방향 차단, 운영 숨김과 삭제를 반영한다.
- 장소를 볼 수 없게 되면 장소 이력 조회를 차단하고 기록·포트폴리오의 파생 장소 정보도 숨긴다. 저장된 스냅샷은 변경하지 않는다.
- 숨겨진 장소의 팁은 수정할 수 없다. 회고의 다른 항목을 저장할 때 해당 팁을 생략하여 기존 내용을 유지한다.
- 기존 기록 사진·영상의 회원 권한 검사와 직접 GET/HEAD/Range 접근 정책을 유지한다.

- `npm run test:places-api`: 실제 Next HTTP 회원/비회원·검색·중복 조건·HEAD·캐시·삭제 후 정보 보호.
- `tests/place-history.test.ts`: 명시적 연결·위조 좌표·스냅샷 보존·세 생성 경로·참가 확인·필터·페이지·숨김·RLS 회귀.
- `npm run check` 및 `npm run build`: 전체 형식·타입·DB 회귀·마이그레이션·운영 빌드.
