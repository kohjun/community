# Sliper

예능 콘텐츠를 함께 즐기는 20~40대의 커뮤니티. Next.js App Router·TypeScript·Tailwind·shadcn/ui 패턴·Drizzle·PostgreSQL로 구현한다. 공식 로고와 `#0A84FE`를 유지하며, 당근의 단정한 탐색·목록·여백을 참고한 모바일 우선 라이트 디자인을 사용한다. 홈·룰북·템플릿·플레이어·행사 관리·로그인에 공통 헤더와 폼 스타일을 적용했다.

현재 메인 화면은 **실제 PostgreSQL CRUD**에 연결되어 있다. 글 상세 URL·공유/OG, 이야기·모집·룰북·템플릿 통합 검색, 가입 승인·행사 활동·검증된 기여를 관리하는 크루를 추가했다. [사용법과 데이터 흐름](docs/SHARING_SEARCH_AND_CREWS.md)을 참고한다. Supabase Auth 기반 카카오·구글 로그인 코드를 준비했으며 프로젝트 키와 공급자 설정 후 활성화된다. [공개 전 기반과 인증 설정](docs/COMMUNITY_FOUNDATION.md)을 참고한다. 개발 환경에서는 별도 테스트 계정의 아이디·비밀번호 로그인과 기존 loopback 전용 임시 작성자를 사용한다. `npm run auth:test:setup`으로 테스트 계정을 준비할 수 있으며 프로덕션 빌드·원격 DB에서는 이 인증이 비활성화된다. [테스트 로그인·Wi-Fi 접속](docs/TEST_ACCOUNT.md)을 참고한다.

행사 참가자는 로그인 후 `/signup`에서 닉네임·연락처와 정보 저장 동의를 한 번 등록한다. 담당자는 `/management/events/{postId}`의 행사 설정에서 참가 질문을 만들고, 참가자는 닉네임·연락처 재입력 없이 질문 답변과 요청사항을 제출한다. [기본정보·참가 질문·외부 승인 사용법](docs/APPLICATION_FORMS_AND_PROFILES.md)을 참고한다. 문자 인증은 아직 연결하지 않았으며 연락처는 사용자 입력값이다. 정식 회원 로그인은 Supabase Auth 설정이 필요하다.

현재 구현·미연동 항목·남은 우선순위는 [2026-10-09 전체 현황과 로드맵](docs/PROJECT_STATUS_AND_ROADMAP.md)에 정리했다.

## 시작하기 (Windows)

현재 프로젝트 위치는 `C:\Sliper`다. 이 폴더에서 아래 명령을 실행한다. Node.js 22.13 이상, PostgreSQL 18이 필요하다. PostgreSQL 경로가 다르면 `POSTGRES_BIN`을 bin 디렉터리로 설정한다.

```powershell
npm ci
npm run db:local:setup
npm run dev
```

[http://127.0.0.1:3000](http://127.0.0.1:3000)을 연다. 최초 setup은 `.local/postgres`에 독립 클러스터를 만들고 **127.0.0.1:55432**에서 시작한다. 기존 PostgreSQL 서비스는 변경하지 않는다. 무작위 DB 암호와 조회수 서명 키는 Git에서 제외된 `.env`에 기록한다. 이미 있는 `.env`를 덮어쓰지 않는다.

setup은 로컬 최소 auth 스키마 준비 → 마이그레이션 → 9개 카테고리 → 예시 글·댓글·사진 순으로 실행한다. 다시 실행해도 기존 글을 덮어쓰지 않는다. 예시 콘텐츠의 행사 내용과 사진은 가상이지만, 좋아요·조회수·댓글 수는 실제 DB 행을 집계한다.

이후 PC를 다시 켰을 때:

```powershell
npm run db:local:start
npm run dev
```

DB 상태와 종료는 `npm run db:local:status`, `npm run db:local:stop`으로 관리한다. 데이터는 `.local/postgres`, 게시글 이미지 파일은 `.local/uploads`, 프로필 사진은 `.local/profile-photos`, 영상 원본은 `.local/video-sources`, 압축 결과는 `.local/videos`에 남는다. 이 폴더들은 개인 로컬 데이터이며 Git에 포함되지 않는다. 앱을 종료해도 DB 프로세스는 별도로 실행된다.

운영 회고를 비공개 템플릿 초안으로 전환하고, 자료 발행 버전·파생 출처·이용 조건과 행사 운영 사본을 보존한다. 새 화면은 초안 저장과 발행을 구분한다. [사용법과 버전/권한 설계](docs/KNOWLEDGE_REUSE_AND_VERSIONS.md)를 참고한다.

완료 행사 기록과 참가·제작 포트폴리오를 추가했다. `/records`에서 회원 전용 회고를 보고, 행사 담당자가 제작진을 확인하면 본인이 수락하여 제작 경력에 반영한다. 완료 처리·경력 공개·미디어 권한과 다음 단계는 [행사 기록과 포트폴리오](docs/EVENT_RECORDS_AND_PORTFOLIOS.md)에 정리했다.

룰북·이벤트 템플릿의 기획, 미션, 큐시트, 준비물·예산을 목차별로 읽고 항목별로 편집할 수 있다. 코엑스 점령전 예시 불러오기와 버전/유료 권한 보존은 [구조화된 운영 가이드](docs/STRUCTURED_PLAYBOOKS.md)에 정리했다.

## 구현한 기능

- `/posts/{postId}`: 모달과 같은 상세 UI, 공유·링크 복사, 한글 OG 이미지. 일반 클릭은 모달, 새 탭 클릭은 상세 URL
- `/search`: 이야기·모집·룰북·템플릿 통합 검색, 카테고리·종류·20개 페이지. 유료 자료 비공개 본문 제외
- `/players`의 **플레이어·크루** 탐색에서 플레이어와 크루를 탭으로 전환. `/players?tab=crews`는 팀 목록·검색·가입 탐색을 제공하고 기존 `/crews` 목록 주소는 이 탭으로 이동. 크루 생성은 `/crews/new`, 개별 팀은 `/crews/{id}`에서 가입 승인·구성원/운영진·공지·행사 연결·QR 참가 기록 기반 기여 인증과 활동점수 유지
- `/lightning`: 무료·2~12명·7일 이내 번개 빠른 개설, 행사장 좌표·일정·정원과 기존 신청/공지방 연결
- `/map`: NAVER 지도에 유저가 공유하는 이벤트 장소와 실제 모집·번개 핀, 주소 검색·위치 선택·카테고리·무료 필터, 본인 장소 수정/삭제·추천, 선택한 장소로 번개 개설. [지도 설정과 데이터 흐름](docs/EVENT_MAP.md)
- 검색창 왼쪽 취향 이벤트 찾기: 카테고리·번개/일반·내 위치 반경·한국 날짜·참가비·신청 가능 조건, 거리 가까운순 정렬. 행사장 좌표는 관리 화면/템플릿 개설에서 등록하며 검색 위치는 프로필에 저장하지 않음

- `/archive`: 룰북과 이벤트 템플릿을 통합한 아카이브. 전체·룰북·이벤트 템플릿 필터, 검색·카테고리·내 자료 보기, 자료 공유·수정·삭제를 한곳에서 제공. 게임 시나리오·규칙·준비물·진행자 멘트·타이머·Markdown 다운로드와 무료/유료 열람 권한 유지
- `/archive/new?kind=rulebook`, `/archive/new?kind=template`: 같은 작성 화면에서 자료 종류를 선택해 등록. 이벤트 템플릿의 장소·한국시간 시작/종료·참가비·정원으로 P2P 행사를 개설하고 기존 신청·결제·승인·공지방 흐름 사용
- `/archive/events/{postId}`: 원저작자와 개설 당시 내용을 보존한 담당자 전용 진행 가이드. 이후 원본 수정·삭제가 행사 내용을 바꾸지 않음. 기존 `/templates`와 상세·작성·편집·개설·진행 가이드 주소는 새 아카이브 주소로 이동
- `/players`, `/players/{publicId}`: 두뇌형·피지컬형·전략가·트릭스터 성향, 실제 참가·우승·진행 전적, 매너 온도, 역할·지역 탐색. 탐색 공개와 전적 상세 공개는 사용자 선택이며 기본 비공개
- 행사 종료 후 담당자가 참가 전적을 기록하고, 같은 행사에 실제로 참가한 플레이어끼리 매너 평가. 샘플 전적은 실제 참가·매너 집계에서 제외
- 한국시간의 달력 날짜를 기준으로 **5일 전까지 100% → 4일 전 80% → 3일 전 60% → 2일 전 40% → 1일 전 20% → 당일 이후 0%** 환불 안내·예상 금액·취소 요청·담당자 처리. 요청 당시 금액과 정책을 보존하고 외부 플랫폼 처리 확인 후 참가/공지방 권한 해제
- 9개 관심 카테고리와 지식·콘텐츠 연구소·함께 만드는 크루 게시판, 세부 주제·태그 탐색
- 전체·이야기·모집·투표 탭, DB 검색·최신순·인기순·더 보기 (기존 후기 데이터는 이야기 탭에서 보존)
- 게시글 작성·조회·수정·삭제, 내 글과 북마크 목록
- 상단 주요 메뉴와 하위 페이지 활성 표시 공유, 모바일의 선택된 메뉴가 보이도록 가로 스크롤
- 정상적으로 읽은 글의 제목을 일반·추천·인기·번개 목록에서 회색 표시. 브라우저에 최신 2,000개 기록을 저장하고 새로고침·페이지 이동·다른 탭에서도 반영하며, 조회 실패·취소·대체된 요청은 기록하지 않음
- 글 수정 시 열어본 버전을 검사해 여러 탭의 오래된 내용이 최신 저장을 덮어쓰지 못하도록 보호
- 외부 신청 링크가 있는 모집글은 `신청하기`로 해당 플랫폼에 이동해 신청·결제. Sliper에서는 선택적인 사후 참가 확인과 담당자 수동 승인 또는 검증된 웹훅 자동 승인 후 공지방 참여
- 외부 링크가 없는 모집글은 Sliper 내부 참가 신청: 무료 즉시 확정, 유료 금액 고정·30분 정원 예약·외부 결제 브리지 확인 후 확정
- `/management`, `/management/events/{id}`: 본인/지정 담당자의 행사 대시보드, 상태별 집계·이름/연락처/신청 번호 검색·30개씩 조회·승인/반려/외부 환불 확인·자동 승인 설정
- 주최자 전용 행사 취소·일정 변경, 변경 당시 참가자 알림/읽음·공지방 안내·Web Push, 참가 유지와 전액 환불 검토. 실제 환불은 외부 플랫폼 확인 후 기록. [행사 변경 안내](docs/EVENT_LIFECYCLE.md)
- 참가 확정 후 본인 QR 입장권 발급·저장, 담당자의 조회 후 입장 확인·중복 방지. 내 행사에 QR 체크인과 결제 예외 검토 화면 추가
- 행사 종료 후 QR 참가 전적 반영과 닉네임 공개 참가 인증 후기, 이야기 게시판·행사/공개 호스트/템플릿 연결. [행사 운영 안내](docs/EVENT_OPERATIONS.md)
- `/participation`, `/events/{id}`, `/rooms/{id}`: 내 참가 내역, 담당자 전용 공지 작성, 참가자 읽기 전용 SSE 갱신과 담당자 지정
- 서명 웹훅·중복/역순 알림 방어·외부 신청 번호 재사용 차단·환불 시 공지방 접근 해제. 외부 참가 확인 요청은 정원을 예약하지 않으며 결제 확인 후 정원이 찬 경우 담당자 확인 상태로 보존
- 투표 주제·2~8개 선택지, 1인 1표·선택 변경·실제 집계, 참여 이후 선택지 변경 제한
- 구조화된 글쓰기 양식, 본문 템플릿·미리보기·태그·익명 선택
- 광고 공간 미리보기, PC 좌우 160×600 광고 영역(일반 페이지 1568px·홈/이야기 1760px 이상 표시, 낮은 화면에서 스크롤 고정 해제), 모바일(720px 이하) 광고 바텀시트와 오늘 숨김·세션 닫기, 좌우 이동·자동 전환 콘텐츠, 핫한 이야기와 1분 갱신, 플로팅 애니메이션·일시정지·동작 줄이기 지원
- `/mypage`: 프로필·지역·관심사 편집, 실제 활동점수·레벨·성취·내 글/댓글/북마크
- `/login`: Supabase Auth 카카오·구글 OAuth(PKCE), 서버에서 검증한 세션과 로그아웃. 격리된 로컬 개발 환경에서는 기존 테스트 계정 로그인 유지
- 글·댓글·장소·플레이어 신고와 익명 사용자 차단, 내 신고 진행 상태와 차단 해제
- `/admin`: 운영자 신고·문의·조치 이력, 콘텐츠 숨김/복원·경고·기간제 이용 제한·관리자 제한 해제
- `/settings/account`, `/support`, `/help`, `/policies/*`: 계정 상태·탈퇴, 문의 접수/답변, 사용 안내와 운영 규칙
- PostgreSQL 기반 사용자별 글·댓글·이미지·신고·문의 요청 제한. 여러 서버에서도 원자적으로 공통 집계
- 커서 위치에 사진·영상·링크를 넣고 텍스트를 이어 쓰는 본문 편집기, 선택적 익명 작성, 사진 업로드·제거. 기존 Markdown 글과 댓글 유지
- 댓글·중첩 답글 CRUD, 부모별 답글 펼치기·더 보기, 삭제된 부모 댓글의 답글 구조 보존
- 멱등 좋아요·북마크, 서명된 HttpOnly 방문자 쿠키와 KST 하루 1회 조회
- 실제 댓글·답글 알림 생성, 수신자별 페이지 조회와 전체 미읽음 수, 개별/전체 읽음
- `/mypage` 웹푸시 설정: 기기 연결·해제, 공지·댓글·참가 확정/환불 완료 알림, PostgreSQL 발송 대기열·재시도·만료 처리. 표준 Web Push/VAPID 사용. 공지방 Redis 갱신과 별도 발송 Worker
- 로그인 후와 북마크·참가 확정·글 읽기 이후의 알림 안내: iOS 홈 화면 추가와 Android 설치/바로 알림 받기를 환경에 맞게 분리하고, 닫은 안내는 7일간 숨김
- 최신순·인기순 커서 페이지 처리, 좋아요·댓글 변경 후 이미 불러온 목록 유지
- 소유권·입력 검증, 트랜잭션, 익명 작성자 식별자 비공개, 같은 출처 쓰기 요청 검사

글쓰기는 Server Actions, 목록·댓글·반응·업로드는 Route Handlers를 사용한다. 두 경로 모두 `src/server/community-service.ts`를 호출한다. 서비스는 게시글 조회·DTO 집계(`post-reader.ts`), 본인 프로필(`profile-service.ts`), 알림(`notification-service.ts`)을 분리하고, 변경 트랜잭션과 소유권 검사는 공통 경계에서 유지한다. 클라이언트 요청은 `src/lib/api-client.ts`, 활동 보상 정책은 `src/domain/activity.ts`에서 공유한다. 첫 화면은 RSC에서 직접 DB를 읽는다. `/api/community/posts`의 REST CRUD도 같은 검증을 제공한다.

공지방에서 멤버 수와 사진·닉네임을 공유한다. 주최자·담당자·확정 참가자를 중복 없이 집계하고 50명씩 조회하며, 변경 사항은 Redis 방 UUID 힌트와 SSE로 갱신하고 정상30초/끊김5초 DB 재확인으로 유실·권한 변경을 보완한다. 내 정보에서 프로필 사진을 올리거나 삭제할 수 있다. 사진은 원본5MiB 이하를 브라우저 Canvas로 준비하고 서버가 실제 바이트를 다시 검증해 512×512 WebP·256KiB 이하로 변환하며 메타데이터를 제거한다. 파일은 비공개 로컬 폴더에, 소유권·파일 키는 RLS가 활성화된 `profile_photos` 테이블에 저장한다. 본인 또는 같은 방의 현재 멤버만 사진을 조회할 수 있으며 연락처와 신청 답변은 멤버 목록에 포함되지 않는다.

게시글 사진은 현재 화면에서 파일당 10 MiB 이하 최대 10장을 원하는 본문 위치에 첨부한다. 브라우저에서 원본보다 작은 최대2400px·2MiB WebP를 준비하고 서버에서 실제 디코딩·한도 검사 후 재인코딩해 메타데이터를 제거한다. 브라우저 API 미지원/실패/이득 없는 경우 입력 한도 안의 원본을 보내며 서버 검증을 유지한다. GIF·움직이는 WebP는 첫 장면만 보존한다. 파일은 공개 폴더에 넣지 않고 게시글 상태/소유권을 확인하는 `/api/media/{id}`로 제공한다. 본문은 구조화된 JSON으로 PostgreSQL에 저장하며 서버가 검색·호환용 Markdown을 생성한다. YouTube·Vimeo·영상 파일 링크는 해당 위치의 재생 버튼으로 열고 다른 안전한 영상 주소는 링크 카드로 표시한다. [본문 편집·저장·기존 글 호환](docs/RICH_POST_EDITOR.md)을 참고한다.

모바일 광고는 홈·이야기·번개 등 서비스 페이지에서 2.5초 뒤 다른 모달이 없을 때 표시한다. 로그인·회원가입·QR 확인 페이지에서는 표시하지 않는다. `오늘 하루 보지 않기`는 한국 시간 다음 자정까지 로컬 저장소에 보관하며, `닫기`·배경/ESC 닫기는 현재 탭 세션 동안 숨긴다. 저장소가 차단된 환경에서는 페이지 이동 중 메모리로 유지한다. 광고는 현재 Sliper 콘텐츠 미리보기이며 외부 광고 네트워크는 연결하지 않았다. `site-left`, `site-right`, `site-mobile-bottom` 슬롯을 추후 광고 연동에 사용할 수 있다.

읽음 기록은 브라우저 로컬 상태이며 로그인 계정이나 여러 기기 사이를 동기화하지 않는다. 서버의 하루 1회 조회수 집계와 별도로 처리하고 정상적인 글 내용 표시 후에만 기록한다. 홈·이야기·번개의 글 제목과 내 정보의 내 글·댓글·북마크 목록에 반영하며, 다른 탭의 변경과 명시적인 기록 삭제를 확인한다. 저장소 접근이 차단되거나 쓰기에 실패하면 메모리로 유지한다.

이전 브라우저 미리보기 저장소는 읽거나 지우지 않는다. 당시 작성한 미리보기 글은 실제 DB에 자동으로 옮기지 않았다.

## 웹푸시 알림

마이페이지의 알림 설정에서 기기를 연결하고 공지방·댓글/답글·참가 확정/환불 완료 알림을 각각 선택한다. 원본 변경과 같은 DB 트랜잭션에서 발송 작업을 저장하고, 별도 Worker가 현재 권한을 다시 확인한 뒤 실제 브라우저 Push 서비스에 전송한다. Web Push 발송은 Redis와 별개인 PostgreSQL 대기열과 표준 VAPID를 사용한다. 공지방 화면 갱신용 Redis는 별도로 선택 설정한다.

로그인 화면에서 알림 받는 방법을 미리 볼 수 있으며, 로그인·가입 경로 진입 후 30분 안에 실제 인증된 설정 응답을 받으면 안내를 이어서 보여준다. 새 북마크·참가 확정·한 글을 화면에 보이는 동안 60초 읽기 이후에도 1.2초 기다려 안내한다. 다른 글 모달 위에는 겹치지 않는다. iOS 일반 브라우저는 공유 → 홈 화면에 추가를 안내하고, 홈 화면 실행 상태에서는 알림 허용에 집중한다. Android는 실제 설치 이벤트가 있을 때만 설치 버튼을 제공하고 설치 없이 알림 받기도 지원한다.

시스템 권한 요청은 **알림 켜기** 클릭에서만 실행하며, 이미 허용한 사용자는 안내를 숨긴다. 차단 상태는 기기 설정 복구 방법을 제공하고 재요청하지 않는다. 닫으면 7일간 숨기며 브라우저 저장소가 막힌 경우 현재 실행 중 메모리로 반복 안내를 방지한다. 로컬 테스트 계정으로 로그인하면 인증된 상태에서 안내를 이어서 확인할 수 있다. 카카오·구글 OAuth 코드는 준비되어 있으며 실제 Supabase 프로젝트와 공급자 설정 후 사용할 수 있다.

```powershell
npm run db:migrate
npm run push:setup
npm run dev
```

`push:setup`은 전용 로컬 환경에서 Git 제외 파일 `.local/push-vapid.json`을 만들며 기존 유효 키를 유지한다. 현재 작업 환경에는 설정을 완료했다. 전용 로컬 개발 서버는 외부 Worker 모드가 지정되지 않으면 내장 발송 Worker를 시작한다. 기존 서버와 키 변경 후에는 완전히 재시작해야 한다.

운영은 HTTPS·실제 회원 인증과 안정적인 서버 VAPID 환경변수를 준비한 뒤 `npm run push:worker`를 상시 실행한다. `npm run push:drain`은 최대 20개를 한 번 처리하고 종료한다. `.env.example`의 `PUSH_WORKER_MODE=external`을 사용하는 개발 환경도 별도 Worker가 필요하다.

아이폰·아이패드는 iOS/iPadOS 16.4 이상에서 홈 화면에 추가한 Sliper를 열고 직접 알림을 허용해야 한다. 휴대폰의 HTTP Wi-Fi 주소는 푸시를 지원하지 않는다. 정확히 설정한 LAN 주소에서는 테스트 비밀번호 로그인으로 일반 기능을 확인할 수 있지만, 쿠키 없는 임시 작성자 인증은 허용하지 않는다. 실제 기기 수신은 아직 검증하지 않았고, 서버의 `sent`는 Push 서비스의 요청 접수 기록이다. [운영 설정·기기 조건·재시도·검증 범위](docs/WEB_PUSH.md)를 참고한다.

## 검증

```powershell
npm run check
npm run build
```

`check`는 Prettier 포맷, TypeScript(미사용 변수 포함), 클라이언트 회귀·도메인·DB·서비스 테스트, Drizzle 메타데이터를 검사한다. PGlite는 테스트에서만 임시 PostgreSQL 엔진으로 사용하며 앱의 저장소는 설치된 PostgreSQL 18이다.

내부/외부 신청의 서명 웹훅 및 동시 신청 검증은 별도 테스트 운영 서버를 사용하는 `npm run test:payments`로 실행한다. 서버 설정과 실행 순서는 [참가 신청 문서](docs/PARTICIPATION.md)를 참고한다.

개발 서버가 실행 중일 때:

```powershell
npm run test:api
npm run test:features
npm run test:lightning
npm run test:rich-post-api
npm run test:search-api
npm run test:crew-api
npm run test:crew-concurrency
```

프로필 사진과 공지방 멤버 HTTP/SSE 검사는 테스트 계정의 비밀번호를 현재 터미널의 `SLIPER_TEST_PASSWORD`에 설정한 후 `npm run test:room-members-api`로 실행한다. 업로드 검증·교체/삭제·현재 멤버 접근·취소 후 차단·실시간 목록 갱신을 확인하고 테스트 프로필의 기존 사진과 기본정보를 복원한다. 해당 계정을 사용하는 통합 검사들은 순서대로 실행한다.

HTTP 통합 검사는 실제 PostgreSQL 두 연결의 동시 쓰기·활동점수 잠금, 읽기 HEAD, 잘못된 업로드 형식, 외부 참가 확인·담당자 승인·대시보드 권한도 확인한다. HTTP 통합 검사는 전용 로컬 DB에서 테스트 글과 이미지를 만들고 CRUD·중복 조회·권한·출처 검사·이미지 차단을 확인한 뒤 해당 테스트 글만 소프트 삭제한다. 기존 글을 수정하지 않는다. 빌드는 개발 서버를 종료한 뒤 실행한다.

룰북·템플릿 접근 권한과 원본 수정 충돌, 행사 개설, 참가 전적·매너 평가 권한, 한국시간 환불 경계와 실제 환불 금액을 검사하는 회귀 테스트를 추가했다. 2026-10-01 검사 결과: 일반 회귀 145개, 기존 HTTP/SSE 9개, 자료/플레이어 HTTP 2개, 번개 HTTP 1개, 운영 서명 웹훅/정원 경합 3개, 총 160개 통과. 포맷·타입·Drizzle 검사와 Next.js 운영 빌드도 통과했다. 운영 모드 유료 자료 접근 차단을 확인했으며 브라우저 직접 클릭·시각적 회귀와 실제 플랫폼 거래는 별도 검증이 필요하다.

신규 기능을 로컬에서 체험할 샘플을 추가하려면 마이그레이션 적용 후 실행한다. 실제 행사·구매·결제를 만들지 않으며 기존 사용자 데이터와 샘플 수정 내용을 덮어쓰지 않는다.

```powershell
npx tsx scripts/seed-library-demo.ts
npx tsx scripts/seed-player-demo.ts
```

샘플 스크립트는 전용 로컬 DB(`127.0.0.1:55432/sliper_dev`, `LOCAL_DATABASE=1`)에서만 실행된다. 준비된 자료와 플레이어는 기능 체험용이며 현장 검증·신뢰 통계에 포함하지 않는다. 현재 Sliper 테이블은 행사 기록·자료 버전·행사 장소 연결과 영상 작업·웹푸시·지도·안전 운영·크루용 비공개 테이블을 포함해 69개이며 서버의 검증된 서비스 경계에서 접근하고 RLS를 활성화한다.

## 구독과 알림함

헤더의 종 아이콘에서 `/notifications`를 연다. 댓글·공지방·참가 변경·구독 모집·행사 리마인더를 모아 보고, 관심 카테고리와 호스트 구독을 관리한다. 리마인더는 현재 행사 시작 24시간 전과 2시간 전을 기준으로 확정 참가자에게 생성한다. 사이트 알림은 기기 권한 없이도 저장되며 마이페이지의 종류별 스위치는 휴대폰 푸시를 제어한다. [데이터 흐름·작업 대기열·실행·검증](docs/ENGAGEMENT_AND_NOTIFICATIONS.md)을 참고한다.

## 후속 단계

1. Supabase 개발 프로젝트에 마이그레이션 적용 및 연결 확인
2. 구현된 Supabase 세션·카카오·구글 로그인으로 실제 신규 계정과 권한 분리 검증
3. 준비된 private Supabase Storage 어댑터의 실제 버킷·업로드·접근 권한 검증 및 과거 로컬 파일 이전
4. 운영용 DB 역할, 오브젝트 스토리지 정리·백업, 배포 및 실제 다중 사용자 부하 검증
5. 영상 Worker·Redis 실서버/컨테이너·운영 알림 Worker·HTTPS 휴대폰 수신 및 실제 결제/외부 승인 어댑터 검증

글 상세·공유/OG·통합 검색·크루와 이미지 저장소 전환 기반은 구현했다. `npm run deploy:check`로 외부 연결 없이 운영 설정 형식을 점검할 수 있다. [연동 준비와 실제 검증 절차](docs/PRODUCTION_INTEGRATION.md)를 참고한다.

Supabase 클라우드 연결·OAuth·실제 결제 플랫폼 연결·배포는 아직 수행하지 않았다. 유료 룰북·템플릿도 실제 결제 연동 전이며 외부 구매 확인 후 작성자의 수동 열람 승인까지만 제공한다. 플레이어 탐색은 공개를 선택한 프로필을 성향·지역으로 찾는 기능이며 자동 매칭 알고리즘은 포함하지 않는다. 행사 진행 기록과 매너 온도는 담당자·참가자의 기록을 집계한 참고 정보로, 전문 품질 인증이나 노쇼·트롤링 완전 방지를 보장하지 않는다. 외부 신청 링크가 있는 행사는 플랫폼에서 결제한 뒤 담당자가 내역을 확인하여 수동 승인할 수 있다. 자동 승인은 실제 플랫폼의 서명 검증 및 공개 프로필 ID 회원 연결 어댑터를 연동해야 활성화된다. 외부 링크가 없는 유료 행사는 미연동 로컬 환경에서 실제 결제가 없는 테스트 버튼을 제공한다. 실제 결제·환불·정산은 외부 플랫폼이 담당하며, Sliper의 확인 체크박스는 외부 처리 내역의 기록이다. 개발 DB에는 여러 샘플 작성자가 있으며 테스트 계정은 기존 loopback 작성자와 다른 프로필을 사용한다. 단일 테스트 계정이 실제 회원 간 OAuth 로그인 테스트를 대신하지 않는다. 개발 플래그만 켜서 운영 인증을 우회할 수 없도록 NODE_ENV·DB 주소·요청 호스트도 검사한다.

## 2026-10-06 사진 준비·영상 Worker·Redis

사진은 브라우저 Canvas로 전송량을 줄이고 서버 Sharp가 다시 검증한다. 영상 접수는 비공개 원본과 PostgreSQL 작업을 저장해 ID를 반환하며 별도 Worker가 FFmpeg 변환·ready 자산 확정·원본/실패 결과 정리를 수행한다. 에디터는 본인 상태를 조회하고 ready 결과만 첨부한다. 작업 임대·시도별 토큰·최대3회 재시도·24시간 원본 만료와 정리 원장을 사용한다.

```powershell
npm run db:migrate
npm run video:worker
# 별도 터미널에서 Web 서버 실행
npm run dev
```

`npm run video:drain`은 정리와 처리 가능한 영상 한 개를 수행하고 종료한다. Web/Worker는 같은 DB·파일 저장소를 공유해야 하며 local이면 `.local/video-sources`와 `.local/videos`의 지속 디스크를 공유한다. 별도 영상 Worker 이미지는 `Dockerfile.video-worker`로 빌드하고 운영에서 같은 Supabase 비공개 버킷을 사용한다. `compose.yaml`은 로컬 Redis만 실행한다.

공지방은 서버 전용 `REDIS_URL`을 설정하면 방 UUID 힌트만 Redis Pub/Sub으로 전달하고 SSE가 DB에서 내용·현재 권한을 다시 읽는다. Redis 정상30초/미설정·장애5초 DB 재확인을 유지한다. `npm run redis:local:start`는 Docker 엔진이 있는 환경에서 loopback6380 포트의 Redis를 준비한다. Next 서버에 `REDIS_URL=redis://127.0.0.1:6380`을 설정하고 다시 시작한 뒤 검사 프로세스에 `ROOM_REDIS_TEST_URL=redis://127.0.0.1:6380`도 설정해 `npm run test:room-realtime`을 실행한다. 알림함·리마인더·Web Push의 PostgreSQL 대기열과 `push:worker`는 별도로 유지한다.

이번 npm run check의 형식·타입·회귀/DB593개·Drizzle 검사가 통과했고 실제 FFmpeg/비동기 Worker 영상 HTTP1개로 원본 제거·비공개 접근·Range 재생을 확인했다. npm audit 취약점0개이며 운영 빌드가 통과했다. 로컬 Redis 컨테이너를 실행했고 healthy·PING/PONG 및 실제 Pub/Sub 프로세스 간 통합 검사 1개가 통과했다. 공지 작성 HTTP→DB 커밋→Redis→SSE 갱신과 참가 취소 후 접근 회수도 3초 이내로 확인했다. 실제 모바일 사진 인코딩/영상 재생·원격 Supabase·운영 부하도 별도 검증이 필요하다. ## 2026-10-06 공통 광고와 Redis 활성화

PC 사이드 광고와 모바일 시트는 RootLayout의 SiteAdvertising 한 곳에서 관리한다. 홈·이야기 목록에는 순환 배너, 번개·룰북·템플릿·플레이어·행사·지도 등에는 공통 본문 배너가 표시된다. 좌우 여백이 충분한 PC에서는 사이드 광고도 보여주며 본문을 덮지 않는다. 모바일은 기존 닫기/오늘 숨김 정책을 모든 페이지에서 공유한다. 로그인·가입·QR 확인 과정에서는 모바일 시트를 띄우지 않는다. 로딩 화면의 중복 본문 광고를 제거했다.

Linux 영상 Worker 이미지도 빌드하고 비관리자 계정에서 FFmpeg·FFprobe 실행과 실제 합성 영상 압축을 확인했다. 설치 패키지의 FFprobe 실행 권한을 수정했으며, 검증용 컨테이너에는 DB·개인 설정·호스트 저장소를 연결하지 않았다. 현재 로컬 영상 처리는 기존 별도 Worker 프로세스가 수행한다.
